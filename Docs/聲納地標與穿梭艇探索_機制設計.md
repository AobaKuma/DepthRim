# 聲納地標與穿梭艇探索：機制設計（草案 2026-11-17）

> 狀態：草案，等待確認「待決定」各項後再開工。關聯：設計稿 §3[8]「聲納探測 → 遺跡」、§4.6、§11 M4／M6。

## 1. 目標

聲納掃到的海洋地標分成兩種處理方式：

- **遭遇型（不生成地圖）**：穿梭艇開到地標時跳出對話視窗，玩家選擇怎麼處理。成敗與收益看艇上乘員的對應技能。處理完，艇載著收穫自動開回出發地。
- **地點型（生成水下地圖）**：抵達時生成一張小型海洋地圖（沉船、海底洞穴、古代設施……），乘員下艇實地探索。

兩種地標都只能靠聲納發現，延續設計稿「要不要開主動聲納本身就是風險換收益」的取捨。

## 2. 現有可直接沿用的部分

| 需要的功能 | 現有實作 | 要改的地方 |
|---|---|---|
| 載人在世界地圖上走海路 | `WorldObject_TravelingBoardingCraft`（每格 250 tick、`OceanRouting`） | `Arrive()` 依目的地分流：地標 → 對話或生成地點；其他 → 照舊 |
| 艇與乘員容器 | `Building_BoardingCraft.aboard` | 新增：記錄出發地（回程用）、回程模式 |
| 出航前檢查 | `BoardingReadiness` | 地標目的地另外顯示「乘員技能 vs 地標需求」 |
| 聲納偵測範圍 | DMSE `WorldComponent_BVRNetwork` 的 node `DetectionRange` | 偵測時分辨主動和被動（見 §3） |
| 遠處只是「未知接觸」 | `SonarContacts.Classified`（半徑一半以內才分得出來） | 地標也照這條規則，沒分類前看不出是哪一種 |
| 海洋地點地圖 | `DepthRim_OceanSite` + `DepthRim_Ocean` 生成器 | 地點型地標各自掛額外的 GenStep |
| 海底研究點數 | `Fortified.KnowledgeUtility.AddKnowledge` | 遭遇型的收益之一 |

## 3. 發現：主動與被動聲納各聽得到什麼

建議讓兩種聲納掃到**不同類型**的地標，這樣被動聲納除了安靜以外，還有自己的用途：

| | 主動聲納（6 格／7.5 格） | 被動聲納（3 格） |
|---|---|---|
| 原理 | 發出聲波，聽回波 | 只聽目標自己發出的聲音 |
| 找得到 | **安靜的實體**：沉船、殘骸、洞穴、古代結構、漂流貨櫃 | **會發聲的東西**：求救信標、運轉中的機械、鯨歌、熱液噴發、海盜通訊 |
| 代價 | 暴露自己的位置（照舊可能被跳幫） | 範圍小 |

- 地標定義欄位 `detectedBy`：`Active`／`Passive`／`Both`。
- 每張開著聲納的玩家地圖（或航行中的潛艇），每天對範圍內的海洋格擲骰生成地標。上限：範圍內同時最多 N 個，全世界最多 M 個。
- 生成時依格子的生態區與水深層級挑地標（`allowedBiomes`、`depthTiers`），熱液噴口區比較常出熱液礦床，深海比較常出古代結構。
- 地標存在期限 `lifetimeDays`。會漂流的（漂流貨櫃、信標）每天漂一格，比照魚群。
- 沒分類前，世界地圖上只標「未知聲納接觸」；分類後才顯示名稱和需求技能。

## 4. 遭遇型：對話與技能判定

### 4.1 流程

```
穿梭艇抵達地標格
  → 開對話視窗（原版 Dialog_NodeTree）：描述 + 2～4 個選項
      每個選項：需要的技能、難度、乘員裡最適合的人、預估成功率
  → 選一個 → 擲骰 → 結果節點（文字 + 收益或損失）
  → 有些結果會接下一段對話（最多 2～3 層）
  → 結束：艇自動開回出發地；地標消失或標記成已探索
```

- 抵達時遊戲**不暫停**也不強制切到世界地圖：發一封信件，信件按鈕開對話。沒處理的話，艇在現場待命，最多等 `waitDays` 天。
- 「離開」一定是選項之一（不擲骰，直接回程）。

### 4.2 技能判定（純函式，放 `LandmarkMath`，可單元測試）

- 每個選項宣告 `skill`、`difficulty`（0～20），可選 `secondarySkill`。
- 擔任主角的乘員：自動挑艇上該技能最高、而且沒有無法執行該工作類型的人（例如「不做採礦」的人不能擔任採礦判定）。
- 成功率：`chance = clamp(base + (skill - difficulty) × 0.06, 0.05, 0.95)`，有副技能時加上 `副技能 × 0.02`。乘員受傷或缺氧時，乘上該乘員的工作能力（`Consciousness`、`Manipulation`）。
- 結果三段：**大成功**（擲骰結果低於 chance × 0.25）／**成功**／**失敗**。失敗可能受傷、消耗物品、地標失去部分收益，嚴重失敗可能讓艇損傷。
- 不論成敗，主角都得到該技能的經驗值（失敗得的較少）。

### 4.3 收益種類

| 收益 | 實作 |
|---|---|
| 物品（鋼、零件、太空材料、武器……） | 直接放進艇上的容器，回程帶回 |
| 海底研究點數 | `KnowledgeUtility.AddKnowledge`（例如古代聲學陣列） |
| 情報 | 揭露附近其他地標，或標出海盜潛艇和基地的位置（接 M7.5） |
| 人 | 救起求救信標旁的倖存者（可能招募，也可能是陷阱） |
| 升級成地點型 | 「標記座標，之後派完整隊伍過來」→ 地標轉成地點型（§5） |

### 4.4 範例地標（遭遇型）

| 地標 | 發現 | 選項（技能／難度） | 收益與風險 |
|---|---|---|---|
| 沉沒的補給艙 | 主動 | 撬開艙門（建造 6）／破解電子鎖（智力 8） | 物資；撬開失敗會讓艙體進水，損失一半物資 |
| 鯨落 | 主動 | 採集骨骼（採礦 4）／採樣生態群落（醫療 6，給研究點數） | 骨頭與研究點數；腐食生物可能咬傷 |
| 求救信標 | 被動 | 接近交涉（社交 8）／遠距掃描（智力 6） | 倖存者入隊；也可能是海盜誘餌，觸發突擊艇襲擊 |
| 熱液礦床 | 被動 | 開採（採礦 10）／小心取樣（智力 6，給研究點數） | 礦石；高溫燙傷 |
| 古代聲學陣列 | 被動 | 讀取資料（智力 12）／拆零件（建造 8） | 大量研究點數，或者先進零件；失敗會發出強信號（等同主動聲納開 1 天） |
| 漂流貨櫃 | 主動 | 拖回（建造 4）／就地拆開（採礦 6） | 隨機物資；會漂流 |

## 5. 地點型：水下地圖

- 抵達時用現有的 `Arrive()` 分支生成地圖。地標的 `WorldObjectDef` 指定 `mapGenerator`：`DepthRim_Ocean` 加上專屬的 GenStep，或者 FFF 結構。
- 地圖尺寸建議用 100×100（比照海盜潛艇用自己的 `mapSize`），減少生成成本。
- 地圖跟著水深層級：水壓、能見度、進水全部照原有系統，乘員必須穿潛水服（出航前檢查要擋）。
- 回程：乘員回艇後按「出發」，目的地預設為出發地。艇上沒人、地圖上也沒有玩家建築時，地圖照 `WorldObject_OceanSite` 原本的規則移除。
- 敵方：有些地點自帶守衛（海盜補給站），或在探索中觸發深海生物。

| 地點 | 發現 | 內容 |
|---|---|---|
| 沉船 | 主動 | 進水的船體結構、需要破門的艙室、貨艙戰利品 |
| 海底洞穴 | 主動 | 礦脈、可燃冰、黑暗；可能有巨物 |
| 古代海底設施 | 主動（深海） | 古代機械、密閉艙室（有空氣）、高價值戰利品；接到終局星艦的線索 |
| 海盜補給站 | 被動（攔截到通訊） | 守衛戰、補給、魚雷；也就是 M7.5 海盜基地的前身 |

## 6. 資料結構

```xml
<DepthRim.OceanLandmarkDef>
  <defName>DR_Landmark_SupplyPod</defName>
  <label>sunken supply pod</label>
  <kind>Encounter</kind>            <!-- Encounter / Site -->
  <detectedBy>Active</detectedBy>   <!-- Active / Passive / Both -->
  <depthTiers><li>Shallow</li><li>Thermocline</li></depthTiers>
  <commonality>1</commonality>
  <lifetimeDays>8~15</lifetimeDays>
  <drifts>false</drifts>
  <!-- Encounter 用 -->
  <encounter>
    <intro>DR_Landmark_SupplyPod_Intro</intro>      <!-- Keyed 文字 -->
    <options>
      <li>
        <label>DR_Landmark_SupplyPod_Pry</label>
        <skill>Construction</skill>
        <difficulty>6</difficulty>
        <onCriticalSuccess> ... </onCriticalSuccess>
        <onSuccess><thingSetMaker>...</thingSetMaker></onSuccess>
        <onFailure><injury>...</injury><lootFactor>0.5</lootFactor></onFailure>
      </li>
    </options>
  </encounter>
  <!-- Site 用 -->
  <siteWorldObject>DR_Site_Shipwreck</siteWorldObject>
</DepthRim.OceanLandmarkDef>
```

- 結果用可擴充的 `LandmarkOutcome` 子類別（`Outcome_Things`、`Outcome_Knowledge`、`Outcome_Injury`、`Outcome_RevealLandmarks`、`Outcome_Raid`、`Outcome_ConvertToSite`、`Outcome_Pawn`）。
- 世界物件：`WorldObject_OceanLandmark`（遭遇型，非 MapParent）；地點型用 `WorldObject_OceanSite` 的子類別，帶自己的 GenStep。
- 對話用原版 `DiaNode`／`DiaOption`／`Dialog_NodeTree`。不引入「对话框架」模組：它只支援 1.4／1.5，而且綁定陣營交涉者。

## 7. 測試

- 單元：`LandmarkMath` 成功率與結果分段、主角挑選、聲納類型過濾、生態區與水深過濾；內容一致性（每個 OceanLandmarkDef 的技能存在、Keyed 文字齊全、地點型指定的 WorldObjectDef 存在）。
- 驗收：L-系列。開聲納 → 地標生成並分類 → 艇出發 → 遭遇對話自動選第一項 → 收益進艇 → 艇回到出發地；地點型：抵達 → 地圖生成 → 截圖。
