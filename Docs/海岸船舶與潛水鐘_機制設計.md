## 0. 全套流程

```
[海岸殖民地]
   │ ① 灣裡鋪船體平台 → 龍骨 → 艦橋／推進器 → 下水
   ▼
[浮航]  海路，避開海冰與陸地
   │
   ├─ ② 抵達既有地圖：玩家選泊位，系統算進場路線與初始朝向
   └─ ③ 抵達空海域：生成海面地點
   ▼
[靠岸]  補給、交易、修理、換人（不能下鐘）
   │ ④ 出港，回到海洋格
   ▼
[下鐘]  甲板吊架 → 垂直放到海床 → 採樣 → 海底研究
   │ ⑤ 鐘未收回前不能出航
   ▼
[耐壓工程] → [壓載水艙＋耐壓牆] → [潛艇]
```

三個東西、三個形狀，誰也不取代誰：

| | 能去哪 | 能待多久 | 代價 |
|---|---|---|---|
| **船** | 水面上任何地方 | 一直（會吃天氣） | 不能下潛、不能躲 |
| **潛艇** | 水面到海床 | 一直（基地） | 只能在淺海／海床下錨 |
| **鐘** | 正下方的海床（每個海洋生態區都有，包括深海平原；越深收放越久） | 一趟（最久 60 秒收放） | 人可能出不去 |

全部沿用既有系統：船體搬移（`RelocateHull`）、水位（`MapComponent_Flooding`）、
壓力（`MapComponent_WallPressure`／`MapComponent_PressureChambers`）、潛水裝備（`CompDivingAir`）、
安全繩（`RopeTetherMath`）、穿梭機容器（`CompTransporter`）、過場（`TransferTakeoffCutscene`）。

## 1. 船＝同一具船體的三個狀態

上浮後的潛艇本來就是一艘船：`SubmarineSurfacing` 把船體從海洋層搬到地表層那一格的海面地圖，
`ShipSeparationUtility.RelocateHull` **不分圖層**，`HullMoveHooks` 讓每格水位與艙壓跟著船走。
所以船與潛艇不是兩種機器，是**同一具船體能進入哪幾個狀態**。

| | 浮航 | 潛航 | 停泊（下錨） |
|---|---|---|---|
| 在哪 | 地表層・海岸／海面地圖 | 海洋層 | 海洋層・海床地圖 |
| 移動 | 海路，慢，吃風浪 | 海路，快，不吃風浪 | 不動 |
| 看得到外面 | 看得到（甲板危險） | 看不到 | 看得到 |
| 進水 | 破口就灌 | 同左，越深越快 | 同左 |
| 離開船 | 可以，要扣繩 | 禁止（甲板＝失蹤） | 可以，出艙作業 |
| 外殼 | 有牆就好 | 朝外牆的耐壓決定**能待多久**，不是能不能下去（§2.2） | 同左 |

**沒有「改裝模式」。** 能進哪個狀態、能下多深，全部是**算出來的**——看船殼範圍上有哪些建築（§2.1）。
所以「這艘船什麼時候變成潛艇」不是一個事件，是玩家把壓載與耐壓牆蓋齊的那一刻。

**浮航移動需要水面推進器。** 潛艇裝的是水下推進器，浮在水面時不出力，所以
「出水後只能停在原地、要移動就得先下潛」這條舊原則仍然成立。
水面推進器可以留著（能浮航移動，但多一份重量與耗電）或拆掉（減重，只能下潛移動）。

「那為什麼還要造潛艇」：

1. 船去不了冰層下面（極地開局的核心場域）。
2. 船躲不了暴風雨。
3. 船不能懸停在無底的水層。
4. 開了聲納找地標的船是浮在水面的靶子：找得到東西，打不贏來搶的東西。

## 2. 船體能力與擴建

### 2.1 能力由船殼範圍上的建築決定

**不需要任何「改裝」流程。** 想做什麼，就在船殼範圍裡蓋對應的建築；蓋好就有能力，拆掉就失去。

| 想做的事 | 船上必須有 | 沒有的話 |
|---|---|---|
| **下潛／上浮** | **壓載水艙**（唯一的門檻） | 永遠停在浮航 |
| 設定巡航深度 | 艦橋 `CompDiveControl` | 不能換深度 |
| 水下移動 | 水下推進器 | 沉下去只能漂 |
| 浮航移動 | 水面推進器 | 出水後停在原地 |
| 在變溫層／深海**撐得住** | 朝外的牆是水密隔牆、外門是耐壓艙門 | 艙壁持續受損（§2.2） |
| 停泊時出艙 | 氣閘 | 只能待在裡面 |
| 抽水 | 排水泵 | 進水只能等 |

這份清單是**能力表**，不是升級表：船的速度、載重上限、耐壓都是從船上實際有什麼算出來的。
拆掉一面耐壓牆換成一般牆，船不會突然下不去——它會下得去，然後在下面被壓壞。

**只有壓載水艙是硬門檻。** 其他的都是「做得到，但會有代價」。

### 2.2 下潛前的耐壓警告

**耐壓不是門檻，是風險。** 有壓載就能下潛，但玩家在下潛前必須被告知現在這副船殼撐不撐得住。

觸發時機：按下「下潛」、或把巡航深度設到比目前更深的層級時，若**目標層級的壓力 > 船殼能耐**
（`HullPressure` = 最弱的那一面朝外牆），跳出確認視窗：

| 顯示 | 內容 |
|---|---|
| 目標深度 | 例：深海（4） |
| 船殼能耐 | 例：變溫層（2）——是哪一面牆、哪個 Def |
| 超出 | 例：超出 2 級；實際損傷照 `WallPressureTopology`：每 250 ticks、每 1 點**壓力負載**超過容量扣 0.4 HP（`DamagePerExcess`，單位是負載點不是層級） |
| 後果 | 艙壁會陸續被壓壞；壞了之後就是受損進水、破口（既有系統接手） |

按「仍然下潛」才會下去。抵達之後、只要仍在超載狀態，檢視面板與 `Alert` 持續顯示「船殼超載」。

> **這是行為變更**：現在的 `SubmarineNavigation` 把 `HullPressure.RatingFor` 當**硬上限**（深度選單超過就不能選）。
> M6 要把這條上限拿掉，改成上面的確認視窗；海床深度的上限（不能潛到海床以下）照留。

**不阻擋的理由**：硬限制會讓玩家覺得「明明能下去卻不讓我下」，而且需要一面一面牆去猜是哪一面不夠。
改成警告之後，玩家可以為了打撈或逃命硬衝一次，代價是被壓壞的牆——這比一個灰色按鈕有戲。

### 2.2b 換深度與上浮（`DepthBlock` 放寬，M6）

**上浮不必先手動回到淺海。** 舊規則：上浮要先把巡航深度設回淺海、等它到了再按上浮（`DepthBlock` 要求巡航與目標都是淺海）。
新規則：

- 任何深度、停著（沒有在航行、沒有在破冰懸停、潛水鐘收好）都能按「上浮」。
  上方的條件（不是陸地、冰棚、海冰，那一格沒有別的東西）**按下時就檢查**，不行就灰掉，不會白爬上去。
- 不在淺海時：巡航深度設成淺海、記下「到了就上浮」，一層一小時往上爬（壓載不夠會更慢，§2.4）；
  到了淺海自動上浮（再檢查一次上方，這段時間結冰或有東西擋住就發訊息、停在淺海）。
- 途中再改深度、開始航行，就取消「到了就上浮」。
- **破冰上浮照舊**要先在淺海（它要先貼著冰懸停一小時）。
- **往上永遠可以**，沒有壓載也行（只是慢，§2.4）；往下（包括從海面下潛）一定要有壓載。

### 2.2c 下潛前清空甲板（M6）

潛航時「離開船＝失蹤」（§1）。所以從海面下潛前，**甲板上不能有人**：

- 甲板＝船殼範圍（龍骨網路的格子）裡、不在密閉艙室內的格子：沒有屋頂，或所在房間用室外溫度（開放的、跟外面通的）。
- 那些格子上有我方的人（殖民者、奴隸、囚犯、動物）時，下潛灰掉，寫出是誰；讓他們進艙或下船再潛。
- **物品不擋**：甲板上的東西跟著船沉下去、泡在水裡（既有的淹水系統），玩家自己決定要不要先收進艙。
- 在海洋層換深度不用檢查：潛航中待在艙外的人本來就會被 `VoyageOverboard` 判定失蹤。

### 2.3 船殼範圍與「航行中不能擴建」

**船殼範圍＝龍骨（結構樁）覆蓋的格子。**

> 規則：**龍骨不能在航行中接上或拆掉。**

所以航行時船殼範圍是固定的——想擴建、想加一塊甲板、想改船型，就得先停下來。
這條同時也是「為什麼不能邊跑邊長大」的唯一理由，不需要另外寫一條「改裝要靜止」的規則。

內部施工不受限：航行中可以改艙內的東西（牆、機器、家具），
只要不動到外殼造成破口（[DepthRim_概念與玩法設計.md](DepthRim_概念與玩法設計.md) §4.6）。

### 2.4 壓載＝浮力上限

**載貨量不該只看空間，要看壓載能不能把你撈回來。** 壓載水艙的總容量（噸）決定「船＋貨」的總重上限；
超載＝下得去、上不來，或只能慢慢擠上來、期間一直耗電。

**M6 的第一版**（先不算重量）：

- **壓載水艙** `DepthRim_BallastTank`（1×2，潛航器建造），蓋在船殼範圍內才算。每座撐 **200 格船體**。
- 船上（從海面下潛時是龍骨網路的範圍內）**一座都沒有**：不能下潛、不能往下換深度；往上可以，但最慢。
- 不夠（船體格數 > 座數 × 200）：每換一層的時間 × （船體格數 ÷ 撐得住的格數），最多 4 倍（4 小時一層）。沒有壓載時也是 4 倍。
- 以後再把「格數」換成「船＋貨的重量」、加上耗電。

### 2.5 搬移時要保住的狀態

船體格子、每格水位、艙壓、電池儲電、船上物品、船上的人——已經是 `HullMoveHooks` 的行為。
直接繼承「船體是一塊會搬動的實體」的模型，**不要另開一套存檔結構**。

### 2.6 換船

舊船不是廢物：可以留在港裡當補給船／打撈船，或拆掉回收。
多船同港可以，前提是**龍骨網路分開**（§4.2）。

## 3. 海岸開局與造船

### 3.1 起點

原版海岸地圖的**海灣**就是船廠。極地冰蓋沒有這個入口（§10 #5）。

```
陸地 ── 岸線 ── 淺水（原版深水，不能走）
                  │
              ① 鋪船體平台（貼著岸邊往海裡長）
              ② 龍骨框架（DMSE 結構樁）
              ③ 艦橋、推進器、電池、排水泵、艙室
              ④ 下水：船體脫離施工區，變成水面上的世界物件
```

下水不需要新的地圖型別：船體本來就在這張殖民地地圖上，只是從「貼著岸的施工區」變成「可以開走的船」。
離港時那幾格還原成原本的水域地形（§9.2），灣就回來了。

### 3.2 平台只有一種

只留 `DepthRim_HullPlatform`，研究掛在**海岸造船**（一般研究）。
一塊甲板本來就不需要耐壓——耐壓的是**牆**，牆留在耐壓工程（海底研究）底下。

| 研究 | 解鎖 |
|---|---|
| 海岸造船（一般研究） | 船體平台、龍骨、艦橋、推進器、舷梯、吊架、潛水鐘 |
| 耐壓工程（海底研究） | 水密隔牆、耐壓艙門等牆類 |

潛艇船塢（深淵上的平台）照用同一種地形，不放寬任何東西：能不能下潛取決於朝外的牆，不是甲板。

> **副作用**：潛艇開局（極地）直接給耐壓工程與潛航器建造，也必須順便給「海岸造船」，
> 否則極地玩家不能擴建自己的船體。

### 3.3 研究順序

```
水下生存（500 一般）       → 潛水服、水密門、排水泵、採樣器、升降井
   └ 海岸造船（600 一般）  → 船體平台、龍骨、舷梯、艦橋、推進器、吊架、鐘
        └ 造船 → 出港（海洋格）→ 下鐘 → 淺海冷泉 → 採樣器 → 海底研究
             └ 耐壓工程（800 海底）→ 水密隔牆、耐壓艙門
                  └ 潛航器建造（1200 海底）→ 壓載＋耐壓牆 → 潛艇
```

**鐘需要船**：吊架只建在船上，港口不能下鐘（§5.4），所以海岸開局一定要先把船造出來。
甲板在一般研究、牆在海底研究，所以不會雞生蛋——被海底研究卡住的是水密隔牆，不是能浮的甲板。

## 4. 水面航行

### 4.1 船的世界格

靠岸時，船的世界格是**泊位對應的那個海洋格**，不是殖民地所在的陸地格；地圖仍然是殖民地地圖。
**只有靠岸時，船的世界格與它所在的地圖不同格**，其他時候兩者一致。

這條要寫死在程式裡，否則世界地圖上的船會以為自己站在陸地上，航線規劃一開始就找不到海格。

> **這個世界格只給航線用，不能拿來判斷能不能下鐘。** 靠岸的船世界格是海洋格，
> 如果吊架照「船的世界格」判斷，就會在港口放得下鐘，違反 §5.4。
> 吊架一律看**自己所在地圖的 `Map.Tile`**（§7.3）。

### 4.2 航線與出航檢查

- `OceanRouting` 照用（只走海格），加一條限制：**不能經過有海冰的格子**。
- 航程時鐘、推力檢查、就地停船照用（`VoyageMath`、`ApplyThrust`、`StopHere`）。
- 動力是**引擎**，不是風帆；成本只有推進器耗電（`SubmarineEnergyWorker` 那一套）。
- **浮航的船可以被魚雷打**：水面船是可被水下彈體命中的目標，交戰域要讓
  `CombatDomain.Underwater` 的魚雷打得中浮在水面的船體。

**出航前檢查**是一張清單，一次列出所有未就緒的項目：

| 項目 | 規則 |
|---|---|
| 潛水鐘 | 必須 `Stowed`（§7.7） |
| 舷梯 | 伸出狀態自動收起（`ticksPerCell` 照算），收完才離港 |
| 龍骨 | 一艘船 = 一組相連龍骨；多艘船的龍骨**不能連在一起**，否則 DMSE 判定成同一艘一起帶走 |

### 4.3 航行中畫什麼

- **地圖**：海面照畫，海水往船尾流過，加上航跡（開爾文波、船尾翻攪水、船艏浪；`SeaWake`，2026-11-20 改：原本是只畫艙內）。
- **世界地圖**：畫一個**會轉向的船圖示**（比照 `DepthRim_Submarine` 的白色剪影 + `expandingIconColor`）。
  這解決「船體朝向固定、航向任意」的矛盾：格子裡的船體不需要跟著轉，只有圖示轉。
- 進出港時才用船體貼圖演出（§7）。

### 4.4 為什麼不掛轉移飛行的環境

DMSE 的轉移飛行綁在 `TransferEnvironmentExtension` 上，那個 extension 掛在**海洋層**。
把 extension 掛到原版 `Surface` 會波及商隊、其他圖層行為與其他模組。

做法：另寫一個輕量的 `SurfaceVoyage`——重用 `OceanRouting`、航程時鐘、`RelocateHull`，
跳過點火／升空／降落。**這是整條線最大的技術賭注。**

## 5. 靠岸

### 5.1 選位設計器：玩家選位置與旋轉

沿用 `Designator_PlaceSubmarine`（船體輪廓跟著滑鼠、逐格白色可停／紅色受阻），加一個 `Rot4`：

- **旋轉**：Q／E 轉 90°，四個朝向都能試。
- **位置**：滑鼠所在的格子是船體外框的中心。
- **即時回饋**：滑鼠旁寫第一個失敗原因（「壓到碼頭」「這一側沒有迴轉空間」「排水泵 2×1 不能轉 90°」）。
- **路線預覽**：把自動算出的進場路線畫成淡虛線。
- **靠法不是開關**：貼著岸放＝舷靠或船尾靠（看旋轉），放在開闊水域＝錨泊。

### 5.2 放置檢查

| 檢查 | 說明 |
|---|---|
| 水上 | 每一格都能承載船體（`DepthRim_HullBase`／開放海面／深淵） |
| 不重疊 | 不壓建築、其他船、礁石、平台支柱 |
| **旋轉合法性** | 旋轉後每個建築的佔地與朝向都要成立。非方形且 `rotatable = false` 的建築（例如 2×1 的排水泵）擋住 90°，那個旋轉直接變紅並寫出是哪一個 |
| 迴轉區 | 泊位旁要有一塊容得下船體迴轉的空水域 |
| 進場路線 | 見 §5.3；算不出來就不能放 |
| 舷梯 | **不是硬條件**：貼岸但搆不到岸時仍可放，只是不能上下船，提示要寫明 |

### 5.3 進場路線（唯一自動的部分）

給定（泊位格、最終朝向），自動算出：

1. **進場口**：地圖水域邊緣（或最寬的連通水域外緣）裡，離泊位最近、船寬過得去的那一個。
2. **路線**：用船寬做 clearance 的 BFS，從進場口走到泊位前方的迴轉區。
3. **初始朝向**：路線第一段的切線方向，船頭朝前。
4. **轉向**：在迴轉區把船轉到玩家選的朝向，最後平移靠上泊位。

兩個以上進場口可用時，選路線最短的；同長取最避風的（風向取 `SeaState`）。
這段是純計算，抽成純函式做單元測試（給定水域遮罩、船體外框、泊位、朝向 → 路線與轉向點）。

### 5.4 港口不能下鐘

陸地正下方**沒有海洋**（[海洋圖層與生態區.md](海洋圖層與生態區.md)：陸地格底下沒有海洋層格子），
而吊架記的是自己的世界格。港口在陸地格上，正下方沒有海床可以生成，所以**吊架只能建在船或潛艇上**：

| 吊架在哪 | 下鐘到哪 | 可以嗎 |
|---|---|---|
| 船／潛艇在海洋格上 | 正下方的海床 | **可以** |
| 船靠在殖民地的海灣 | 沒有海床 | **不行** |
| 碼頭（岸邊） | 沒有海床 | **不行** |

**規則：靠岸＝補給、交易、修理、換人；出港＝作業。**要下鐘就把船開出海。
提示與教學訊息要寫出來，不然玩家會以為鐘壞了。

### 5.5 存檔

泊位＝(格、`Rot4`)，玩家選的就存下來，不重算、不重排。船的世界格是泊位旁的海洋格（§4.1）。

### 5.6 安全島與舷梯

原版水域不可通行，所以停泊中的船，近戰敵人根本上不去——除了**舷梯**。敵人會走舷梯上船
（比照原版 `PawnCanOpen` 的可達性規則）。靠岸＝安全但被綁住，而且舷梯是把敵人請上船的門；
出港＝自由，但船上的東西沒有人守。這個取捨要留著。

## 6. 進出港演出

### 6.1 管線

1. `TransferTakeoffCutscene` 先把船體**擷取成一張貼圖**（`CapturedTexture`）。
2. 子類別用 `SimpleCurve` 拉透明度、顏色、縮放、位移（`SurfacingCurves` 是範本）。
3. 停靠要加的是**位置曲線與旋轉角**。俯視圖裡旋轉一張船體貼圖，幾何上本來就是對的。
4. 最後一幀 `RelocateHull` **並把船體旋轉到玩家選的朝向**，貼圖同幀消失。

貼圖的最終角度、路線的轉向點、落地的 `Rot4` 三者必須是同一個值，否則最後一刻會跳一下。

**旋轉活船體**已有先例（`SubmarinePrefab.Spawn(map, center, Rot4 rot)` 會擺整份結構），
但那是從 Def 生成；活船體要另外處理：

| 東西 | 怎麼轉 |
|---|---|
| 地形（甲板） | 逐格座標變換 |
| 建築 | 座標變換 + `Rotation` 加同樣的圈數 |
| 物品、Pawn | 座標變換 |
| 儲存區、種植區 | 逐格重畫（最麻煩的一項） |
| 訂單、藍圖 | 跟著建築走；沒有建築的藍圖要取消 |

180° 永遠安全（佔地不變、只有朝向 +2）；90° 會被「非方形且不可旋轉」的建築擋住（§5.2），
**轉不動就讓那個旋轉變紅，不要硬轉**。

### 6.2 腳本（約 10 秒，遊戲暫停）

```
0.0–2.0s  ｜灣外進場：貼圖由小到大，船頭浪開始，鏡頭緩慢跟上
2.0–5.0s  ｜減速轉向：貼圖繞船艏旋轉，側傾 2~3°，引擎聲轉低，尾流散開
5.0–8.0s  ｜貼靠：平移貼上泊位，碰墊擠壓、船身回彈一次，兩條纜繩拋上岸
8.0–10.0s ｜收尾：引擎停、水花收、纜繩拉緊、舷梯伸出（現成的 `Gangway`）
10.0s     ｜最後一幀 RelocateHull + 旋轉船體，貼圖同幀消失
```

離港反向播。演出播放時遊戲暫停（奧德賽式）；**因為暫停，不會出現同時停靠的情況**。

### 6.3 四種靠法

靠法不是另外選的開關，是**位置與朝向的結果**：

| 靠法 | 演出重點 | 位置／朝向 |
|---|---|---|
| 舷靠 | 平行進場、側推、碰墊、雙纜 | 船體長邊貼著岸 |
| 船尾靠 | 進灣、原地轉、倒車進泊位 | 船體短邊貼著岸 |
| 錨泊 | 頂風、拋錨、放下舷梯 | 放在開闊水域，舷梯接岸 |
| 進塢（可選） | 滑進塢門、坐墩 | 玩家自己蓋的 flavor 塢，沒有任何功能 |

### 6.4 播放頻率

每次進出都 10 秒，短程補給會讓人抓狂。三個控制：

1. 模組設定「簡化進出港」。
2. 同一個港口重複靠泊只播 3 秒短版。
3. 沿用 `SubmarineSurfacing.skipCutscenes` 的測試開關。

### 6.5 和鐘的收放不是同一件事

| | 船舶進出港 | 潛水鐘收放 |
|---|---|---|
| 遊戲 | **暫停**（奧德賽式） | **照常運行** |
| 畫面 | 擷取船體貼圖、曲線演出 | 即時狀態機（絞盤、臍帶、下沉） |
| 時間 | 約 10 秒 | 依深度計時，最久 60 秒 |
| 為什麼 | 結果性演出，看完就好 | 過程性計時，中途會出事 |

兩者唯一共用的是「換地圖發生在結束那一刻」，其餘不要互相呼叫。

### 6.6 還沒做

- 拖船、倒車、掉頭空間不足的失敗情況（現在設計器直接不讓放）。
- 演出中有人從甲板掉下去（§10 #9）。

## 7. 潛水鐘與吊架

### 7.1 鐘是載具建築，不是門也不是房間

鐘不是 `MapPortal`（門），也不是可以站人的艙室。它是一台 **2×2 的載具建築**：
乘員與貨物放在**容器**裡（`CompTransporter`，和突擊艇 `Building_BoardingCraft` 同一套），
**不是站在格子裡**。

- **落地**：鐘在正下方的海床生成，接著**自動**把人與貨放到旁邊可站的海床格（比照突擊艇放出乘員）。
  落地後容器是空的。
- **回鐘**是一個「登鐘」工作，把人與貨收回容器。容器只裝兩種人：等著被吊上去的、躲進來避險的。
- 鐘身上那扇艙門只是貼圖，沒有實體的 `Building_Door`。

> 海床地圖照舊用 `OceanWorldView.TileBelow` 建立或重用（`DepthRim_OceanSite`），
> 地圖保留到鐘收回為止——只是「誰在門裡」從門變成鐘的容器。

### 7.2 規格

**只有一種鐘，一個 Def `DepthRim_DivingBell`。** 不做耐壓等級——耐壓這件事由潛水員的裝備與適應負責。

| 項目 | 規格 |
|---|---|
| 大小 | 2×2（4×5 的月池現在就放得下，之後 5×5 更寬） |
| 乘員 | 2 人，放在容器裡 |
| 內容物 | 人＋貨；落地時放到旁邊 |
| 耐久 | 會被打破；**壞了內容物掉在旁邊的海床上**（比照突擊艇） |
| 耐壓 | **沒有等級、也沒有被壓扁的判定** |
| 艙內 | 常壓，進出鐘不改變壓力適應值 |
| 氧氣 | 吊架通電就有（§7.5）；容器裡的人 `CompDivingAir` 會回充 |

**不做的事**（比不做耐壓表更重要，因為會牽動既有系統）：

- **不進 `MapComponent_WallPressure`**：鐘不是房間，沒有「朝外的牆」要算負載。
- **鐘內不會淹水**：不是艙室，沒有 `MapComponent_Flooding` 的格子水位；裡面的人只有「有沒有氧氣」。
- **容器裡的 Pawn 不會被一般的溺水邏輯處理**，所以缺氧要自己算（§7.5）。**這是最容易漏的一條。**

深度門檻在人身上（潛水服的 2 級抗性 + 適應值），不在鐘身上——所以鐘可以下到任何**正下方有海床地圖**的地方，
只是人可能出不去。每個海洋生態區都有海床（生態區的層級就是海床在多深），所以深海平原、變溫層的深礁也能下鐘（2026-11-22）；越深收放越久，人在下面的水壓越大。

### 7.3 吊架（`Building_BellDavit`）

鐘的**母港與狀態機**，1×1，建在船甲板（月池旁）或潛艇的月池上。**碼頭上不能放**（§5.4）。

| 儲存 | 用途 |
|---|---|
| 鐘的地圖＋格＋朝向 | 收回時知道去哪裡接它 |
| **鐘的寄存**（容器裡的人與貨、耐久、名字） | 收回時在吊架旁重新生成一台鐘（§7.4） |
| 收放狀態 `Stowed`／`Deploying`／`Deployed`／`Retracting` | 決定船能不能出航 |
| 倒數（tick） | 收放要時間，中途不能取消 |

- **能不能下鐘看吊架所在的地圖**：吊架的 `Map.Tile` 必須是海面地點（`WorldObject_SeaSurfaceSite`）或潛艇，
  且 `OceanWorldView.TileBelow` 有海床。**不看船的世界格**——靠岸的船世界格是海洋格（§4.1），照那個判斷會在港口放得下鐘。
- **供氧**：鐘的氧氣由吊架供給，**只要吊架有電就一直有氧**。容器裡的人 `CompDivingAir` 直接回充，
  不需要「去建築補氧」的新工作。斷電＝斷氧。
- **供電**：吊架接船上自己的電網，**不需要跨層電力**——鐘本身不耗電，氧氣與絞盤都算在吊架上。
- **畫臍帶**：兩張地圖各畫一段——海面層從吊架往下、海床層從鐘往上（比照支柱柱身的兩層畫法）。
  **純渲染**：它不代表一條會被切斷的實體，狀態只由「通電／停電」決定。

潛艇月池目前是 4×5 的建築、之後改成 5×5，**只要擺得下就塞得進去**（2×2 的鐘沒問題，同時停突擊艇也不衝突）。

### 7.4 下潛與回收

**下潛**（`Stowed` → `Deploying` → `Deployed`）：

1. 條件：吊架通電、鐘停在吊架上、**吊架所在地圖是海面地點或潛艇**、正下方有海床（§7.3）。
2. 人與貨進鐘（原版穿梭機的裝載介面，`CompTransporter`）。
3. 放下：**依深度計時，最久 60 秒**（淺海最快；公式待調），期間不能取消。
4. **鐘從原地圖消失**（DeSpawn），吊架記下它的容器內容與耐久；同時在正下方的海床上**生成一台鐘**，
   內容物一起放進去，然後立刻自動放到旁邊（§7.1）。海床地圖建立或重用。

**回收**（`Deployed` → `Retracting` → `Stowed`）：還在外面的人要先**登鐘** → 收 **依深度計時，最久 60 秒**
→ 海床上的鐘 DeSpawn，**吊架旁重新生成一台鐘**（內容物、耐久照舊），海床地圖沒人、沒玩家建築就移除。

**沒登鐘的人不會跟著走**——留在海床上，有沒有氧氣看自己的裝備。收鐘前確認人數是玩家的事，系統只給警告。

**這就是 shuttle 的語意**：起飛＝原地消失，落地＝在另一張地圖生成一台新的。原版穿梭機與突擊艇都這樣做。
差別只有一個——**鐘不能選目的地**：起點是吊架，終點是吊架正下方的海床；反過來也一樣。

**寄存不是備份。** 吊架保存的是「部署中的那台鐘」的資料。海床上的鐘被毀就是那台鐘沒了，
吊架只能重新造一台，不會免費生回來。

**為什麼是垂直下放而不是選位**：鐘吊在纜繩上，不是自由飛行的 shuttle。吊架在哪、鐘就在哪的正下方——
這也讓「船必須正停在那個海洋格」變成物理事實，而不是一條規則。

**收放不是過場。** 鐘的升降是**即時狀態機**：絞盤轉、臍帶放、鐘慢慢沉下去，**遊戲照常運行**——
敵人會動、天氣會變、人會被打、氧氣繼續算。它和 §6 的船舶進出港是兩套完全無關的演出，不要共用管線。

### 7.5 供氧與斷電

| 條件 | 容器裡的人 |
|---|---|
| 吊架通電 | 有氧氣，可以一直待著，隨時可以收 |
| 吊架停電（被炸、被拆、反應爐熄火、電池耗盡） | **斷氧**，而且收不回來——絞盤也要電 |

危險不是「纜繩斷了」，是**沒有電**。而電是可以被奪走的：打壞吊架、打壞電池、打壞發電機，同一個後果。

**斷氧的計時要自己算**：容器裡的 Pawn 不會走一般的溺水／缺氧流程（§7.2），
所以鐘要有一個專屬的窒息倒數，時間到就窒息。

安全繩照舊（`RopeTetherMath`：9 格、不能穿牆、門算通），錨點換成鐘。**同一個系統、第二個使用者。**

### 7.6 天氣是時鐘

氧氣由電力供給，所以死線是**天氣**：暴風雨會打壞甲板上的吊架、船殼與電池（`MapComponent_SeaWeather`），
一停電就收不回來、也開始缺氧。收放最久 60 秒，所以「決定收鐘」要提前——那 60 秒就是玩家的賭注。

### 7.7 出航封鎖（硬規則）

**鐘不在 `Stowed` 時，船與潛艇都不能出航、下潛、上浮、離港。**

- 航行指令、艦橋選單、DMSE 的起飛檢查都要擋，並寫出原因（「潛水鐘尚未收回」）。
- 拆吊架＝鐘失去電力與收回能力（§7.5），不是免費取消。
- 這條取代「收鐘才能下潛」的軟規則：硬封鎖，沒有「先走再說」。
- **唯一的出口是「放棄潛水鐘」**（吊架上的 gizmo，要確認視窗）：吊架回到沒有鐘的 `Stowed`、寄存清空、
  海床上的鐘與人照 §7.9 進入失聯。吊架被毀也等同放棄。

### 7.7b 狀態 × 事件

| 狀態＼事件 | 吊架斷電 | 吊架被拆／毀 | 海床上的鐘被毀 | 存讀檔 | 海床地圖被卸除 |
|---|---|---|---|---|---|
| `Stowed` | 不能下鐘 | 鐘掉在原地（變成一般物品／殘骸） | — | 照存 | — |
| `Deploying` | **倒數暫停**，鐘還在船上、人還在容器裡；容器開始斷氧倒數；來電就繼續 | 放棄下潛：鐘留在原地、人從容器放出 | — | 存倒數與目標 | —（還沒生成） |
| `Deployed` | 斷氧；不能收 | 等同放棄（§7.7），進入失聯（§7.9） | 寄存清空、內容物掉在海床；吊架變成沒有鐘的 `Stowed` | 存鐘的地圖／格／寄存 | 不允許：鐘是玩家建築，`WorldObject_OceanSite` 保留地圖 |
| `Retracting` | **倒數暫停**，鐘還在海床、人在容器裡斷氧；來電就繼續 | 倒數中止，鐘留在海床 → 失聯 | 同 `Deployed` | 存倒數 | 不允許（同上） |

原則：**倒數只在通電時前進**；任何中斷都把鐘留在「它此刻實際所在的那張地圖」，不做瞬移。

### 7.8 後期定位

鐘沒有被潛艇淘汰，但從「第二個基地」變成「專用工具」：

- 潛艇在**淺海／海床**下錨時，人直接出艙，不需要鐘。
- 潛艇**不能下錨**的地方（變溫層、深海）**鐘下得去**（2026-11-22）：那些生態區其實有海床（例如深海平原），只是潛艇不在那裡觸底。
  這是鐘目前唯一做得到、潛艇做不到的深度用途。
- 鐘不可取代的三件事：**打撈沉船、救援失聯、在潛艇不方便停的淺點作業**。

| 平台 | 能到哪 | 限制 |
|---|---|---|
| 船 + 鐘 | 任何有海床的海域 | 天氣窗口、人能走出去的深度 |
| 潛艇下錨 | 淺海／海床 | 基地，不需要鐘 |
| 月池 + 鐘 | 同船 | 收放最久 60 秒，期間不能出航 |

### 7.9 失聯

- **吊架被毀或停電** → 鐘與裡面的人留在海床地圖（地圖保留比照 `WorldObject_OceanSite`：
  有玩家建築或有人在就保留），而且開始缺氧。
- **船必須離開** → 用「放棄潛水鐘」（§7.7），發信，鐘與人進入失蹤名單。
- **救援**：另一艘船／潛艇在同一格下鐘或下錨，先把人接出來；鐘本身要新的吊架才能收。

### 7.10 跨層電力

需求：水面層 → 平台層（支柱）、船 → 岸（可選）。**鐘不需要**：鐘不耗電，供氧與絞盤都算在吊架上（§7.3）。

- 成對的橋接建築 `CompCrossLayerPower`，兩端各在自己的地圖上，每 tick 把一邊的剩餘電力送到另一邊。
- 規則：容量上限（暫定 2000 W）、線損 5%、兩端都通電才成立、任一端被拆就斷。
- 套用點：**柱腳↔柱頂**（平台層現在沒有電，這個順便解掉）。以後若鐘要帶燈或工具，再加吊架↔鐘。

> 實作風險：RimWorld 的 `PowerNet` 是 per-map，沒有原生的跨圖輸電。要自己算兩邊的剩餘／缺口
> 再灌進對面的電池或 `CompPowerTrader`。**這是一個新的子系統，不要當成吊架的附屬功能低估它。**

### 7.11 以後：孤立地形區（未設計）

現階段鐘在變溫層／深海確實沒有用途——那裡沒有底，鐘只能停在海床上、人又出不去。
以後可以加**孤立地形區**：在變溫層／深海中央冒出來的一小片可站地形，例如
**海底堡礁**（珊瑚或熱液堆積成的高台）與**巨型火山柱**（從深處長上來的柱狀岩體，頂端在水層中間）。

一旦有這種地形，鐘就有了著力點：吊下去、停在礁頂或柱頂、人走出來作業——
「潛艇懸停 + 鐘」這個組合才第一次有意義。

還沒解：地形怎麼生成、能不能下錨（或只能停鐘）、深度層級怎麼算（礁頂算淺海還是深海？）、
會不會擋住潛艇的中層視差畫面。

## 9. 原版深水支援

### 9.1 承載力不是白名單

船體平台能不能鋪，看地形有沒有帶 `DepthRim_HullBase` 承載力（深淵、開放海面、海床都有）。
給原版水域加這一條就好，不用改 C#：

```xml
<Operation Class="PatchOperationAdd">
  <xpath>/Defs/TerrainDef[defName="WaterOceanDeep"]/affordances</xpath>
  <value><li>DepthRim_HullBase</li></value>
</Operation>
```

同樣給 `WaterOceanShallow`。**河川（`WaterDeep`）不開。**

### 9.2 離港後的空地形要依地圖決定（最大的坑）

DMSE 分離船體時，會把船體範圍鋪成該圖層的 `voidTerrain`。地表圖層沒有這個設定，
所以 DMSE 一律鋪成 **`TerrainDefOf.Space`（太空）**。

`Patch_SeaSurfaceVoid` 會在 `TerrainGrid.SetTerrain` 之後把太空換掉，但**只在地圖是海面地點的兩層時才動手**
（`SeaLevels.IsAnyLevel`），換成 `SeaLevels.VoidTerrain(map)`：水面層→開放海面、平台層→高空。

所以船從原版海岸地圖離港時，補丁根本不會觸發，灣裡會留下一整片**太空地形**——黑底、太空背景。
比「一個洞」更明顯，也比「開放海面」更糟。

修法：把 `VoidTerrain(map)` 擴充成「這張地圖的空地形」，並讓補丁認得原版海岸地圖：

| 地圖 | 離港後鋪回 | 現在 |
|---|---|---|
| 水面層 | 開放海面 | ✅ |
| 平台層 | 高空 | ✅ |
| 海洋層 | 深淵（走 `TransferEnvironmentExtension.voidTerrain`，不經過這個補丁） | ✅ |
| 原版海岸地圖 | **原本的水域地形**（靠格子記憶還原；沒有記憶時退回 `WaterOceanDeep`） | ❌ 鋪成太空 |

第四條正好是 `MapComponent_SeabedMemory` 已經在做的事（記下平台蓋掉的地形、之後還原），
只是要從「海床」擴展到「水域」，而且要在**離港路徑**上也觸發一次，不是只有拆平台時。

### 9.3 乾舷側面要認得「水」

`SectionLayer_HullPlatformProps` 現在判斷鄰格是不是深淵／開放海面才畫船身側面。
船停在原版海灣裡時鄰格是原版水，不畫側面，看起來像地上鋪了一塊鋼板。改成「鄰格是任何水域地形就畫」。

### 9.4 沒有水線遮罩

原版地圖上沒有 `_Hull` 遮罩，所以**沒有水線影子和白沫**。

- 第一版：貼圖自帶一條暗邊 + 船邊撒浪花 fleck。
- 之後：把水面層局部掛到原版地圖上（`SectionLayer_SeaSurface` 只覆蓋灣的一小塊）。這條路先不走。

### 9.5 相容性

- 其他改動水域的模組（漁業、船、水體著色）可能與 `DepthRim_HullBase` 承載力或側面貼圖衝突。
- 原版襲擊的路徑要能處理「水上的建築」（比照海上平台已有的處理）。

## 10. 已知限制與缺口

1. **港口不能下鐘。** 陸地格正下方沒有海洋，吊架又只認自己的世界格（§5.4）。
   這條要寫進玩家看得到的地方，不然玩家會以為鐘壞了。
2. **船的世界格 ≠ 地圖格。** 靠岸時船在陸地格的地圖上，但世界格必須是旁邊的海洋格（§4.1）。
3. **平台研究搬家。** 船體平台從耐壓工程移到海岸造船，潛艇開局要補給海岸造船（§3.2）。
4. **航行中船體無法對齊航向。** 船頭固定、航向任意 → 只畫艙內，世界地圖用會轉向的圖示（§4.3）。
5. **冰海不能浮航。** 極地開局不能用船，兩條入口不互通——要在設計稿講明，否則玩家會期待「開船去極地」。
6. **靠岸的船是無敵安全島。** 原版水不可通行，敵人上不了船，除了舷梯（§5.6）。要驗收，不然就是破口。
7. **同時三張地圖。** 港口地圖 + 海床地圖 + 鐘，人在不同地圖上。地圖保留規則要比照 `WorldObject_OceanSite`。
8. **演出頻率。** 每次進出 10 秒（§6.4），三個控制要一開始就有。
9. **浮航的船遇到水下襲擊。** 可以打；交戰域要讓 `CombatDomain.Underwater` 的彈體命中浮航船體（§4.2）。
10. **人口分散。** 船在海上時殖民地少一批人；靠岸時船上的事又沒人管。
11. **平台拆掉或離港後要還原成原本的地形。** 鋪在原版水上，拆掉或離港時要還原成水域
    （不是深淵、不是太空）；海床記憶要同時認得「水域」和「海床」兩種原始地形。
12. **一格船體網路只算一艘船。** 多船同港可以，但龍骨必須分開（§4.2）。
13. **擴建 vs 換船的成本。** 要確認「往舊船體上加蓋」沒有變成「永遠比較貴」的假選項。
14. **鐘是 DeSpawn／生成。** 人與貨要經 `CompTransporter` 轉手、海床地圖靠 `TileBelow` + `DepthRim_OceanSite`
    建立與保留、收放最久 60 秒期間遊戲照常運行（§7.4）。
15. **跨層電力是新子系統。** `PowerNet` 是 per-map（§7.10）。鐘不需要它，只有支柱需要。
16. ~~「從建築取氧」的 AI job 不存在。~~ 不需要：回鐘（登鐘）就是補氧，容器裡的人直接回充 `CompDivingAir`（§7.3）。

**M1 的實際範圍（2026-11-20）**：

- 研究 `DepthRim_CoastalShipbuilding`（一般研究 600，前置水下生存）解鎖船體平台、龍骨框架（大／小）、艦橋、
  新的**水面推進器** `DepthRim_SurfaceThruster`、可收放舷梯。潛航器建造改成也要海岸造船，只剩水下推進器與安全繩錨點；
  潛艇開局多給海岸造船。
- 龍骨的 `spaceMapOnly` 關掉，靠 `allowedTerrains`（只有船體平台）限制。
- 水面推進器只有推力資料（`CompSurfaceThruster`），沒有 DMSE 的引擎元件，不算進水下航行；M2 才用到。
- **下水**＝原版海岸地圖上艦橋的「下水」指令：整個龍骨網路的船體 `RelocateHull` 到殖民地**相鄰**的開放海面格的海面地點
  （沒有就建立；有冰、陸地不行）。檢查：在龍骨網路上、艦橋有電、船上的舷梯已收起、旁邊有開放海面、海面地圖放得下。
  灣裡由 M0 還原成原本的水。沒有演出（M4）、還不能開回來（M3）、不能在海上移動（M2）。
- **下潛的暫時門檻**：壓載水艙（M6）出來之前，從海面下潛要先研究潛航器建造，否則灣裡造的第一艘船一下水就能潛。M6 用壓載取代它。

**M2 的實際範圍（2026-11-20）**：

- **`WorldObject_SurfaceShip`**＝海面地點的子類別：船的地圖就是一張海面地圖（同一個生成器），海面畫法、天氣、乾舷、下潛、地圖去留全部照用。
  停著的船就是一個普通的海面地點；航行中才動。
- **出航**：艦橋航行選單的「航行到……」→ 世界地圖選海面格（航程圈＝電池能跑幾格）。艦橋所在龍骨網路的船體 `RelocateHull` 進一張新的船地圖（同座標），
  不在船體上的人（海裡游的）留在原地點；原地點空了就照海面地點規則移除。
- **出航前檢查**：艦橋有電（同一個龍骨網路上可以有多座艦橋，例如母船載子船，整個網路一起走）、有能運作的水面推進器、電池至少夠走一格。
  **舷梯自動收**：船上伸出的舷梯先收，`GameComponent_SurfaceSail` 等收完才出航（5000 ticks 收不完就放棄）。潛水鐘的檢查留給 M5。
- **航線** `SurfaceRouting`：地表圖層上、不是陸地與冰棚、沒結冰（`IceConditions`）的格子；BFS 沿用 `OceanRouting.Bfs`，快取以（起點、遊戲日）為鍵。
  走到下一格前重檢查，前方結冰就停在原地。
- **速度與耗電**：每格 6 小時（`SurfaceVoyageMath`：每 1 點水面推力全速推 50 格船體，超過照比例變慢）；水面推進器只有航行中才全速耗電，
  電池沒電→推進器停→推力 0→漂著不動。水下推進器浮在水面時不出力；水面推進器在潛艇上也不出力。
- **到達／就地停船**：那一格沒有其他海面地點就停在那裡；有的話把船體搬進那張地圖（找得到開放海面的位置才搬，否則停在旁邊）、船物件移除。
- **畫面（2026-11-20 使用者修正：浮航不淡出，要航跡）**：航行中海面照畫，不用潛艇的艙外淡出。航跡畫在海面著色器裡（`SeaWake`）：
  海水依推力往船尾流過（`_Flow`，暫停時不動）；船艏張開約 19.5° 的開爾文波（浪頂白線＋浪谷＋羽狀紋）；船尾一條被雜訊打散、往後變寬變淡的翻攪水；船艏浪。
  白沫在跟著海水流的座標上取樣，所以留在水裡往後流。航向＝世界地圖上這一格往下一格的方位，船體外框＝船體平台格投影到航向上；
  強度以真實時間約 2 秒淡入淡出。世界地圖圖示沿航向轉、位置在兩格之間內插（圖示暫用潛艇剪影改暖色）。航行中不能下潛（要先停船）。
  這取代了 §4.3「航行中只畫艙內」對水面船的部分；潛艇照舊。
- **沒做**（之後）：魚雷打得中浮航的船（§4.2）、浮航時的甲板危險／落海、天氣影響航速、靠岸（M3）、演出（M4）。

**M3 的實際範圍（2026-11-20）**：

- **從哪裡開始**：船停在海面上（沒在航行）、旁邊一格是自己的原版海岸殖民地時，艦橋航行選單多一個「靠岸：X……」。
  「航行到……」點殖民地那一格時，會改成開到它旁邊海路最近的一格海，到了發訊息提示用「靠岸」。
  檢查：艦橋有電、龍骨沒和別的船連在一起、有能運作的水面推進器、船上的舷梯已收起。
- **選泊位**（`Designator_DockShip`）：切到殖民地地圖，船體輪廓跟著滑鼠（滑鼠格＝轉好後外框的中心），Q／E 轉 90°，逐格白／紅，
  滑鼠旁寫第一個失敗原因與轉向按鍵；路線算得出來時畫淡虛線。舷梯搆不到岸只用黃字提示，不擋。上次在這個殖民地停過，預設同一個朝向。
- **放置檢查**：每格是能承載船體的水（原版海水，沒有平台、沒有建築）且符合 DMSE 的降落規則（不在邊緣、沒屋頂、沒有擋路的東西）；
  非方形又不能轉的建築擋住奇數次旋轉（`HullRotator.Blocker`）；迴轉區與進場路線（`DockingMath.Plan`）。
- **進場路線**（`DockingMath`，純函式、有單元測試）：淨空＝到最近非水格的切比雪夫距離（地圖邊不算障礙）；迴轉點＝從泊位往外第一個淨空 ≥ 半對角線的水格；
  路線＝從所有淨空 ≥ 半船寬的地圖邊緣格同時出發的 BFS 到迴轉點；初始船頭＝第一段方向。**「同長取最避風」還沒做。**
- **靠岸**（`Docking.Dock`）：船不在自己的船地圖上時先搬到同一格的一張新船地圖；在那裡原地旋轉（`HullRotator`：地形與地板、屋頂、
  所有東西連朝向、區域、水位、艙壓；建築用 `WillReplace` 移出，DMSE 的龍骨連結保留；指派取消）；再 `RelocateHull` 平移到泊位。
  游泳的人放上甲板；船地圖移除（這次事件才生成的暫時地圖交給海面地點規則下一個 tick 自己移除）；接得到岸的舷梯自動伸出；發信。
- **舷梯接岸**：原版海岸地圖上，舷梯跨的是沒有平台的原版水域、對岸是陸地或甲板；可以蓋在殖民地地圖上的船體平台上。
- **泊位存檔**（`MapComponent_Berths`，殖民地地圖，以船名為鍵）：外框中心、轉了幾次、從哪一格海來。再下水時優先從那一格出去（§4.1）。
- **沒做**：演出（M4）、地基（舷梯的臨時甲板）不跟著轉（靠岸前舷梯必須收起）、最避風的進場口、拖船／空間不足的失敗演出。

**M5.5 的實際範圍（2026-11-20）**：

- `CompCrossLayerPower`（`Power/CrossLayerPower.cs`）掛在支柱腳與支柱頂。兩端各是自己地圖電網上的一個**原版** `CompPowerTrader`（耗電 0；

  - 平台層缺多少：開著或想開（開關開著、沒故障）的用電減開著的發電；平台層電池沒充滿時再加上容量（多的拿去充電）。

- **上浮放寬**（§2.2b）：航行選單的「上浮」在任何深度都能按（`SurfaceOrAscend`），上方條件先查；不在淺海時設 `surfaceWhenShallow`，

## 12. 風險

1. **水面航行是最大的技術賭注。** DMSE 的轉移飛行綁圖層，船要另寫一條。
   先做「只有航線與時間、沒有演出」的版本驗證可行性，再談進出港。
2. **原版深水的視覺接縫。** 沒有 `_Hull` 遮罩就沒有水線；先接受「貼圖暗邊 + 浪花」，不要一開始就改水面層。
3. **演出是四段過場的量。** 每段都是 400 行等級；先做舷靠＋錨泊，不要四種全做。
4. **旋轉活船體。** 90° 一起做，但「非方形且不可旋轉」的建築要先有一套明確處理（轉不動就讓旋轉變紅）。
5. **海岸開局與極地開局的分家。** 兩條入口共用後段，但前期內容完全不同；
   要確認海岸開局不會變成「沒有冰、沒有壓力、無聊版」。
6. **跨層電力。** `PowerNet` 是 per-map。先做「柱腳→柱頂」單向、容量先給 500 W，驗證可行再談雙向與 2000 W。
7. **鐘的狀態機。** 四態跨兩張地圖，存讀檔、地圖卸除、吊架被拆、鐘被毀都會卡在中間。
   收場規則見 §7.7b，每一格都要有驗收測試。
