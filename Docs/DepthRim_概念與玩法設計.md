# DepthRim — 概念與玩法設計稿 v0.3

> 一句話：**深海才是敵人，潛艇是唯一的庇護所。**
> 不是「換皮太空」，而是一個「看不見、出不去、壓力無所不在」的生存模組。

**前置需求：** 硬相依 DMSE（未來可能統合為同一框架）。

---

## 0. 設計範圍與基調

| 原則 | 說明 |
|---|---|
| 不做水面 | 沒有水面航行、水面地圖或水面事件，所有內容都在冰層之下。 |
| 襲擊綁定主動聲納 | 水下襲擊只會發生在玩家設有**主動聲納**的地圖上。沒有主動聲納的地圖（例如早期的冰洋基地）威脅只來自環境：進水、水壓、維生。主動聲納同時也是發現值得探索的水下地點的唯一手段，所以「要不要開聲納」本身就是一個風險換收益的選擇。 |
| 生物從簡 | 就算加入水下生物，也只做少量、行為簡單的種類。 |
| 礦業豐富 | 深海的回報是資源：礦脈、熱泉等，用來支撐開採與發電。 |
| 高挑戰 | 環境本身就足以致命，玩家的每一步擴張都必須先顧好排水與維生。 |

## 1. 核心設計支柱

| 支柱 | 說明 | 與「軌道 / 太空」的差異 |
|---|---|---|
| **封閉** | 航行期間只能待在艙內（比照 DMSE 軌道船）；淺海或海床下錨時才能出艙。 | 真空是逐格擴散的失壓；深海則是依船殼受損程度與深度持續進水。 |
| **無光** | 艙外一片漆黑，航行時連艙外都不顯示；下錨後艙外才可見。 | 太空至少看得到星光和敵艦。 |
| **水壓** | 越深，船殼受損造成的進水越快；牆體完全破口時，整間艙室會瞬間淹沒。 | — |
| **聽而不見** | 戰鬥靠聲納和魚雷在地圖外進行（BVR）；等你真的看到敵人，通常已經是對方跳幫上艙了。 | — |

## 2. 船殼損傷與進水規則

### 2.1 兩種狀態

| 狀態 | 定義 | 結果 |
|---|---|---|
| **船殼受損** | 船艙牆體被打傷，但還沒完全摧毀。 | 依**受損百分比 × 當前深度層級**決定進水速度，艙室水位逐漸上升。 |
| **船殼破口** | 船艙牆體被**徹底摧毀**。 | 該艙室立即淹沒；航行中發生時，**艙內殖民者全部判定失蹤**。 |

### 2.2 水位模型
- **每間艙室（Room）一個水位值**（0–100%），不做逐格計算，以兼顧效能。
- 水位上升的艙室會讓殖民者移動變慢、溺水，也會損壞設備與物品。
- **視覺：** 依艙室水位高度裁切 Pawn 的渲染，從腳往上把被淹到的部分改成水色，讓玩家一眼看出水淹到哪裡。

#### 實作（`MapComponent_Flooding`，2026-11-01）
- **開放水域：** 碰到地圖邊緣、或有任何沒屋頂格子的房間，水位固定 100%。牆被打穿、房間連到外面，就會立刻變成開放水域。
- **密閉艙室**的水位只會因三件事改變：
  - 受損牆體滲水：受損比例 × 水壓倍率（淺海 1、變溫層 2、深海 4、海床 8）× 兩側水位差。
  - 打開的門：兩側水位往平均值流動。
  - 排水泵：每秒抽 2 格。
- **存放：** 水位存在每一格（0–255），房間水位 = 格子平均。原版每次牆體變動都會重建房間物件，用格子存就能讓新房間自然繼承水位，不需要 patch 原版房間重建。
- **對 Pawn 的影響**（每 250 ticks 結算）：
  - 涉水減速。
  - 沒入水中（站著 ≥ 75%、躺著 ≥ 30%）又沒有潛水服氧氣時會溺水，約 1 小時致死。
  - 水壓抗性不足時累積水壓傷害。
- **Pawn 水位渲染**（`PawnWaterRendering`）：在水中時，每個渲染節點的材質換成原版 CutoutComplex 著色器，配一張垂直漸層遮罩。水線以上是遮罩紅色（主色 = 原色），水線以下是綠色（第二色 = 原色 × 水色）。人形身體節點約佔全身高度 0–72%、頭部約 62–100%；躺著時水位到 30% 就整個上色。不需要自訂著色器。
  - 限制：雙色衣物在水中會失去第二色；遮罩顏色慣例（紅 = 主色）要進遊戲確認。
- **水體顯示**：分兩層，GLSL 放在 `1.7/Shaders`。1.7（Waylith）會在執行期編譯，做法比照 DMS 本體。
  - **外海層**（`SectionLayer_WaterOuter` + `DepthRim_WaterOuter.frag.glsl`）：
    - 繪製順序 3177，介於原版迷霧（3175）和光照暗化（3180）之間，關閉深度測試。開放水域裡的岩體、建築、Pawn 都會被蒙上一層水，未探索的迷霧區變成深海，燈光仍然照得到水面。
    - 涵蓋範圍是迷霧格加上已探索的開放水域和岩體。已探索的密閉艙室和它們的牆不在網格裡，所以沿格子邊界乾淨地切開，並往艙室方向淡出。網格本來就是逐格的，不需要模板遮罩。
    - 迷霧格一律只帶迷霧權重，不用房間或地形資料，避免洩漏未探索的洞穴。
  - **艙室層**（`SectionLayer_WaterVolume` + `DepthRim_WaterVolume.frag.glsl`）：
    - 只畫密閉艙室裡的積水，畫在 MoteLow 高度（建築之下）。頂點水位只平均同一間艙室的格子；碰到牆和關著的門算岸邊。
  - 每格的「開放水域」旗標由 `MapComponent_Flooding` 每次更新寫入，渲染在平行執行緒也能查。Pawn 水線只用在密閉艙室；開放水域的 Pawn 由外海層蓋住。
  - 冰洋地圖現在有迷霧（`GenStep_IceOceanFog`）：開放水域可見，岩體內部保持迷霧，升降井出口會從出口揭開。
- **光照與混濁度（2026-11-01，`水體視覺分層_實作指南.md` A/B 階段）：**
  - 每個水體頂點取周圍四格的光照平均寫進頂點色的 g 通道（迷霧格一律 0，不洩漏迷霧下的光源）。光照量 = **日光與人造光取大者**：日光取原版 `skyManager.CurSkyGlow`（無屋頂時），所以白天淺海整片都算有光、不會再有「明明有太陽卻一片不透明」的暗塊；人造光（燈、頭燈）用平滑衰減的原始值，燈下才會有一圈由亮到暗的漸層。
  - 日光會乘上層級的 `ambientReach`（淺海 1.0、變溫層 0.55、深海 0.25、海床 0.12）：日光本來就穿不深，深海在白天也不會因此變透明；人造光不折減。
  - 著色器用同一條公式算「清澈度」：光照 ≥ 0.6 視為清澈（`_ClearAlpha` 0.40–0.50，看得到海底但仍是水），≤ 0.05 視為全暗（`_MurkAlpha` 0.85–0.93，依層級，幾乎看不到海底）。所以**燈照到哪裡，水就看到哪裡**；關燈後只剩層級設定的微光。迷霧區固定 `_FogAlpha`，不受光照影響。
  - 潛水服自帶頭燈（`CompSuitLamp`，半徑 4.5、冷白光 (200,225,255)）：穿著者在水中時在腳下註冊原版自訂光源（`GlowGrid.RegisterCustomGlower`），每 15 ticks 檢查、換格才搬移，脫下／死亡／倒地 10 秒後解除。
  - 暗處的己方提示（`MapComponent_DarkWaterHints`）：己方 Pawn 站混濁的水裡（混濁度 ≥ 0.5）時，用原版剪影著色器畫一層淡青色輪廓，`alpha = (混濁度 − 0.5) / 0.5 × 0.6`。敵人、野生生物、密閉艙室裡的 Pawn 都沒有提示；跟著右下角的水體顯示開關。
- **水深層級化（2026-11-01，C/D/E 階段）：**
  - 每個層級（淺海／變溫層／深海／海床）一組參數寫在 `1.7/Defs/Rendering/WaterVisualTiers.xml`（`WaterVisualTierDef`）：水色、深處色、迷霧色、混濁度上下限、波紋尺度與強度、光紋、光柱、海洋雪、生物光、沉積霧氣、變溫層晃動。
  - 淺海：大尺度波紋與穿過冰層的光柱；變溫層：水面晃動與稀疏懸浮物；深海：日光幾乎穿不到，燈下看得到海洋雪、關燈只剩生物光；海床：貼地沉積霧氣＋生物光。
  - 海洋雪是兩層不同速度的亮點（視差），每顆自己的擺幅、頻率、相位、大小與亮度都不同，所以不會整片同步往下滑；`snowSpeed` 是倍率，改 Def 就能調快慢。
  - 外海層與艙室層各準備四個材質（`WaterTierMaterials`），地圖層級改變時整張重建。艙室層只讀水色、深處色、混濁度與波紋尺度，**不套用**海洋雪／生物光／霧氣／晃動。
  - 除錯動作「DepthRim: Override water visual tier」可以手動切換層級看畫面（只影響渲染，水壓與滲水速度仍照地圖實際層級）。
- **冰洋地圖的屋頂規則（驗收測試發現後修正）：** 開放水域沒有屋頂，只有岩體上方有岩頂。玩家要圍牆**並蓋人造屋頂**才算密閉艙室。地圖生成器不能設 `isUnderground`，否則原版會把整張地圖鋪滿厚岩頂、高度全設為岩體，玩家永遠蓋不出艙室。
- **水下基地不會消失：** `WorldObject_IceOceanSite` 在還有升降井出口或玩家建築時保留地圖。原版太空地圖父物件在沒人時會移除地圖。
- **還沒做：** 航行中破口的「整艙失蹤」判定（等潛艇原型）。

### 2.3 進水的處理
- 可以用排水泵把水抽掉，並修補受損的牆體。
- 水密艙門 / 隔艙能把進水擋在單一艙室，這是潛艇設計的核心取捨：犧牲空間換安全。

### 2.4 失蹤與救回
- 因破口而失蹤的殖民者並沒有死，之後有機會透過**打撈 / 救援事件**找回（例如在海床找到殘骸艙或逃生艙）。

## 3. 遊戲流程總覽

```
[1] 冰蓋前進基地
      │  在極地冰蓋建立地面基地
      ▼
[2] 建造升降井
      │  打通冰層，開啟「地下冰洋」地圖
      ▼
[3] 第一次下地
      │  穿戴潛水裝備的人員下去探勘
      ▼
[4] 冰洋探索
      │  尋找礦產與可用於發電的資源（熱泉等）
      ▼
[5] 升降井平台基地
      │  圍著平台建造密閉區、排水、供電
      │  排完水的區域，之後下來的人不需要再穿潛水裝備
      ▼
[6] 擴展設施
      │  排水隔艙與維生系統必須跟上擴建速度
      ▼
[7] 建造潛航器（比照重力船）
      │  在水下基地建造潛艇，探索冰洋的其他位置
      ▼
[8] 深海航行循環
      │  ├─ 在四個水深層級之間下潛 / 上浮
      │  ├─ 聲納探測 → 魚群 / 海盜潛艇 / 跳幫突擊艇 / 遺跡
      │  ├─ BVR 魚雷交戰、攔截
      │  ├─ 跳幫與反跳幫
      │  └─ 在淺海 / 海床下錨 → 出艙採礦、探索、打撈
      ▼
[9] 終局：啟動水下星艦
```

地面基地在潛艇出航後仍然是一張**獨立運作的殖民地地圖**。

## 4. 各階段細節

### 4.1 冰蓋前進基地
- 起始地形限定在冰蓋生態區：極寒、資源匱乏。
- 定位是前哨、物資中轉站和升降井基座。
- 潛艇出航後仍繼續運作，作為母港。

### 4.2 升降井與第一次下地
- 「冰層升降井」完成後，會開啟一張附屬的**地下冰洋地圖**。
- 地下冰洋預設**整張都是水**；人員必須穿潛水裝備才能活動。

#### 潛水裝備的限制
| 限制 | 說明 |
|---|---|
| **氧氣時間** | 裝備內的氧氣會隨時間消耗，用完前必須回到乾區或補充。 |
| **工作效率** | 穿著裝備時工作速度下降（越重的裝備降得越多）。 |
| **移動效率** | 穿著裝備時移動速度下降。 |
| **環境水壓抗性**（新 Stat） | 決定能在哪個水深層級活動；水壓超過抗性就會持續受傷。裝備等級越高，抗性越高，但效率懲罰也越重。 |

> 「環境水壓抗性」也可以用在敵方海盜的重型潛水服、水下生物，甚至義體 / 基因上，成為一個通用的深度門檻。

### 4.3 水下基地：排水與擴張
這是前中期的主要玩法，邏輯是「把水趕出去」：

1. 圍著升降井平台蓋出密閉的牆體與屋頂。
2. 架設排水泵與電力，把密閉區域內的水抽乾。
3. 排乾的艙室變成「乾區」，人員可以不穿潛水裝備活動。
4. 每擴建一個新區域，都要重複「密閉 → 排水 → 維生」。
5. 維生系統（氧氣、暖氣、除濕）的容量會限制基地能擴多大。

> 這套「乾區 / 濕區」的判定，之後會直接沿用到潛艇的艙室進水系統（§2），兩邊共用同一套水位模型。

### 4.4 資源
- **礦業：** 冰洋與海床都有豐富的水下礦脈與山體，是推進科技與造艦的主要來源。
- **發電：** 地下熱液泉（類似原版的蒸汽間歇泉，但在水下）。
- **特殊資源：** 可燃冰（燃料 / 化工原料）、黑曜石（火山活動帶的建材）等。
- 越深的層級，資源越稀有、越珍貴。

### 4.5 潛艇建造（比照重力船）
在水下基地的船塢建造。初步的艙段 / 設施清單：

| 類別 | 項目 | 功能 |
|---|---|---|
| 結構 | 船體平台（`DepthRim_HullPlatform`，已實作） | 潛艇的基礎甲板，比照 DMSE 軌道平台：只能鋪在深淵上、承載 Heavy（水密隔牆與水密艙門都能蓋）、邊框與下方側面由 `SectionLayer_HullPlatformProps` 畫（比照 Odyssey 的 `SectionLayer_SubstructureProps`，貼圖 `Textures/Thing/DR_LightPlatform`，路徑在 `HullPlatformPropsExtension`）：側面只畫進深淵格，往下第二格是實地時只畫上半。不用原版 `spaceEdgeGraphicData`，因為原版側面一律畫滿兩格、靠地形蓋掉落在實地上的部分，和不透明的深淵背景互相衝突。拆除沿用 DMSE 的「拆除平台」，海洋層上拆完露出深淵（DMSE 讀海洋層 `TransferEnvironmentExtension` 的 `voidTerrain`），返還一半鋼材 |
| 結構 | 水密隔牆 | 船殼不分等級，水密隔牆可撐到淵底；水壓損傷依牆兩側壓力差判定（§5.1） |
| 結構 | 水密艙門 / 隔艙 | 把進水限制在單一艙室 |
| 動力 | 反應爐 / 電池組 | 推進、照明、維生 |
| 維生 | 氧氣再生、除濕、暖氣、排水泵 | 艙內環境維持 |
| 航行 | 壓載水艙、推進器、艦橋 | 下潛 / 上浮 / 移動 |
| 感測 | 主動 / 被動聲納 | 世界地圖視野、預警 |
| 武裝 | 魚雷管、誘餌發射器 | BVR 攻擊、攔截 |
| 對接 | 對接艙門、月池 | 跳幫攻防、整備突擊艇 |
| 出艙 | 氣閘 / 潛水裝備櫃 | 下錨時出艙作業 |

### 4.6 航行狀態（比照 DMSE 軌道船）
- **本地地圖：** 只顯示艙內，艙外不渲染。
- **世界地圖：** 視野只有聲納範圍。
  - 主動聲納：範圍大，但會暴露自己的位置。
  - 被動聲納：範圍小，但安靜。
- **允許艙內施工：** 可以在航行中改建內部，但只要拆掉外殼牆體，就會依 §2 判定為破口。
- **禁止出艙。**

### 4.7 下錨狀態
- 只能在**淺海**或**海床觸底**時下錨。
- 下錨後艙外才會顯示，而且是一張**完整的地圖**：水下礦物與山體、地下熱液泉、可燃冰、黑曜石等。
- 人員可以穿潛水裝備出艙：採礦、探索遺跡、打撈失蹤人員、從外側修補船殼。
- 如果這張地圖上有運作中的主動聲納，就可能遭到襲擊（見 §6.3）。
- 變溫層和深海（未觸底）不能下錨。

### 4.8 潛艇實作（2026-11-09，DMSE 轉移飛行換皮）

整套航行沿用 DMSE 的轉移飛行（結構樁網路 → 控制台計畫 → 倒數 → 分離到船體地圖 → 點火／滑行／點火 → 抵達或選位降落、安全期），DepthRim 只補海洋層需要的部分。DMSE 的設計見 `_Dead-Man-Switch-Expedition/docs/CelestialTransfer_轉移飛行重構.md`。

| 部分 | 做法 |
|---|---|
| 讓海洋層可以起飛 | `DepthRim_Ocean` 掛 `DMSE.TransferEnvironmentExtension`：虛空 = 深淵、船體地圖 = `DepthRim_SubmarineHull`（只鋪深淵）、父物件 = `DepthRim_Submarine`。 |
| 船體 | 龍骨框架（`DepthRim_Keel`／`DepthRim_KeelSmall`，DMSE 結構樁換皮）。`allowedTerrains` 只有船體平台：船體 = 樁覆蓋範圍內的平台格與上面的東西，海床不會被帶走；樁也只能蓋在平台上。所以潛艇只能在深淵上的船塢建造。 |
| 船塢 | 船體平台只能鋪在深淵上，而升降井通到的極地冰蓋本來沒有深淵：極地冰蓋生成 1～2 個深淵坑（`WaterMapExtension.abyssPockets`，半徑 9～13）。井底出口周圍的深淵會填回海床。 |
| 艦橋 | `DepthRim_Helm`：DMSE 轉移控制台換皮，另掛 `CompDiveControl`（巡航深度）。 |
| 推進器 | `DepthRim_Thruster`（推力 3、150 W）與 `DepthRim_AdvancedThruster`（磁流體，推力 8、300 W），繼承 DMSE 引擎基底；沒有尾焰區、不噴火、只冒氣泡，要接電。 |
| 能源 | 船上電池：`BatteryFuelSource` 註冊成 DMSE 的燃料來源（只在海洋層地圖上算數，1 單位 = 1 Wd），讓規劃畫面顯示儲電。出航不預扣（見下方航行規則）；成本是推進器在航行中的耗電：一具 150 W 的推進器每格（4 小時）約 25 Wd，一顆原版電池（600 Wd）約走 20 格。 |
| 航線 | 不能穿過陸地：`OceanRouting` 只走海洋格的廣度優先搜尋，取代 DMSE 的距離（`TransferFlightMath.Distance`）、航線（`BuildPath`），目的地也不能是陸地或海路到不了的地方。 |
| 深度 | `WorldObject_Submarine`（繼承 DMSE 的 `WorldObject_TransferShip`）實作 `IDepthTierProvider`。巡航深度由玩家設定，每小時換一層；實際層級不會比腳下的海床更深（航行經過淺海時自動被推上來）。往下潛不能超過海床，也不能超過船殼耐壓（`HullPressure`：朝外海的艙壁中最弱的那一個；一般牆與門算淺海、水密艙門算變溫層、水密隔牆算海床）。層級一變，整張地圖的水體重建。 |

**研究**（分頁「水下」，`1.7/Defs/Research/DepthRim_Research.xml`）：水下生存（500，需電力：升降井、潛水服、水密艙門、排水泵）→ 耐壓工程（1200：水密隔牆、船體平台）→ 潛航器建造（1600：龍骨框架、艦橋、水下推進器）→ 深淵潛航（4000：先進水下推進器）。→ 水下戰鬥（2400：主動聲納、被動聲納、魚雷發射管、魚雷）。深海科研點數還沒做，目前都用一般研究點數。

**世界地圖圖示**：`Textures/World/WorldObjects/Expanding/DepthRim_Submarine`（`.source/Tools/gen_submarine_icon.py` 產生的白色剪影，由 expandingIconColor 上色）。

**下錨**（2026-11-09）：下錨就是 DMSE 的降落。潛艇抵達後（不在航行中），「下錨」指令在旁邊一格（沒有世界物件、海床深度相同的海洋格）建立海洋地點，生成那裡的海床地圖，玩家選位後船體搬進去、潛艇世界物件移除；艙外從此看得見，穿潛水裝備的人員可以走下甲板。

- **深度規則**（`DiveMath.CanAnchor`）：只有淺海或深海海床有能下錨的底（變溫層、深海不行），而且潛艇要正停在那個深度（巡航深度等於海床、沒有在換層）。降落到既有的海洋地點（例如開回自己的基地）也守同樣的規則（`SubmarineLandingWorker`：DMSE 轉移飛行的降落 worker，掛在海洋層）。
- **海床記憶**（`MapComponent_SeabedMemory`）：船塢只能蓋在深淵上，但下錨可以停在海床上。平台蓋過海床時記下原本的地形；之後潛艇再離港（DMSE 把船體範圍設成深淵）或平台被拆掉，那格會換回原本的海床，不會留下深淵洞。
- 下錨地點用自己的格子會撞到潛艇本身的地圖，所以一定是旁邊一格。

**和 DMSE 不同的航行規則**（2026-11-09）：

- **推進器要一直運作才會前進**（`VoyageMath`、`WorldObject_Submarine.ApplyThrust`）：DMSE 的航程進度完全由時間決定（起飛時刻 + 點火／滑行時長），推進器只在分離那一刻檢查。潛艇每 60 ticks 重新勘查一次可用推力（通電、開著、沒壞的推進器），和出航時的推力相比；不足的部分把航程時鐘往後推，等於那段時間沒有前進。推力剩一半就以一半的速度前進；全部停擺時潛艇停在海中漂流（發一則訊息），推進器恢復後繼續。電池沒電、推進器故障、被關掉都會讓航程停下來。
- **就地停船**（`StopHere`）：航行中潛艇與艦橋上都有「就地停船」指令，結束航程，停在目前所在的格子，推進器回到待機。之後可以下錨，或從那裡重新規劃航程。
- **航程成本只有推進器的耗電**（`SubmarineEnergyWorker`：DMSE 轉移飛行的能源 worker，掛在海洋層；`CompThrusterDraw`）：DMSE 出航時一次扣掉整趟的燃料；潛艇不扣，海洋層上的 `TransferFlightMath.FuelRequired(survey, distance)` 回傳 0。推進器只有在航行中才全速耗電，其他時候（船塢、停泊、停船後）待機 10%。規劃畫面的「所需／可用」改成推進器功率 × 航行時間 對 電池儲電，最大航程 = 電池能讓推進器跑多久（`VoyageMath.RangeTiles`，上限 500 格），超出就不能選。估算只算推進器，艦橋、照明等其他用電也會吃電池；航行中沒電就會停在海中，充電或接上發電機後繼續。

**還沒做**：見 §11 實作計劃的 M4 起。

## 5. 水深分級

不使用絕對深度數值，而是用**四個層級**套用不同機制：

| 層級 | 光照 | 水壓（進水倍率） | 可下錨 | 主要威脅 / 事件 | 船殼需求 |
|---|---|---|---|---|---|
| **淺海** | 微光 | 低 | ✅ | 海盜潛艇、魚群 | 一般牆 |
| **變溫層** | 幾乎無光 | 中 | ❌ | 聲納干擾（溫躍層遮蔽）、伏擊、跳幫突擊艇 | 水密隔牆 |
| **深海** | 無光 | 高 | ❌ | 深海海盜、大型生物、結構疲勞 | 水密隔牆 |
| **深海海床** | 無光（生物光） | 極高 | ✅（觸底） | 遺跡、稀有礦藏、星艦相關內容 | 水密隔牆 |

機制建議：
- **船殼等級低於層級需求：** 持續累積結構疲勞，隨機造成船殼受損。
- **變溫層聲納遮蔽：** 躲在溫躍層下面比較不容易被偵測，但自己也聽不太清楚。
- **層級決定襲擊池：** 每一層有自己的事件與襲擊清單。
- **心情：** 越深越壓抑（無光、幽閉恐懼），需要照明、娛樂、舒適度來抵銷。

### 5.1 牆體水壓損傷判定（2026-11-09 實作：`WallPressureTopology`、`MapComponent_WallPressure`）

船殼不另外分等級：**水密隔牆就是最高級的耐壓牆**（`LeakResistanceExtension.pressureRating = Seabed`），潛艇和水下基地都用它撐到淵底。

**實作時的決定**：厚度加成取「÷ min(厚度, 2)」（兩層牆有加成，再疊沒有）；耐壓上限 = 等級的水壓倍率（淺海 1、變溫層 2、深海 4、海床 8）；每次更新每 1 點超載扣 0.4 HP，一般鋼牆（300 HP）在深海約 1 天、在變溫層約 3 天被壓壞；第一次壓壞牆時發一則訊息（每張地圖一天最多一次）。拓樸只在牆／門變動（`RegionDirtyer` 的三個方法）或密閉艙室改變時重建。

**核心規則：牆承受的是兩側的壓力差，不是所在深度。** 只看「這面牆在幾公尺深」會讓雙層牆的內層也一起被壓壞，這不對。

**1. 每個房間的壓力。** 每間房間有一個壓力比例 p（0 = 艙內一大氣壓，1 = 外部水壓）：

| 房間 | p | 理由 |
|---|---|---|
| 開放水域（`IsOpenWater`：碰到地圖邊緣或有沒屋頂的格子） | 1 | 就是外海 |
| 密閉艙室 | 等於它的水位（0–1） | 在數百公尺深處，進水的艙室會把空氣壓縮到幾乎沒有體積，水位滿了就等於和外海同壓。直接沿用現有的格子水位，不必另外存壓力 |
| 門口格（`IsDoorway`） | 取兩側房間中較高的 p | 關著的門也是艙壁的一部分 |

**2. 找出一面牆兩側的房間：雙標籤 BFS，結果快取起來。**

先前的寫法是每 250 ticks 掃一遍所有密閉艙室的 `BorderCellsCardinal`，再從每一格往外直線走。這樣有三個問題：
- 每次更新都重算一遍，可是牆的位置其實很少改變。
- 直線只看單一方向，L 形牆、T 形接頭和轉角牆厚會判錯。
- 碰到靠在岩壁上的牆，要靠固定的步數上限才停得下來。

改成「只在牆改變時重算拓樸，每次更新只套用壓力」：

- **障壁格**：有 edifice 而且不可通行的格子（牆、門、排風口、自然岩）。
- **建快取（雙標籤 BFS）**：
  - 從每個和房間正交相鄰的障壁格開始，多源 BFS 只在障壁格裡擴散。每格最多記住**兩個不同房間**的標籤和距離（最近的兩個），距離上限是 `MaxWallThickness` = 4。
  - 同一格收到第三個標籤時就丟掉；每格最多被展開兩次，成本是 O(2 × 帶狀範圍內的障壁格)。
  - 標籤不存 `Room` 物件，存那個房間的**種子格**（與障壁相鄰的那一格可通行格）。每次更新再用 `seed.GetRoom(map)` 查回房間，所以原版重建或重用 `Room` 物件時，快取不會失效。
- **快取的內容**：每個帶有兩個標籤的障壁格存一筆 `(cell, seedA, seedB, thickness = dA + dB − 1)`。
  - 只有一個標籤的格子（岩體內部、只面對一個房間的牆）不存，永遠不受力。
  - 靠在厚岩壁上的牆，另一側的標籤超過距離上限，自然就不受力；不需要另外判斷自然岩。
- **只在密閉艙室附近建**：BFS 的種子限制在「密閉艙室的障壁格」往外 2 × `MaxWallThickness` 的範圍內。一張還沒有基地的海洋地圖完全沒有密閉艙室，快取是空的，每次更新的成本是零。
- **何時重建**：
  - Harmony postfix 掛在 `RegionDirtyer.Notify_WalkabilityChanged(c)` 和 `RegionDirtyer.DirtyRegionForThing(t)`（牆、門蓋好或被拆掉時原版都會呼叫）以及 `SetAllDirty`，只標記「髒」，不立刻重算。
  - 屋頂改變不會讓區域變髒，可是會改變哪些房間算密閉。所以每次更新另外比對「密閉艙室數 + 總格數」的簡單雜湊，有變化也標記髒。
  - 下一次 250 ticks 更新時，有髒標記才整份重建一次，同一段時間內蓋了很多牆也只重建一次。快取不存檔，讀檔後第一次更新時重建。
  - 之後如果整份重建太慢，可以改成只重算髒格周圍 2 × `MaxWallThickness` 的方塊。這個方塊外面的標籤不受影響，因為標籤只看距離上限內的格子。

**3. 每次更新：套用壓力與損傷。**

- 對快取裡的每一筆，查兩側房間的 p，Δp = |p<sub>A</sub> − p<sub>B</sub>|。房間的 p 直接取 `roomLevel` 和 `openRooms`，這兩個在同一輪更新裡已經算好了。
- Δp 小於 ε，或這一格是打開的門（兩側正在等化），就跳過。大部分格子在這一步就結束：兩側都是乾艙，或兩側都是海。
- 負載 = Δp × `PressureFactor(tier)` ÷ thickness。負載超過牆的耐壓上限（由 `pressureRating` 換算）時累積損傷，存在一個 float 陣列裡，滿 1 點才呼叫一次 `TakeDamage`，避免每次更新都對幾百面牆送傷害。自然岩不扣血。
- 成本是 O(快取筆數)，大約等於基地外殼的格數 × 厚度。不會再列舉 `BorderCellsCardinal`，也沒有迭代器配置。

**順帶的好處**：`AccumulateLeaks` 現在要用 `HighestNeighborRoom` 找受損牆的水源。改用同一份快取，就能直接從兩個標籤拿到牆的兩側（也包括厚牆的另一側）。

**可以單獨做單元測試**：拓樸計算抽成純函式 `WallPressureTopology.Build(width, height, isBarrier, roomIdAt)`，不碰遊戲物件。下面表格裡的每一種情況，都能在 `DepthRim.Tests` 裡用小網格驗證；遊戲內驗收測試只需要確認 Harmony 的髒標記有接上。

**這樣判定之後，各種情況的結果：**

| 情況 | 結果 |
|---|---|
| 單層牆：外海 \| 牆 \| 乾艙 | Δp = 1，牆承受全部負載 |
| 雙層牆、夾層乾燥：外海 \| 外牆 \| 乾夾層 \| 內牆 \| 乾艙 | 外牆 Δp = 1；內牆兩側都是 0，**不受力** |
| 外牆破了、夾層灌滿 | 夾層 p 跟著水位升到 1，負載自動轉到內牆。外牆兩側都是 1，不再受損 |
| 兩格厚的實心牆：外海 \| 牆牆 \| 乾艙 | 同一段牆厚 2 格，每格承受一半 |
| 兩間都是乾艙之間的隔牆 | Δp = 0，不受力 |
| 立在外海裡的牆、兩側都是海 | Δp = 0，不受力 |
| 艙室半滿 | Δp = 1 − 水位，進水越多牆的負擔越小（但艙室已經在淹） |

**實作時要注意的地方**

- **夾層一定要有屋頂。** 沒有屋頂的夾層會被 `IsOpenWater` 判成外海（p = 1），外牆不受力、內牆承受全部負載，雙層牆就等於沒用。原版的自動屋頂（`AutoBuildRoofAreaSetter`）只會替 320 格以下、26 個區域以下的房間標記屋頂區，而且只是標記，還要有人去蓋。一圈繞著整座基地的夾層很容易超過 320 格。要處理的話，可以加一則提示（「夾層沒有屋頂，會被當成外海」），或者讓整面被牆圍住的狹長空間也能自動標記屋頂。
- **兩格厚的牆能不能取代水密隔牆**是平衡上的選擇：照上面「負載 ÷ thickness」的算法，兩層一般牆可以撐到兩倍深度。如果不想讓一般牆疊厚就撐到深海，負載就不要除以 thickness（厚度不加成），或者改成只除以 min(thickness, 2)，限制加成的幅度。
- **排風口**（原版 `ImpassableFreeAirExchange` 區域型）兩側在原版是不同房間，要和門一樣當成艙壁。水密排風口偵測到進水自動關閉，關著時就是牆。
- **潛艇地圖**用同一套規則；`DepthTier` 改由 `IDepthTierProvider` 依下潛深度提供，所以潛艇上浮時負載會自然下降。
- 掉血要用原版的 `TakeDamage`（DamageDefOf.Deterioration 或自訂的水壓傷害），牆壞了之後現有的滲水和破艙判定就會接手。

### 5.2 中層水域：地形下方經過的生物（2026-11-09 實作）

無法下錨的變溫層與深海，「腳下」不是海床而是更深的水。這一層比照原版 `MapDrawLayer_OrbitalDebris`（太空地圖地板下方的軌道碎片），在深淵格底下畫出經過的生物。巨物經過事件也用這一層演出。

| 部分 | 實作 |
|---|---|
| 層級 | `MidwaterMath.ShowsMidwater`：只有變溫層與深海。畫面看視覺層級（`RenderTier`，除錯覆寫可切換）；背景生物與事件看實際層級。 |
| 生物定義 | `MidwaterCreatureDef`（`1.7/Defs/Midwater/Midwater.xml`）：貼圖朝 +x、大小、色調、速度、深度（parallax）、層級、擺動參數。分成巨物（`giant`，只由事件叫出）和背景生物（`ambientWeight`）。目前有鯨魚（變溫層巨物）、大王魷魚（深海巨物）、魚群（變溫層背景）、水母（兩層背景）。 |
| 模擬 | `MapComponent_Midwater`：每隻生物沿直線從地圖外游到地圖外（`MidwaterMath.CrossingPath`），前後 12% 的路程淡入淡出。背景生物每 900 格深淵一隻、最多 5 隻，不存檔；巨物存檔。 |
| 畫面 | `MapDrawLayer_Midwater`（原版自動為每張地圖建立的全域繪製層）：每幀依生物位置建四邊形，依深度把位置與大小往鏡頭正下方縮（透視：越深移動越慢、越小）。著色器 `DepthRim_Midwater`（renderQueue 3178，在外海層 3177 之後、光照暗化 3180 之前：畫在外海層下面會被 85% 的水色完全蓋掉，驗收截圖實測）用深淵遮罩貼圖把生物裁在已探索的深淵格裡，所以牠們只會在深淵上方出現一片暗影，海床、岩體與迷霧上都沒有。眼睛、水母發光管等亮部另外用 `glowColor` 發光。 |
| 深淵遮罩 | 每格一個像素，已探索的深淵 = 1。地形或迷霧改變時由繪製層重建；貼圖屬於 `MapComponent_Midwater`，地圖卸除時銷毀。 |
| 巨物事件 | `DepthRim_GiantPasses`（`IncidentWorker_GiantPasses`）：深淵至少 300 格、同時只有一隻巨物。原版說書人只挑 `Map_PlayerHome` 等目標，不會挑海洋地圖，所以由 `MapComponent_Midwater` 依平均 4 天一次自己觸發；海洋地點帶 `DepthRim_OceanMap` 標籤，開發者選單也能直接執行。發出中性訊息，並在目前地圖播一聲船殼低鳴。 |
| 除錯 | 開發者選單「DepthRim → Midwater creature passes」：在目前地圖叫任一種生物（不檢查層級；要看到畫面，先用「Override water visual tier」切到變溫層或深海）。 |

**要注意**：變溫層目前不挖深淵（`FloodingMath.CarvesAbyss` 只有深海與海床），所以變溫層地圖上暫時看不到這一層，要等潛艇航行地圖（艙外就是深淵）或變溫層開始挖深淵後才會出現。

## 6. 戰鬥：BVR + 跳幫

建立在 DMSE 的軌道船與 BVR 系統上（硬相依）。

**觸發條件：** 只有在設有主動聲納的地圖上才會發生水下襲擊。

### 6.1 交戰流程（航行中）
```
聲納預警 ──► 目標分類（魚群 / 海盜潛艇 / 跳幫突擊艇 / 未知）
   │
   ├─ 玩家選擇：迴避 / 靜默 / 主動攻擊
   ▼
地圖外 BVR 階段
   ├─ 發射魚雷攻擊敵艦
   ├─ 發射魚雷 / 誘餌攔截來襲的突擊艇或魚雷
   └─ 被敵方魚雷命中 → 我方某段外殼受損（進水）或破口（艙內人員失蹤）
   ▼
攔截失敗 → 敵方突擊艇抵達
   ▼
本地地圖：突擊艇穿入船艙 → 室內跳幫戰
   ▼
襲擊撤退 → 存活的敵人登上突擊艇脫離
```

### 6.2 跳幫突擊艇
- 本質是一種**特殊的運輸艙**：穿入船艙時**不會破壞密閉性**（不會造成進水）。
- 突擊艇會留在艙內；襲擊撤退時，敵人會回到艇上**載人脫離**（可能帶走俘虜或物資）。
- 摧毀停在艙內的突擊艇，就能切斷敵方退路。
- **玩家方：** 可以在**月池**建造與整備自己的突擊艇，主動跳幫敵方潛艇（掠奪、俘虜、奪船）。

### 6.3 下錨時的襲擊（淺海 / 海床）
- 突擊艇不直接穿入船艙，而是降落在海床上，放下**穿重型潛水服的海盜突擊隊員**。
- 突擊隊員從艙外推進，可能攻擊外殼（造成受損進水，甚至破口）或嘗試從氣閘 / 對接艙門突入。
- 出艙作業中的殖民者會直接暴露在交戰中，所以下錨時的出艙安排本身就有風險。
- 撤退時，突擊隊員回到海床上的突擊艇脫離。

## 8. 實作切入點（基於 RimWorld 1.6 / Odyssey 原版系統）

以下類別已在原版源碼中確認存在，可以作為參考或掛鉤點：

| 需求 | 原版參考 | 備註 |
|---|---|---|
| 乾區 / 濕區、艙室水位 | `Verse.VacuumComponent : MapComponent` | Odyssey 的真空系統是「室外為真空、密閉艙室保有空氣」，正好可以反過來用成「室外是水、密閉且排乾的艙室是乾區」。不過水位需要持續的進水 / 排水數值，而不是只有開或關，所以要另寫 `MapComponent_Flooding`，每間艙室存一個水位值。 |
| Pawn 水位渲染 | Pawn 渲染管線（待查） | 依所在艙室水位裁切 Pawn 下半部並改色，可能需要 Shader 或額外疊一層遮罩。 |
| 環境水壓抗性 | 自訂 `StatDef` | 由裝備 / 義體 / 基因提供，和地圖的水深層級比對。 |
| 終局任務 | 原版 Journey Offer 任務 | 以它的任務結構為範本，改寫成水下版本。 |
| 潛艇建造與船體判定 | `RimWorld.SubstructureGrid`、`RimWorld.GravshipUtility` | 「比照重力船」：參考它判定連通船體範圍的方式，改成耐壓船殼。 |
| 潛艇在世界地圖移動 | `RimWorld.Planet.Gravship : WorldObject` / DMSE 軌道船 | Odyssey 的飛船在飛行中**沒有地圖**；DepthRim 航行時要保留艙內地圖，所以以 DMSE 軌道船的航行模式為主。 |
| 海洋地圖 | Odyssey `PlanetLayerDef` | 研究 DMSE 後改為獨立的圖層（而非 `PocketMapParent`），潛艇才能在世界上航行；升降井做成 `MapPortal`。詳見 [DMSE_對接研究.md](DMSE_對接研究.md) §4。2026-11-01 起「冰洋」擴充為有七種生態區的「海洋」圖層，冰洋成為其中的極地冰蓋，見 [海洋圖層與生態區.md](海洋圖層與生態區.md)。 |
| 跳幫突擊艇 | 原版運輸艙 / 空投艙 | 改成不破壞屋頂與密閉性的穿入方式，並加上撤退時的回收邏輯。 |
| 失蹤處理 | — | 把 Pawn 移出地圖並保存在世界中（不殺死），供之後的打撈事件取回。 |

> 以上仍是概念階段的筆記，動工前需要再逐一用源碼（以及 DMSE 的實作）確認細節與 Patch 點。
