# DepthRim — 概念與玩法設計稿 v0.3

> 一句話：**深海才是敵人，潛艇是唯一的庇護所。**
> 不是「換皮太空」，而是一個「看不見、出不去、壓力無所不在」的生存模組。

**前置需求：** 硬相依 DMSE（未來可能統合為同一框架）。

---

## 0. 設計範圍與基調

| 原則 | 說明 |
|---|---|
| 水面只當出入口 | 沒有水面航行與水面事件。海面只做兩件事：海面地圖與海上平台（§4.4b），以及潛艇上浮／破冰上浮後停在原地（[潛艇破冰出水_機制設計.md](潛艇破冰出水_機制設計.md)）；要移動就得先下潛。 |
| 襲擊綁定主動聲納 | 水下襲擊只會發生在玩家設有**主動聲納**的地圖上。沒有主動聲納的地圖（例如早期的冰洋基地）威脅只來自環境：進水、水壓、維生。主動聲納同時也是發現值得探索的水下地點的唯一手段，所以「要不要開聲納」本身就是一個風險換收益的選擇。 |
| 生物從簡 | 就算加入水下生物，也只做少量、行為簡單的種類。 |
| 礦業豐富 | 深海的回報是資源：礦脈、熱泉等，用來支撐開採與發電。 |
| 高挑戰 | 環境本身就足以致命，玩家的每一步擴張都必須先顧好排水與維生。 |

## 1. 核心設計支柱

| 支柱 | 說明 | 與「軌道 / 太空」的差異 |
|---|---|---|
| **封閉** | 航行期間只能待在艙內（比照 DMSE 軌道船）；淺海或海床下錨時才能出艙。 | 真空是逐格擴散的失壓；深海則是依船殼受損程度與深度持續進水。 |
| **無光** | 艙外一片漆黑，航行時連艙外都不顯示；下錨後艙外才可見。 | 太空至少看得到星光和敵艦。 |
| **水壓** | 越深，船殼受損造成的進水越快；牆體完全破口時，整間艙室會瞬間淹沒。 | — |
| **聽而不見** | 戰鬥靠聲納和魚雷在地圖外進行（BVR）；等你真的看到敵人，通常已經是對方跳幫上艙了。 | — |

## 2. 船殼損傷與進水規則

### 2.1 兩種狀態

| 狀態 | 定義 | 結果 |
|---|---|---|
| **船殼受損** | 船艙牆體被打傷，但還沒完全摧毀。 | 依**受損百分比 × 當前深度層級**決定進水速度，艙室水位逐漸上升。 |
| **船殼破口** | 船艙牆體被**徹底摧毀**。 | 該艙室立即淹沒；航行中發生時，**艙內殖民者全部判定失蹤**。 |

### 2.2 水位模型
- **每間艙室（Room）一個水位值**（0–100%），不做逐格計算，以兼顧效能。
- 水位上升的艙室會讓殖民者移動變慢、溺水，也會損壞設備與物品。
- **視覺：** 依艙室水位高度裁切 Pawn 的渲染，從腳往上把被淹到的部分改成水色，讓玩家一眼看出水淹到哪裡。

#### 實作（`MapComponent_Flooding`，2026-11-01）
- **開放水域：** 碰到地圖邊緣、或有任何沒屋頂格子的房間，水位固定 100%。牆被打穿、房間連到外面，就會立刻變成開放水域。
- **密閉艙室**的水位只會因三件事改變：
  - 受損牆體滲水：受損比例 × 水壓倍率（淺海 1、變溫層 2、深海 4、海床 8）× 兩側水位差。
  - 打開的門：兩側水位往平均值流動。
  - 排水泵：每秒抽 2 格。
- **存放：** 水位存在每一格（0–255），房間水位 = 格子平均。原版每次牆體變動都會重建房間物件，用格子存就能讓新房間自然繼承水位，不需要 patch 原版房間重建。
- **對 Pawn 的影響**（每 250 ticks 結算）：
  - 涉水減速。
  - 沒入水中（站著 ≥ 75%、躺著 ≥ 30%）又沒有潛水服氧氣時會溺水，約 1 小時致死。
  - 水下呼吸裝備（`CompDivingAir`）：潛水服 36 小時（每 tick 回充 30）；原版 Odyssey 真空服頭盔配真空服身體（`requiredApparel`）12 小時、不給水壓抗性，只適合淺海。
  - 水壓抗性不足時累積水壓傷害。
- **Pawn 水位渲染**（`PawnWaterRendering`）：在水中時，每個渲染節點的材質換成原版 CutoutComplex 著色器，配一張垂直漸層遮罩。水線以上是遮罩紅色（主色 = 原色），水線以下是綠色（第二色 = 原色 × 水色）。人形身體節點約佔全身高度 0–72%、頭部約 62–100%；躺著時水位到 30% 就整個上色。不需要自訂著色器。
  - 限制：雙色衣物在水中會失去第二色；遮罩顏色慣例（紅 = 主色）要進遊戲確認。
- **水體顯示**：分兩層，GLSL 放在 `1.7/Shaders`。1.7（Waylith）會在執行期編譯，做法比照 DMS 本體。
  - **外海層**（`SectionLayer_WaterOuter` + `DepthRim_WaterOuter.frag.glsl`）：
    - 繪製順序 3177，介於原版迷霧（3175）和光照暗化（3180）之間，關閉深度測試。開放水域裡的岩體、建築、Pawn 都會被蒙上一層水，未探索的迷霧區變成深海，燈光仍然照得到水面。
    - 涵蓋範圍是迷霧格加上已探索的開放水域和岩體。已探索的密閉艙室和它們的牆不在網格裡，所以沿格子邊界乾淨地切開，並往艙室方向淡出。網格本來就是逐格的，不需要模板遮罩。
    - 迷霧格一律只帶迷霧權重，不用房間或地形資料，避免洩漏未探索的洞穴。
  - **艙室層**（`SectionLayer_WaterVolume` + `DepthRim_WaterVolume.frag.glsl`）：
    - 只畫密閉艙室裡的積水，畫在 MoteLow 高度（建築之下）。頂點水位只平均同一間艙室的格子；碰到牆和關著的門算岸邊。
  - 每格的「開放水域」旗標由 `MapComponent_Flooding` 每次更新寫入，渲染在平行執行緒也能查。Pawn 水線只用在密閉艙室；開放水域的 Pawn 由外海層蓋住。
  - 冰洋地圖現在有迷霧（`GenStep_IceOceanFog`）：開放水域可見，岩體內部保持迷霧，升降井出口會從出口揭開。
- **光照與混濁度（2026-11-01，細節見 [水體視覺.md](水體視覺.md)）：**
  - 每個水體頂點取周圍四格的光照平均寫進頂點色的 g 通道（迷霧格一律 0，不洩漏迷霧下的光源）。光照量 = **日光與人造光取大者**：日光取原版 `skyManager.CurSkyGlow`（無屋頂時），所以白天淺海整片都算有光、不會再有「明明有太陽卻一片不透明」的暗塊；人造光（燈、頭燈）用平滑衰減的原始值，燈下才會有一圈由亮到暗的漸層。
  - 日光會乘上層級的 `ambientReach`（淺海 1.0、變溫層 0.55、深海 0.25、海床 0.12）：日光本來就穿不深，深海在白天也不會因此變透明；人造光不折減。
  - 著色器用同一條公式算「清澈度」：光照 ≥ 0.6 視為清澈（`_ClearAlpha` 0.40–0.50，看得到海底但仍是水），≤ 0.05 視為全暗（`_MurkAlpha` 0.85–0.93，依層級，幾乎看不到海底）。所以**燈照到哪裡，水就看到哪裡**；關燈後只剩層級設定的微光。迷霧區固定 `_FogAlpha`，不受光照影響。
  - 潛水服自帶頭燈（`CompSuitLamp`，半徑 4.5、冷白光 (200,225,255)）：穿著者在水中時在腳下註冊原版自訂光源（`GlowGrid.RegisterCustomGlower`），每 15 ticks 檢查、換格才搬移，脫下／死亡／倒地 10 秒後解除。
  - 暗處的己方提示（`MapComponent_DarkWaterHints`）：己方 Pawn 站混濁的水裡（混濁度 ≥ 0.5）時，用原版剪影著色器畫一層淡青色輪廓，`alpha = (混濁度 − 0.5) / 0.5 × 0.6`。敵人、野生生物、密閉艙室裡的 Pawn 都沒有提示；跟著右下角的水體顯示開關。
- **水深層級化（2026-11-01）：**
  - 每個層級（淺海／變溫層／深海／海床）一組參數寫在 `1.7/Defs/Rendering/WaterVisualTiers.xml`（`WaterVisualTierDef`）：水色、深處色、迷霧色、混濁度上下限、波紋尺度與強度、光紋、光柱、海洋雪、生物光、沉積霧氣、變溫層晃動。
  - 淺海：大尺度波紋與穿過冰層的光柱；變溫層：水面晃動與稀疏懸浮物；深海：日光幾乎穿不到，燈下看得到海洋雪、關燈只剩生物光；海床：貼地沉積霧氣＋生物光。
  - 海洋雪是兩層不同速度的亮點（視差），每顆自己的擺幅、頻率、相位、大小與亮度都不同，所以不會整片同步往下滑；`snowSpeed` 是倍率，改 Def 就能調快慢。
  - 外海層與艙室層各準備四個材質（`WaterTierMaterials`），地圖層級改變時整張重建。艙室層只讀水色、深處色、混濁度與波紋尺度，**不套用**海洋雪／生物光／霧氣／晃動。
  - 除錯動作「DepthRim: Override water visual tier」可以手動切換層級看畫面（只影響渲染，水壓與滲水速度仍照地圖實際層級）。
- **冰洋地圖的屋頂規則（驗收測試發現後修正）：** 開放水域沒有屋頂，只有岩體上方有岩頂。玩家要圍牆**並蓋人造屋頂**才算密閉艙室。地圖生成器不能設 `isUnderground`，否則原版會把整張地圖鋪滿厚岩頂、高度全設為岩體，玩家永遠蓋不出艙室。
- **水下基地不會消失：** `WorldObject_IceOceanSite` 在還有升降井出口或玩家建築時保留地圖。原版太空地圖父物件在沒人時會移除地圖。
- **水下 AI 找空氣**（`SeekAir.cs`，比照 Odyssey 真空的 `JobGiver_FindOxygen`）：沒入水中又沒有潛水裝備、或氣量偏低的玩家角色自己游到乾處；床淹水時睡著的人會被叫醒；找床與地鋪時排除淹水的位置。
- **還沒做：** 航行中破口的「整艙失蹤」判定（艙外的人落海失蹤已做，見 §4.8）。

### 2.3 進水的處理
- 可以用排水泵把水抽掉，並修補受損的牆體。
- 水密艙門 / 隔艙能把進水擋在單一艙室，這是潛艇設計的核心取捨：犧牲空間換安全。

### 2.4 失蹤與救回
- 因破口而失蹤的殖民者並沒有死，之後有機會透過**打撈 / 救援事件**找回（例如在海床找到殘骸艙或逃生艙）。

```
      │  在極地冰蓋建立地面基地
      ▼
[2] 建造升降井
      │  打通冰層，開啟「地下冰洋」地圖
      ▼
[3] 第一次下地
      │  穿戴潛水裝備的人員下去探勘
      ▼
[4] 冰洋探索
      │  尋找礦產與可用於發電的資源（熱泉等）
      ▼
[5] 升降井平台基地
      │  圍著平台建造密閉區、排水、供電
      │  排完水的區域，之後下來的人不需要再穿潛水裝備
      ▼
[6] 擴展設施
      │  排水隔艙與維生系統必須跟上擴建速度
      ▼
[7] 建造潛航器（比照重力船）
      │  在水下基地建造潛艇，探索冰洋的其他位置
      ▼
[8] 深海航行循環
      │  ├─ 在四個水深層級之間下潛 / 上浮

      │  ├─ 跳幫與反跳幫
      │  └─ 在淺海 / 海床下錨 → 出艙採礦、探索、打撈
      ▼
[9] 終局：啟動水下星艦
```

## 4. 各階段細節

### 4.1 冰蓋前進基地
- 起始地形限定在冰蓋生態區：極寒、資源匱乏。
- 定位是前哨、物資中轉站和升降井基座。
- 潛艇出航後仍繼續運作，作為母港。

### 4.2 升降井與第一次下地
- 「冰層升降井」完成後，會開啟一張附屬的**地下冰洋地圖**。
- 地下冰洋預設**整張都是水**；人員必須穿潛水裝備才能活動。

#### 潛水裝備的限制
| 限制 | 說明 |
|---|---|
| **氧氣時間** | 裝備內的氧氣會隨時間消耗，用完前必須回到乾區或補充。 |
| **工作效率** | 穿著裝備時工作速度下降（越重的裝備降得越多）。 |
| **移動效率** | 穿著裝備時移動速度下降。 |
| **環境水壓抗性**（新 Stat） | 決定能在哪個水深層級活動；水壓超過抗性就會持續受傷。裝備等級越高，抗性越高，但效率懲罰也越重。 |

> 「環境水壓抗性」也可以用在敵方海盜的重型潛水服、水下生物，甚至義體 / 基因上，成為一個通用的深度門檻。

#### 4.2a 壓力適應與加壓艙（2026-11-13 實作：`.source/DepthRim/Pressure/`）

和「環境水壓抗性」是兩件事：抗性管的是泡在水裡會不會被壓傷（裝備），適應管的是身體能不能待在這個深度（生理）。

- **適應值**：每個血肉角色有一個適應值（0–3，和壓力等級同單位：0 常壓／淺海、1 變溫層、2 深海、3 海床），存在 `DepthRim_PressureAdaptation` hediff 上，跟著角色跨地圖與存檔。機械體不用適應。
- **艙壓**（`MapComponent_PressureChambers`，每格存一個 0–3 級，存檔）：**密閉的艙室記住自己原有的壓力**（2026-11-13 使用者決定）。潛艇換深度、加壓機關掉都不會改變它；從海面出航的潛艇，乾艙一直是常壓。每 250 ticks 結算：同一間艙室取平均（牆拆掉時按格數混合）；「外面」（碰地圖邊緣或沒屋頂，水下地圖上就是開放水域）一律 0；撐不住壓力的艙室（地板不是耐壓甲板／船體平台，或有一般的門）每小時洩 0.5 級；開著的門讓兩側艙室互相靠近（門外是地表的外面時往 0 洩，門外是開放水域時不交換空氣，海水灌進來由水位系統處理）；運作中的加壓機把艙室推向目標。水不改變艙壓：淹水艙室的壓力看水位，抽乾後回到原本的艙壓。潛艇出航、下錨、上浮與下潛時，艙壓與水位跟著船體格子搬（`HullMoveHooks`，訂閱 DMSE 的 `ShipSeparationUtility.HullPlaced` 事件）。
- **環境壓力**（`PressureEnvironment`）：開放水域是地圖的水深層級；地表的外面與商隊是 0；艙室是「艙壓」與「水位 × 層級水壓」取大的；門口取兩側大的。
- **適應速度**：適應值一直往環境壓力移動，每 1 級要 `1 ÷ 血液過濾能力` 天，限制在 0.5～2 天（過濾 200% 以上半天、100% 是 1 天、50% 以下 2 天；2026-11-15 前是 `6 ÷ 呼吸能力`、4～8 天）。
- **不適**：適應值和環境相差不超過 1 級時沒有任何影響。超過的部分是嚴重度（下潛、上浮都算，最多 2）：輕微不適（> 0）、壓力不適（≥ 0.5）、嚴重壓力不適（≥ 1.25），降低意識、移動、操作並增加疼痛，**不致命**。例：從地表直接到深海，壓力不適半天、輕微不適半天；一級一級下潛、每級停 1 天左右則完全不會不適。
- **其他陣營與野生動物**第一次被記錄時視為已經適應所在的深度（跳幫的海盜不會一上船就不適）。
- **加壓艙**：`DepthRim_Pressurizer`（加壓機）把所在艙室推到玩家指定的壓力等級（0–3，指令調整），運作時每小時移動 1 級；停機時艙壓不變。艙室必須：有屋頂且密閉、不超過 80 格、地板全部是耐壓甲板或船體平台、所有的門都是水密門（`PressureChamberUtility.Problem`）；不符合「撐得住壓力」的條件時慢慢洩壓，破艙（變成外面）時立刻歸零。用途：在地表造一間高壓艙，讓從深處上來的人分段減壓（3 → 2 → 1 → 0，每級 0.5～2 天）；或下潛前先加壓。
- **耐壓甲板**（`DepthRim_PressureDeck`）：船體平台的陸上版本。船體平台是只能鋪在深淵上的基底地形，用 DMSE 的指令拆掉會露出該圖層的虛空，不能直接鋪在實地上；耐壓甲板是一般地板，提供同一個 `DepthRim_HullPlatform` 承載力。
- 耐壓甲板與加壓機由「耐壓工程」解鎖。

- **活動範圍靠水密門**（`Building_WatertightDoor.PressureAllows`、`PressureAdaptationMath.DoorAllows`）：門兩側壓力不同時（加壓艙，或水下地圖上乾艙對外海），走過去會比現在更不適的**玩家角色**不會自己通過（其他陣營的 AI 不受限）。所以適應中的人留在艙裡（適應到和門外差 1 級以內才出得去），沒適應的人也不會闖進去。徵召中照命令走；已經不適的人可以往比較不糟的一側走；機械體不受限。和淹水側規則一樣走原版的 `PawnCanOpen`，可達性與尋路一致；艙壓或適應值每變 0.1 級清一次可達性快取。
- **開門洩壓**：水密門每開一次，兩側艙室的艙壓互相靠近 0.1 級；門開著的期間每小時 2 級（比加壓機快）。
- **艙壁耐壓：和外海同一套**（§5.1 的 `MapComponent_WallPressure` 是唯一的損傷來源）：每間房間換成絕對壓力（常壓 0、淺海 1、變溫層 2、深海 4、海床 8；艙壓 L 級 → 0 級是 0、其餘是 2^L，`PressureAdaptationMath.GaugeOfLevel`），負載 = 兩側差 ÷ 厚度（最多 2），上限一般牆 1、水密門 2、水密隔牆 8，每超載 1 點每 250 ticks 扣 0.4 HP。水下地圖照舊算所有密閉艙室；其他地圖只在有艙壓時算有艙壓的艙室。加壓機的檢視面板顯示邊界上超載的格數。結果：地表 1 級艙要兩層一般牆或水密隔牆，門用水密門；2 級艙的門對常壓撐不住，要接一間 1 級的前艙；3 級艙目前沒有門撐得住（要等耐壓艙門）。潛艇的乾艙是常壓，所以船殼承受全部的海壓；把艙室加壓到和外海一樣時那一面不受力。
- **出艙的水壓抗性**：泡在水裡時的缺口 = 水深層級 − 裝備抗性 − 適應值（`FloodingMath.PressureShortfall`，不再取整數）。潛水服給 2 級抗性（2026-11-16 起，原本 1 級）：不用適應就能在深海出艙，適應到 1 級可以在海床出艙。升降井只通淺海與變溫層的限制沒有變。
- **警示**（`Alert_PressureSickness`）：有殖民者壓力不適時顯示，列出每個人的適應值、環境壓力與大約還要多久。

**還沒做**：加壓機沒有「自動一級一級調整」的模式（要玩家自己調）；沒適應的醫生不徵召就進不了艙照顧病人；沒有耐壓到海床的門（3 級艙與深海出艙需要）；艙壓高於外海時不會擋住進水。

### 4.3 水下基地：排水與擴張
這是前中期的主要玩法，邏輯是「把水趕出去」：

1. 圍著升降井平台蓋出密閉的牆體與屋頂。
2. 架設排水泵與電力，把密閉區域內的水抽乾。
3. 排乾的艙室變成「乾區」，人員可以不穿潛水裝備活動。
4. 每擴建一個新區域，都要重複「密閉 → 排水 → 維生」。
5. 維生系統（氧氣、暖氣、除濕）的容量會限制基地能擴多大。

> 這套「乾區 / 濕區」的判定，之後會直接沿用到潛艇的艙室進水系統（§2），兩邊共用同一套水位模型。

### 4.4 資源
- **礦業：** 冰洋與海床都有豐富的水下礦脈與山體，是推進科技與造艦的主要來源。
- **發電：** 地下熱液泉（類似原版的蒸汽間歇泉，但在水下）。
- **特殊資源：** 可燃冰（燃料 / 化工原料）、黑曜石（火山活動帶的建材）等。
- 越深的層級，資源越稀有、越珍貴。

### 4.4b 海面地圖：水面層與平台層（2026-11-13 改成兩層）

地表圖層海洋格上的地點（`DepthRim_SeaSurfaceSite`，`WorldObject_SeaSurfaceSite`）。為了讓平台的高度差畫得正確，海面分成兩張座標對齊的地圖（偽多層，`SeaLevels`）：

| | 水面層 | 平台層 |
|---|---|---|
| 地圖 | 海面地點本身（地圖生成 `DepthRim_SeaSurface`） | 水面層的口袋地圖（`PocketMapParent`，`sourceMap` = 水面層，生成 `DepthRim_PlatformLevel`），同尺寸、同世界格子 |
| 「空」的地形 | 開放海面 `DepthRim_OpenSea`（承載力 OpenSea、OpenWater） | 高空 `DepthRim_OpenAir`（承載力 OpenAir）；兩者都 `dontRender`、不可通行 |
| 能蓋的地形 | 船體平台（浮在水面，§4.5） | 海上平台 `DepthRim_OceanPlatform`（只能在支柱支撐範圍內） |
| 看到的海 | 原位（`_Height.x` = 0） | 下方 14.1 格（`SeaDropCells`） |
| 看到另一層 | 平台的影子（遮罩 r）、從入水處往上伸的柱身 | 水面層的地形與建築快照（`SectionLayer_LowerLevel`），畫在 14.1 格下方 |

- **建立**：新的海面地圖只有海、沒有平台層。玩家在開放海面上蓋第一根平台支柱時建立平台層（`SeaLevels.GetOrGeneratePlatformLevel`：比照原版口袋地圖，但地點設在水面層的格子上，天空、日照一致；溫度由 `Patch_PlatformLevelTemperature` 改用水面層的室外溫度）。之後的支柱共用同一張平台層。
- **平台支柱**：`DepthRim_PlatformPillar`（`Building_PillarFoot`，原版 `MapPortal`）蓋在水面層的開放海面上（9×9，平台層的支柱頂仍是 3×3；本身不畫；地形是開放海面，原版尋路不看建築，所以支柱腳站不上去）。不能旋轉、沒有固定交互點：升降點（`Building_PillarFoot.LandingCell`）是 9×9 四邊外側緊貼的任一格能站的浮船（不含四角，正南中間優先，2026-11-15 起；之前固定在交互點，玩家只能對準浮船北緣才放得下）。上去時走到升降點（`Patch_PillarFootPathToInteractionCell` 把原版 Touch 改成走到這一格），下來時落在升降點；沒有升降點時兩端都不能搭。放置時做上下檢查（`PlaceWorker_PillarFoot`）：四邊至少一格是浮船（或已規劃地形藍圖），可用的格子以綠框標出；平台層上支柱頂（3×3）的位置不能有建築、藍圖或框架（只看支柱頂的大小）。蓋好時在平台層同一位置開出 5×5 海上平台（`StartPlatformSize`，已經是平台的格子不動），中間放支柱頂 `DepthRim_PlatformPillarTop`（`Building_PlatformPillar`，`PocketMapExit`，不能建造、不能拆）。支柱就是升降梯：腳是下端、頂是上端（原版進出視窗、搬運）。拆支柱腳時支柱頂一起消失。
- **海面背景**：兩層都由 `SectionLayer_SeaSurface`（queue 1900）在「空」的格子上畫海。遮罩兩層相同（`MapComponent_SeaSurface`，任一層變動兩層都標記）：r = 平台層的海上平台（影子）、g = 支柱入水處（白沫）、b = 水面層浮在水上的船體平台（貼著水線的影子與白沫，`_Hull`）。著色器的海面座標 = 畫面座標往北 `_Height.x` 格：平台層是 14.1、水面層是 0。
  - **海水的樣子照原版深海**（2026-11-14）：海水本身用原版深海水（`WaterOceanDeep`）的畫法：
    - 漣漪：原版 `Other/Ripples` 四層相乘的高度場，在世界座標直接算，再用有限差分求法線；
    - 打光：原版的日月漫射與反光公式，查 `WaterOceanDeep` 的光照色階；
    - 再加原版雲的倒影（`Other/WaterReflection`）與表面雜訊。
    - 原本自己的斑塊、浪峰線與閃光點不畫了；平台影子、支柱與船身的白沫、海水擺動照舊。
    - 貼圖要像原版著色器定義一樣設成重複（引擎預設 Clamp，漣漪會平掉）。
    - 驗收測試 U3 在海面地圖左半鋪原版深海、右半是 DepthRim 的海並排截圖：平均色差 1 以內，交界看不出來。
- **海水擺動**（`SeaSway`，2026-11-13）：海水以左右為主、上下為輔來回擺盪（上下約左右的 35%），不是往一個方向一直流；浪峰是上下拉長的線條（和擺動方向垂直），另外有很慢的往東漂移，浪峰才不會在同一處來回。位移與速度是同一組正弦的和與導數，著色器的 `swayOffset`／`swayVelocity` 用一模一樣的式子（單元測試逐項比對）。支柱的白沫尾流拖在水流的下游、長度隨流速；船身的水線白沫也偏向下游：水往回擺時跟著換邊。
- **天氣**：幅度 = 0.6 格 × 天氣倍率。倍率由水面層的風速決定（`SeaSway.WeatherFactor`：風速 0.5 以下 1，之後每多 1 風速多 1.2 倍，上限 2.5；暴風雨的風速約 1.8，倍率 2 以上）。倍率每秒最多變 0.25，起風時慢慢變大。兩層都用水面層的風速。
- **惡劣海況天氣**（2026-11-17，`SeaSurface/SeaState.cs`、`MapComponent_SeaWeather`、`1.7/Defs/SeaSurface/SeaSurface_Weather.xml`）：海面地圖的生態區是原版 Ocean，原版沒有天氣表（一直晴天並警告），`Patches/SeaSurface_Weather.xml` 給它一份海上的天氣表：晴、霧、雨、霧雨、小雪、大雪，加上兩種新天氣：
  - **惡劣海況** `DepthRim_RoughSea`：強風、不下雨、天色陰暗。
  - **海上暴風雨** `DepthRim_RoughSeaStorm`：狂風、暴雨（SoakingWet）、閃電與雷擊，0 °C 以上才會出現。
  - 海況寫在天氣的 `SeaStateExtension`：擺動倍率下限（惡劣 2.0、暴風雨 2.5，所以一定算落海風險，見安全繩錨點設計稿 §3.2）、海面的兇度 `roughness`（0.65／1.0）、物品被捲走的平均間隔（10／3 小時）、建築被打的平均間隔與傷害（8 小時 3～8／3 小時 6～15）。天氣轉換中兩種海況內插（平均間隔對機率率內插）。
  - **海面的樣子**：著色器多一個 `_Rough`（x 白浪、y 海色變暗偏灰綠並加大片的明暗起伏、z 支柱與船身的浪花範圍加大）；另外浪花強度 `_FoamAmount`、船身水線白沫 `_Hull.z`、浪峰線 `_Vanilla.y`、漣漪強度 `_Vanilla.w` 一起加大。不改 `_WaveSpeed`（乘在動畫時鐘上，中途改會整片海跳一下）。兇度和擺動倍率一樣按真實時間平滑（每秒 0.15）。
  - **捲走物品**：水面層每 250 ticks，戶外（沒屋頂，或房間是開放的）的物品照平均間隔被浪捲走（銷毀、水花），2 格內沒有開放海面的甲板中央 ×0.25；合併成一則訊息。
  - **打壞建築**：靠海邊（2 格內有開放海面）或戶外的人造建築照平均間隔被打（鈍傷，先除掉原版對建築的鈍傷倍率），不會低於最大耐久的 20%；訊息最多每半天一則。
  - **平台層**：天氣跟著水面層（`WeatherDecider.ChooseNextWeather` 前置補丁＋每 250 ticks 同步），看下去的海一樣兇；高出海面 14.1 格，物品與建築不受浪影響。
  - 開放海面 `extinguishesFire`：雷擊打在海上不留火。
- **鏡頭擺動**（`Patch_SeaCameraSway`，掛在 `CameraDriver.ApplyPositionToGameObject`）：只在水面層（平台層站在支柱上，不擺）。只移動畫面、不改鏡頭的根位置，所以不影響捲動與縮放。幅度非常小：平靜時約 0.03 格、暴風時約 0.07 格，週期約 7 秒（真實時間）。模組設定「鏡頭隨海浪擺動」可關（`seaCameraSway`，預設開）。
- **柱身**：同一張貼圖（11×18.33 格，`PlatformPillarExtension`）。平台層從支柱頂往下畫（背景著色器 `DepthRim_Background`，queue 1950：海面之上、甲板與平台側面之下）。水面層從支柱腳往上畫（整根往北移 14.1 格，入水處在支柱腳中心），用 `DepthRim_PillarRaised`（queue 2910）：在浮船、建築、Pawn（2900）之後，擋住柱子北邊（後面）的東西；柱子南邊（前面）的東西畫在入水處以南，碰不到柱身。
- **往下看的快照**（`SectionLayer_LowerLevel`，平台層）：水面層的地形（船體平台與它的乾舷側面）與人造建築（原版 `Thing.Print`），整層往南移 14.1 格、換成 `DepthRim_BackgroundLower`（queue 1940，略暗偏藍）：在海面之上、柱身之下（浮船在柱身後面），被平台層的甲板蓋住。不畫 Pawn 與物品。**不即時**：水面層的地形或建築改變時（`Patch_SeaLevelChanged`，掛在 `MapDrawer.MapMeshDirty`）版本號加一，平台層在畫面上時每 2 秒（真實時間）比對一次，變了才用自訂旗標 `DepthRim_LowerLevel` 整張重建。
- **支撐與崩塌**（`MapComponent_PlatformSupport`，平台層）：每根支柱支撐半徑 18 格（圓形）。一格海上平台要「在某根支柱的半徑內」而且「以共邊相連的方式連到某根支柱頂底下的平台」才撐得住（2026-11-15 起；連通沿用 DMSE 結構樁網路判定船體範圍的方式：`DMSE.GridTopology` 增量維護平台格的共邊連通塊，含支柱頂佔地格的塊才算數）。放置海上平台只看半徑（一次拖拉的整片藍圖彼此還沒連上）。建築分頁只在平台層顯示海上平台（`PlaceWorker_PlatformSupported.IsBuildDesignatorVisible`，2026-11-15 起；god mode 照原版一律顯示）。平台層的基底地形在平台與高空之間變動時（`Patch_PlatformStructureChanged`，鋪好、拆掉、崩塌）標記結構變動，每 10 tick 合併檢查一次。支柱消失或平台被切斷時，撐不住的海上平台進入 15 秒倒數（紅框、威脅訊息）；倒數中蓋好新支柱或補上斷口就取消。倒數結束：上面的建築毀掉、物品掉下去（銷毀）、地形變回高空；**上面的 Pawn 掉到水面層**：落點 6 格內有能站的地方（浮船、支柱腳）就掉到那裡並受鈍傷；沒有就照舊爬回最近的平台，再沒有就落海失蹤。海面落點（往南 14.1 格）濺起原版 `PawnEmergeFromWaterLarge` 水花（每 5×5 一塊，一次最多 12 個）。
- **拆除**：沿用 DMSE 的「拆除平台」；地表圖層沒有 `voidTerrain`，DMSE 會鋪太空，`Patch_SeaSurfaceVoid` 在水面層換回開放海面、在平台層換回高空。
- **地圖保留**：水面層或平台層有玩家建築、擋住移除的 Pawn，或玩家正在看其中一層時保留；兩層一起移除。
- 目前只有除錯動作「Create sea-surface map」（世界地圖上點地表海洋格）能建立；正式的前往方式待定。
- **還沒做**：舊存檔的單層海面地圖不轉換（之前只有除錯動作能建立）；快照不畫 Pawn；水面層的柱身擋住後面的東西時沒有淡出；支柱腳只能從旁邊的浮船走過去（新地圖上要先有船）。

### 4.5 潛艇建造（比照重力船）
在水下基地的船塢建造。初步的艙段 / 設施清單：

| 類別 | 項目 | 功能 |
|---|---|---|
| 結構 | 船體平台（`DepthRim_HullPlatform`，已實作） | 潛艇的基礎甲板，比照 DMSE 軌道平台：只能鋪在開放水域上（`DepthRim_OpenWater` 承載力：水下地圖的深淵、海面地圖的開放海面，2026-11-13 起）。海面地圖上它浮在水面，不需要平台支柱：側面只畫 `seaSurfaceFreeboard`（0.5 格）的乾舷，海面遮罩記在 b 通道，著色器把它的影子與水線白沫畫在甲板下 0.5 格（`_Hull`），不像海上平台高出海面 14.1 格。其餘照舊：承載 Heavy（水密隔牆與水密艙門都能蓋）、邊框與下方側面由 `SectionLayer_HullPlatformProps` 畫（比照 Odyssey 的 `SectionLayer_SubstructureProps`，貼圖 `Textures/Thing/DR_LightPlatform`，路徑在 `HullPlatformPropsExtension`）：側面只畫進深淵格，往下第二格是實地時只畫上半。不用原版 `spaceEdgeGraphicData`，因為原版側面一律畫滿兩格、靠地形蓋掉落在實地上的部分，和不透明的深淵背景互相衝突。拆除沿用 DMSE 的「拆除平台」，海洋層上拆完露出深淵（DMSE 讀海洋層 `TransferEnvironmentExtension` 的 `voidTerrain`），返還一半鋼材 |
| 結構 | 水密隔牆 | 船殼不分等級，水密隔牆可撐到淵底；水壓損傷依牆兩側壓力差判定（§5.1） |
| 結構 | 水密艙門 / 隔艙 | 把進水限制在單一艙室 |
| 動力 | 反應爐 / 電池組 | 推進、照明、維生 |
| 維生 | 氧氣再生、除濕、暖氣、排水泵 | 艙內環境維持 |
| 航行 | 壓載水艙、推進器、艦橋 | 下潛 / 上浮 / 移動 |
| 感測 | 主動 / 被動聲納 | 世界地圖視野、預警 |
| 武裝 | 魚雷管、誘餌發射器 | BVR 攻擊、攔截 |
| 對接 | 對接艙門、月池 | 跳幫攻防、整備突擊艇 |
| 出艙 | 氣閘 / 潛水裝備櫃 | 下錨時出艙作業 |

### 4.6 航行狀態（比照 DMSE 軌道船）
- **本地地圖：** 只顯示艙內，艙外不渲染。
- **世界地圖：** 視野只有聲納範圍。
  - 主動聲納：範圍大，但會暴露自己的位置。
  - 被動聲納：範圍小，但安靜。
- **允許艙內施工：** 可以在航行中改建內部，但只要拆掉外殼牆體，就會依 §2 判定為破口。
- **禁止出艙。**

### 4.7 下錨狀態
- 只能在**淺海**或**海床觸底**時下錨。
- 下錨後艙外才會顯示，而且是一張**完整的地圖**：水下礦物與山體、地下熱液泉、可燃冰、黑曜石等。
- 人員可以穿潛水裝備出艙：採礦、探索遺跡、打撈失蹤人員、從外側修補船殼。
- 如果這張地圖上有運作中的主動聲納，就可能遭到襲擊（見 §6.3）。
- 變溫層和深海（未觸底）不能下錨。

### 4.8 潛艇實作（2026-11-09，DMSE 轉移飛行換皮）

整套航行沿用 DMSE 的轉移飛行（結構樁網路 → 控制台計畫 → 倒數 → 分離到船體地圖 → 點火／滑行／點火 → 抵達或選位降落、安全期），DepthRim 只補海洋層需要的部分。DMSE 的設計見 `_Dead-Man-Switch-Expedition/docs/CelestialTransfer_轉移飛行重構.md`。

| 部分 | 做法 |
|---|---|
| 讓海洋層可以起飛 | `DepthRim_Ocean` 掛 `DMSE.TransferEnvironmentExtension`：虛空 = 深淵、船體地圖 = `DepthRim_SubmarineHull`（只鋪深淵）、父物件 = `DepthRim_Submarine`。 |
| 船體 | 龍骨框架（`DepthRim_Keel`／`DepthRim_KeelSmall`，DMSE 結構樁換皮）。`allowedTerrains` 只有船體平台：船體 = 樁覆蓋範圍內的平台格與上面的東西，海床不會被帶走；樁也只能蓋在平台上。所以潛艇只能在深淵上的船塢建造。 |
| 船塢 | 船體平台只能鋪在深淵上，而升降井通到的極地冰蓋本來沒有深淵：極地冰蓋生成 1～2 個深淵坑（`WaterMapExtension.abyssPockets`，半徑 9～13）。井底出口周圍的深淵會填回海床。 |
| 艦橋 | `DepthRim_Helm`：DMSE 轉移控制台換皮，另掛 `CompDiveControl`（巡航深度）。 |
| 推進器 | `DepthRim_Thruster`（推力 3、150 W）與 `DepthRim_AdvancedThruster`（磁流體，推力 8、300 W），繼承 DMSE 引擎基底；沒有尾焰區、不噴火、只冒氣泡，要接電。 |
| 能源 | 船上電池：`BatteryFuelSource` 註冊成 DMSE 的燃料來源（只在海洋層地圖上算數，1 單位 = 1 Wd），讓規劃畫面顯示儲電。出航不預扣（見下方航行規則）；成本是推進器在航行中的耗電：一具 150 W 的推進器每格（4 小時）約 25 Wd，一顆原版電池（600 Wd）約走 20 格。 |
| 航線 | 不能穿過陸地：`OceanRouting` 只走海洋格的廣度優先搜尋，取代 DMSE 的距離（`TransferFlightMath.Distance`）、航線（`BuildPath`），目的地也不能是陸地或海路到不了的地方。 |
| 深度 | `WorldObject_Submarine`（繼承 DMSE 的 `WorldObject_TransferShip`）實作 `IDepthTierProvider`。巡航深度由玩家設定，每小時換一層；實際層級不會比腳下的海床更深（航行經過淺海時自動被推上來）。往下潛不能超過海床，也不能超過船殼耐壓（`HullPressure`：朝外海的艙壁中最弱的那一個；一般牆與門算淺海、水密艙門算變溫層、水密隔牆算海床）。層級一變，整張地圖的水體重建。 |

**研究**（`1.7/Defs/Research/DepthRim_Research.xml`，2026-11-17 改版）：分頁「水下」只剩初始科技水下生存（500 一般研究點數，需電力：升降井、潛水服、水密艙門、排水泵、海底採樣器）。其餘改用**海底研究點數**（FFF 知識類別 `DepthRim_Seabed`，分頁「海底研究」掛 `Fortified.ModExtension_UniqueResearchTab`），研究台做不出來：耐壓工程（800：水密隔牆、船體平台）→ 潛航器建造（1200：龍骨框架、艦橋、水下推進器）→ 深淵潛航（3000）、水下戰鬥（2000）、極地航行（1500）。有 Anomaly 時要在分頁裡選目前的專案；沒有 Anomaly 時 FFF 依分頁位置自動灌進可研究的專案。潛艇開局直接給耐壓工程與潛航器建造（沒有 Anomaly 時靠 FFF 的 `Patch_ResearchManager_FinishProject` 把知識進度記進 KnowledgeStore）。

**海底採樣器**（`DR_SeafloorSampler`，2×1，水下生存解鎖，`1.7/Defs/Buildings/SeafloorSampler.xml`）：海底研究點數的唯一來源。只能蓋在海洋地圖、緊貼（含斜角）冷泉、海底火山或熱液泉。通電時每天 360 點（乘難度研究速度）經 `Fortified.KnowledgeUtility.AddKnowledge` 注入海底研究；每處冷泉 1200、海底火山 2500、熱液泉 1200 點，採完就停（同一地標旁多台共用），會自動換到旁邊另一個還有剩的地標。沒有可推進的海底研究或沒東西可採時只吃 20 W 待機電力。剩餘量記在 `MapComponent_SeafloorResearch`（熱液泉是原版間歇泉，所以不用 FFF 的 CompOccultechSource）。冷泉（`DR_ColdSeep`，`Ocean_ColdSeep.xml`）每張淺海／變溫層地圖 2~3 處，讓只有升降井的前期也拿得到海底研究。貼圖暫借原版大型引擎缸體與蒸汽間歇泉。

**世界地圖圖示**：`Textures/World/WorldObjects/Expanding/DepthRim_Submarine`（`.source/Tools/gen_submarine_icon.py` 產生的白色剪影，由 expandingIconColor 上色）。

**下錨**（2026-11-09）：下錨就是 DMSE 的降落。潛艇抵達後（不在航行中），「下錨」指令在旁邊一格（沒有世界物件、海床深度相同的海洋格）建立海洋地點，生成那裡的海床地圖，玩家選位後船體搬進去、潛艇世界物件移除；艙外從此看得見，穿潛水裝備的人員可以走下甲板。

- **深度規則**（`DiveMath.CanAnchor`）：只有淺海或深海海床有能下錨的底（變溫層、深海不行），而且潛艇要正停在那個深度（巡航深度等於海床、沒有在換層）。降落到既有的海洋地點（例如開回自己的基地）也守同樣的規則（`SubmarineLandingWorker`：DMSE 轉移飛行的降落 worker，掛在海洋層）。
- **海床記憶**（`MapComponent_SeabedMemory`）：船塢只能蓋在深淵上，但下錨可以停在海床上。平台蓋過海床時記下原本的地形；之後潛艇再離港（DMSE 把船體範圍設成深淵）或平台被拆掉，那格會換回原本的海床，不會留下深淵洞。
- **預製潛艇**（2026-11-13，`1.7/Defs/Submarine/Submarine_Prefabs.xml`，FFF 結構 `DepthRim_Prefab_PatrolSubmarine`）：17×11 的完整潛艇，三個艙室加氣閘（船尾機艙：兩具推進器、三顆電池；中艙：龍骨框架、加壓機、暖氣；船艏：艦橋、被動聲納、兩張床；每個艙室與氣閘各一台排水泵），全部蓋屋頂、抗壓水密牆外殼，氣閘外門是水密門，所以耐壓變溫層。入口 `SubmarinePrefab.Spawn`（補上屋頂、設成乾的、通知 DMSE 重算龍骨網路；迷霧由 FFF 的 `RecomputeFog` 處理，只動結構占地）；地圖生成用 `GenStep_PrefabSubmarine`（預設先挖深淵船塢）；除錯動作「Spawn prefab submarine」；驗收測試用 `DepthRimFixture.SpawnPrefabSubmarine`。DepthRim 因此直接參考 FFF（`Fortified.dll`，DMS 本來就相依它）。
- **潛艇開局**（2026-11-13，場景「深淵船員」`DepthRim_SubmarineStart`，`1.7/Defs/Submarine/Submarine_Scenario.xml`、`SubmarineStart.cs`）：
  - 三名船員一開始就在遊戲內用 FFF 匯出的潛艇 `DR_Submarine_Test` 上（`1.7/Defs/Structures.xml`，重新匯出同名結構就會換船）。
  - 選地點照常選地表格，海面也可以。`ScenPart_SubmarineStart.FindOceanStart` 從正下方的海洋格往外找最近、不超過淺海的格子（6 圈內）。附近沒有海就不能按「下一步」。
  - 建立玩家據點之前（`ScenPart_PlayerFaction.PreMapGenerate` 的前置補丁），開局格換成那個海洋格，地圖生成器換成 `DepthRim_OceanStart`：海洋地圖加上排在海洋迷霧之後的 `GenStep_SubmarineStart`。
  - `GenStep_SubmarineStart` 在中央挖深淵船塢、生成潛艇、揭開船塢迷霧、把船體劃進家園區、燃料加滿，再把殖民者與開局物品放進船艙。
  - 場景沒有原版的抵達方式。起始研究是水下生存、耐壓工程、潛艇建造；開局物品有潛水衣、口糧、藥、化學燃料、鋼、零件、兩把槍。
  - 開局據點是海洋層上的原版 `Settlement`。
  - 龍骨框架要有鋼梁連起來才算同一艘船，而 FFF 結構（包括遊戲內匯出的）不記錄鋼梁：`SubmarinePrefab.Spawn` 生成後自動把佔地內的龍骨照距離連成一棵樹（`LinkKeels`，遵守 DMSE 的距離與連結數上限），不然出港只帶走艦橋那一座龍骨覆蓋的部分（`DR_Submarine_Test` 原本只帶走 283／996 格）。
- **上浮與破冰上浮**（2026-11-13，[潛艇破冰出水_機制設計.md](潛艇破冰出水_機制設計.md)，`SubmarineSurfacing`、`IceBreach/`）：
  - 停在淺海的潛艇可以「上浮」到正上方沒有冰的海面（船體浮在海面地圖上），或用船艙裡的破冰結構「破冰上浮」頂開海冰（懸停一小時、照冰厚與船體大小判定，成功時船體停在冰面地圖的破口裡）。
  - 從艦橋「下潛」回到正下方的海洋格。冰面上的破口會重新結冰，冰超過 0.4 m 時船被凍住，要用破冰結構撞開。
  - 新研究「極地潛航」解鎖破冰結構。
- 下錨地點用自己的格子會撞到潛艇本身的地圖，所以一定是旁邊一格。

**和 DMSE 不同的航行規則**（2026-11-09）：

- **推進器要一直運作才會前進**（`VoyageMath`、`WorldObject_Submarine.ApplyThrust`）：DMSE 的航程進度完全由時間決定（起飛時刻 + 點火／滑行時長），推進器只在分離那一刻檢查。潛艇每 60 ticks 重新勘查一次可用推力（通電、開著、沒壞的推進器），和出航時的推力相比；不足的部分把航程時鐘往後推，等於那段時間沒有前進。推力剩一半就以一半的速度前進；全部停擺時潛艇停在海中漂流（發一則訊息），推進器恢復後繼續。電池沒電、推進器故障、被關掉都會讓航程停下來。
- **就地停船**（`StopHere`）：航行中潛艇與艦橋上都有「就地停船」指令，結束航程，停在目前所在的格子，推進器回到待機。之後可以下錨，或從那裡重新規劃航程。
- **航程成本只有推進器的耗電**（`SubmarineEnergyWorker`：DMSE 轉移飛行的能源 worker，掛在海洋層；`CompThrusterDraw`）：DMSE 出航時一次扣掉整趟的燃料；潛艇不扣，海洋層上的 `TransferFlightMath.FuelRequired(survey, distance)` 回傳 0。推進器只有在航行中才全速耗電，其他時候（船塢、停泊、停船後）待機 10%。規劃畫面的「所需／可用」改成推進器功率 × 航行時間 對 電池儲電，最大航程 = 電池能讓推進器跑多久（`VoyageMath.RangeTiles`，上限 500 格），超出就不能選。估算只算推進器，艦橋、照明等其他用電也會吃電池；航行中沒電就會停在海中，充電或接上發電機後繼續。

**操作與航行畫面**：

- **單一「航行」指令**（`SubmarineNavigation`）：取代巡航深度、上浮、破冰上浮、下錨、下潛與 DMSE 的規劃航線。在世界地圖點一格再選終端深度：自己這一格是換深度或上浮；旁邊的空海域是下錨；已有地點是停靠（到了之後用 `Designator_PlaceSubmarine` 選停船位置）；其他海域是航線。
- **艙外黑暗**（`SectionLayer_VoyageDarkness`、`VoyageView`、`VoyageMotion`）：航行地圖上離船體越遠越接近地圖界外的顏色，畫在原版光照暗化之後；微粒跟著船的前進、上浮、下潛流動；鏡頭有不明顯的週期晃動。
- **落海**（`VoyageOverboard`）：船在推進時，待在艙外（開放水域，包括沒蓋屋頂的甲板）的我方人員每 250 ticks 檢查一次，跟不上船就失蹤（比照 DMSE 被擊落載具的乘員），寄一封信。停船、漂流、下錨、上浮後不觸發。
- **水下沒有天空**（`UnderwaterSkyfallerBlock`）：海洋層地圖上原版會從天上掉東西的事件（隕石、空投、飛船殘骸、空投襲擊等）在 `CanFireNow` 最後一關擋掉，forced 也擋。DepthRim 自己的突擊艇不受影響。
- **觸底揚塵**（`MapComponent_TouchdownDust`）：船體停到海床地圖時揚起沉積物。
- **抗壓水密牆的斜角**（`SectionLayer_ShipHullCorners`）：外殼轉角補斜角貼圖。
- **待機耗電**（`IdlePowerUtility`）：排水泵、加壓機沒事做時只吃 XML 的 `idlePowerDraw`。

**還沒做**：見 [待補內容清單.md](待補內容清單.md)。

## 5. 水深分級

不使用絕對深度數值，而是用**四個層級**套用不同機制：

| 層級 | 光照 | 水壓（進水倍率） | 可下錨 | 主要威脅 / 事件 | 船殼需求 |
|---|---|---|---|---|---|
| **淺海** | 微光 | 低 | ✅ | 海盜潛艇、魚群 | 一般牆 |
| **變溫層** | 幾乎無光 | 中 | ❌ | 聲納干擾（溫躍層遮蔽）、伏擊、跳幫突擊艇 | 水密隔牆 |
| **深海** | 無光 | 高 | ❌ | 深海海盜、大型生物、結構疲勞 | 水密隔牆 |
| **深海海床** | 無光（生物光） | 極高 | ✅（觸底） | 遺跡、稀有礦藏、星艦相關內容 | 水密隔牆 |

機制建議：
- **船殼等級低於層級需求：** 持續累積結構疲勞，隨機造成船殼受損。
- **變溫層聲納遮蔽：** 躲在溫躍層下面比較不容易被偵測，但自己也聽不太清楚。
- **層級決定襲擊池：** 每一層有自己的事件與襲擊清單。
- **心情：** 越深越壓抑（無光、幽閉恐懼），需要照明、娛樂、舒適度來抵銷。

### 5.1 牆體水壓損傷判定（2026-11-09 實作：`WallPressureTopology`、`MapComponent_WallPressure`）

船殼不另外分等級：**水密隔牆就是最高級的耐壓牆**（`LeakResistanceExtension.pressureRating = Seabed`），潛艇和水下基地都用它撐到淵底。

**實作時的決定**：厚度加成取「÷ min(厚度, 2)」（兩層牆有加成，再疊沒有）；耐壓上限 = 等級的水壓倍率（淺海 1、變溫層 2、深海 4、海床 8）；每次更新每 1 點超載扣 0.4 HP，一般鋼牆（300 HP）在深海約 1 天、在變溫層約 3 天被壓壞；第一次壓壞牆時發一則訊息（每張地圖一天最多一次）。拓樸只在牆／門變動（`RegionDirtyer` 的三個方法）或密閉艙室改變時重建。

**核心規則：牆承受的是兩側的壓力差，不是所在深度。** 只看「這面牆在幾公尺深」會讓雙層牆的內層也一起被壓壞，這不對。

**1. 每個房間的壓力。** 每間房間有一個壓力比例 p（0 = 艙內一大氣壓，1 = 外部水壓）：

| 房間 | p | 理由 |
|---|---|---|
| 開放水域（`IsOpenWater`：碰到地圖邊緣或有沒屋頂的格子） | 1 | 就是外海 |
| 密閉艙室 | 等於它的水位（0–1） | 在數百公尺深處，進水的艙室會把空氣壓縮到幾乎沒有體積，水位滿了就等於和外海同壓。直接沿用現有的格子水位，不必另外存壓力 |
| 門口格（`IsDoorway`） | 取兩側房間中較高的 p | 關著的門也是艙壁的一部分 |

**2. 找出一面牆兩側的房間：雙標籤 BFS，結果快取起來。**

先前的寫法是每 250 ticks 掃一遍所有密閉艙室的 `BorderCellsCardinal`，再從每一格往外直線走。這樣有三個問題：
- 每次更新都重算一遍，可是牆的位置其實很少改變。
- 直線只看單一方向，L 形牆、T 形接頭和轉角牆厚會判錯。
- 碰到靠在岩壁上的牆，要靠固定的步數上限才停得下來。

改成「只在牆改變時重算拓樸，每次更新只套用壓力」：

- **障壁格**：有 edifice 而且不可通行的格子（牆、門、排風口、自然岩）。
- **建快取（雙標籤 BFS）**：
  - 從每個和房間正交相鄰的障壁格開始，多源 BFS 只在障壁格裡擴散。每格最多記住**兩個不同房間**的標籤和距離（最近的兩個），距離上限是 `MaxWallThickness` = 4。
  - 同一格收到第三個標籤時就丟掉；每格最多被展開兩次，成本是 O(2 × 帶狀範圍內的障壁格)。
  - 標籤不存 `Room` 物件，存那個房間的**種子格**（與障壁相鄰的那一格可通行格）。每次更新再用 `seed.GetRoom(map)` 查回房間，所以原版重建或重用 `Room` 物件時，快取不會失效。
- **快取的內容**：每個帶有兩個標籤的障壁格存一筆 `(cell, seedA, seedB, thickness = dA + dB − 1)`。
  - 只有一個標籤的格子（岩體內部、只面對一個房間的牆）不存，永遠不受力。
  - 靠在厚岩壁上的牆，另一側的標籤超過距離上限，自然就不受力；不需要另外判斷自然岩。
- **只在密閉艙室附近建**：BFS 的種子限制在「密閉艙室的障壁格」往外 2 × `MaxWallThickness` 的範圍內。一張還沒有基地的海洋地圖完全沒有密閉艙室，快取是空的，每次更新的成本是零。
- **何時重建**：
  - Harmony postfix 掛在 `RegionDirtyer.Notify_WalkabilityChanged(c)` 和 `RegionDirtyer.DirtyRegionForThing(t)`（牆、門蓋好或被拆掉時原版都會呼叫）以及 `SetAllDirty`，只標記「髒」，不立刻重算。
  - 屋頂改變不會讓區域變髒，可是會改變哪些房間算密閉。所以每次更新另外比對「密閉艙室數 + 總格數」的簡單雜湊，有變化也標記髒。
  - 下一次 250 ticks 更新時，有髒標記才整份重建一次，同一段時間內蓋了很多牆也只重建一次。快取不存檔，讀檔後第一次更新時重建。
  - 之後如果整份重建太慢，可以改成只重算髒格周圍 2 × `MaxWallThickness` 的方塊。這個方塊外面的標籤不受影響，因為標籤只看距離上限內的格子。

**3. 每次更新：套用壓力與損傷。**

- 對快取裡的每一筆，查兩側房間的 p，Δp = |p<sub>A</sub> − p<sub>B</sub>|。房間的 p 直接取 `roomLevel` 和 `openRooms`，這兩個在同一輪更新裡已經算好了。
- Δp 小於 ε，或這一格是打開的門（兩側正在等化），就跳過。大部分格子在這一步就結束：兩側都是乾艙，或兩側都是海。
- 負載 = Δp × `PressureFactor(tier)` ÷ thickness。負載超過牆的耐壓上限（由 `pressureRating` 換算）時累積損傷，存在一個 float 陣列裡，滿 1 點才呼叫一次 `TakeDamage`，避免每次更新都對幾百面牆送傷害。自然岩不扣血。
- 成本是 O(快取筆數)，大約等於基地外殼的格數 × 厚度。不會再列舉 `BorderCellsCardinal`，也沒有迭代器配置。

**順帶的好處**：`AccumulateLeaks` 現在要用 `HighestNeighborRoom` 找受損牆的水源。改用同一份快取，就能直接從兩個標籤拿到牆的兩側（也包括厚牆的另一側）。

**可以單獨做單元測試**：拓樸計算抽成純函式 `WallPressureTopology.Build(width, height, isBarrier, roomIdAt)`，不碰遊戲物件。下面表格裡的每一種情況，都能在 `DepthRim.Tests` 裡用小網格驗證；遊戲內驗收測試只需要確認 Harmony 的髒標記有接上。

**這樣判定之後，各種情況的結果：**

| 情況 | 結果 |
|---|---|
| 單層牆：外海 \| 牆 \| 乾艙 | Δp = 1，牆承受全部負載 |
| 雙層牆、夾層乾燥：外海 \| 外牆 \| 乾夾層 \| 內牆 \| 乾艙 | 外牆 Δp = 1；內牆兩側都是 0，**不受力** |
| 外牆破了、夾層灌滿 | 夾層 p 跟著水位升到 1，負載自動轉到內牆。外牆兩側都是 1，不再受損 |
| 兩格厚的實心牆：外海 \| 牆牆 \| 乾艙 | 同一段牆厚 2 格，每格承受一半 |
| 兩間都是乾艙之間的隔牆 | Δp = 0，不受力 |
| 立在外海裡的牆、兩側都是海 | Δp = 0，不受力 |
| 艙室半滿 | Δp = 1 − 水位，進水越多牆的負擔越小（但艙室已經在淹） |

**實作時要注意的地方**

- **夾層一定要有屋頂。** 沒有屋頂的夾層會被 `IsOpenWater` 判成外海（p = 1），外牆不受力、內牆承受全部負載，雙層牆就等於沒用。原版的自動屋頂（`AutoBuildRoofAreaSetter`）只會替 320 格以下、26 個區域以下的房間標記屋頂區，而且只是標記，還要有人去蓋。一圈繞著整座基地的夾層很容易超過 320 格。要處理的話，可以加一則提示（「夾層沒有屋頂，會被當成外海」），或者讓整面被牆圍住的狹長空間也能自動標記屋頂。
- **兩格厚的牆能不能取代水密隔牆**是平衡上的選擇：照上面「負載 ÷ thickness」的算法，兩層一般牆可以撐到兩倍深度。如果不想讓一般牆疊厚就撐到深海，負載就不要除以 thickness（厚度不加成），或者改成只除以 min(thickness, 2)，限制加成的幅度。
- **排風口**（原版 `ImpassableFreeAirExchange` 區域型）兩側在原版是不同房間，要和門一樣當成艙壁。水密排風口偵測到進水自動關閉，關著時就是牆。
- **潛艇地圖**用同一套規則；`DepthTier` 改由 `IDepthTierProvider` 依下潛深度提供，所以潛艇上浮時負載會自然下降。
- 掉血要用原版的 `TakeDamage`（DamageDefOf.Deterioration 或自訂的水壓傷害），牆壞了之後現有的滲水和破艙判定就會接手。

### 5.2 中層水域：地形下方經過的生物（2026-11-09 實作）

無法下錨的變溫層與深海，「腳下」不是海床而是更深的水。這一層比照原版 `MapDrawLayer_OrbitalDebris`（太空地圖地板下方的軌道碎片），在深淵格底下畫出經過的生物。巨物經過事件也用這一層演出。

| 部分 | 實作 |
|---|---|
| 層級 | `MidwaterMath.ShowsMidwater`：只有變溫層與深海。畫面看視覺層級（`RenderTier`，除錯覆寫可切換）；背景生物與事件看實際層級。 |
| 生物定義 | `MidwaterCreatureDef`（`1.7/Defs/Midwater/Midwater.xml`）：貼圖朝 +x、大小、色調、速度、深度（parallax）、層級、擺動參數。分成巨物（`giant`，只由事件叫出）和背景生物（`ambientWeight`）。目前有鯨魚（變溫層巨物）、大王魷魚（深海巨物）、魚群（變溫層背景）、水母（兩層背景）。 |
| 模擬 | `MapComponent_Midwater`：每隻生物沿直線從地圖外游到地圖外（`MidwaterMath.CrossingPath`），前後 12% 的路程淡入淡出。背景生物每 900 格深淵一隻、最多 5 隻，不存檔；巨物存檔。 |
| 畫面 | `MapDrawLayer_Midwater`（原版自動為每張地圖建立的全域繪製層）：每幀依生物位置建四邊形，依深度把位置與大小往鏡頭正下方縮（透視：越深移動越慢、越小）。著色器 `DepthRim_Midwater`（renderQueue 3178，在外海層 3177 之後、光照暗化 3180 之前：畫在外海層下面會被 85% 的水色完全蓋掉，驗收截圖實測）用深淵遮罩貼圖把生物裁在已探索的深淵格裡，所以牠們只會在深淵上方出現一片暗影，海床、岩體與迷霧上都沒有。眼睛、水母發光管等亮部另外用 `glowColor` 發光。 |
| 深淵遮罩 | 每格一個像素，已探索的深淵 = 1。地形或迷霧改變時由繪製層重建；貼圖屬於 `MapComponent_Midwater`，地圖卸除時銷毀。 |
| 巨物事件 | `DepthRim_GiantPasses`（`IncidentWorker_GiantPasses`）：深淵至少 300 格、同時只有一隻巨物。原版說書人只挑 `Map_PlayerHome` 等目標，不會挑海洋地圖，所以由 `MapComponent_Midwater` 依平均 4 天一次自己觸發；海洋地點帶 `DepthRim_OceanMap` 標籤，開發者選單也能直接執行。發出中性訊息，並在目前地圖播一聲船殼低鳴。 |
| 除錯 | 開發者選單「DepthRim → Midwater creature passes」：在目前地圖叫任一種生物（不檢查層級；要看到畫面，先用「Override water visual tier」切到變溫層或深海）。 |

**要注意**：變溫層的海洋地點不挖深淵（`FloodingMath.CarvesAbyss` 只有深海與海床），所以變溫層只有在潛艇航行地圖（艙外就是深淵）上看得到這一層。

## 6. 戰鬥：BVR + 跳幫

建立在 DMSE 的軌道船與 BVR 系統上（硬相依）。

**觸發條件：** 只有在設有主動聲納的地圖上才會發生水下襲擊。

### 6.1 交戰流程（航行中）
```
聲納預警 ──► 目標分類（魚群 / 海盜潛艇 / 跳幫突擊艇 / 未知）
   │
   ├─ 玩家選擇：迴避 / 靜默 / 主動攻擊
   ▼
地圖外 BVR 階段
   ├─ 發射魚雷攻擊敵艦
   ├─ 發射魚雷 / 誘餌攔截來襲的突擊艇或魚雷
   └─ 被敵方魚雷命中 → 我方某段外殼受損（進水）或破口（艙內人員失蹤）
   ▼
攔截失敗 → 敵方突擊艇抵達
   ▼
本地地圖：突擊艇穿入船艙 → 室內跳幫戰
   ▼
襲擊撤退 → 存活的敵人登上突擊艇脫離
```

### 6.2 跳幫突擊艇
- 本質是一種**特殊的運輸艙**：穿入船艙時**不會破壞密閉性**（不會造成進水）。
- 突擊艇會留在艙內；襲擊撤退時，敵人會回到艇上**載人脫離**（可能帶走俘虜或物資）。
- 摧毀停在艙內的突擊艇，就能切斷敵方退路。
- **玩家方：** 可以在**月池**建造與整備自己的突擊艇，主動跳幫敵方潛艇（掠奪、俘虜、奪船）。
- 實作上艇是 `Building_BoardingCraft`，乘員與容器直接掛奧德賽穿梭機的 `CompShuttle`＋`CompTransporter`（`DepthRim.CompUnderwaterShuttle`／`CompUnderwaterTransporter`）：玩家艇的登艇選單、載入清單、艇上內容物都走原版；敵方襲擊者仍走 lord 的 `JobDriver_BoardCraft`。艇自己的海路航行、水下切殼、回程與遭遇對話留在 `Building_BoardingCraft`。

### 6.3 下錨時的襲擊（淺海 / 海床）
- 突擊艇不直接穿入船艙，而是降落在海床上，放下**穿重型潛水服的海盜突擊隊員**。
- 突擊隊員從艙外推進，可能攻擊外殼（造成受損進水，甚至破口）或嘗試從氣閘 / 對接艙門突入。
- 出艙作業中的殖民者會直接暴露在交戰中，所以下錨時的出艙安排本身就有風險。
- 撤退時，突擊隊員回到海床上的突擊艇脫離。
