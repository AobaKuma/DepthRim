# 安全繩錨點（DR_RopeAnchor）— 機制與流程設計

草稿日期：2026-11-16。狀態：**已實作**（2026-11-17）。下面先列和設計稿不同的地方，§0～§10 是設計本身。

## 實作與設計稿的差異（2026-11-17）

程式：`Rope/RopeTetherMath.cs`（純計算）、`Rope/RopeCoverage.cs`（格子遮罩）、`Rope/OverboardHazard.cs`、`Rope/Building_RopeAnchor.cs`（建築、右鍵選單 `FloatMenuOptionProvider_RopeAnchor`）、`Rope/MapComponent_RopeTethers.cs`（掃描、反向索引、畫繩子、`RopeTether` 靜態查詢）、`Rope/MapComponent_RoughSeaOverboard.cs`、`Rope/RopeAnchorUI.cs`（放置、警報、Pawn 的指令與說明）；`Submarine/VoyageOverboard.cs` 改為跳過受保護的人；XML `1.7/Defs/Rope/RopeAnchor.xml`。

- **§10 待決事項先照本稿的預設做**：保護上限 = 畫面上限 = 2；航行中扣繩有移動 −30%、操作 −10%；材料鋼 25 + 布 20；defName 維持 `DR_RopeAnchor`（其他 Def 仍是 `DepthRim_` 前綴）；扣繩聲借原版 `EntityChainLow`（沒有 Anomaly 時用 `Metal_Drop`）。
- **繩子會不會被擋（§2.2）**：用自己的 Bresenham 直線（`RopeTetherMath.RopePasses`），不是原版的 `GenSight.PointsOnLineOfSight`：純計算才能在單元測試裡和遮罩逐格比對。
- **錨點斷開後的落海判定（§2.5）**：在**下一個 tick** 做（`MapComponent_RopeTethers.CheckPending`），不是同一 tick：不在建築 `DeSpawn` 的途中把 Pawn 移出地圖。惡劣海況時斷開的人直接算被浪打中。
- **落海檢查前先掃描一次**：`VoyageOverboard.Sweep` 與惡劣海況的擲骰都先呼叫 `MapComponent_RopeTethers.Scan()`。出港後第一個 tick 就會檢查落海，不先掃描的話甲板上的人來不及扣上。
- **候選 Pawn 的順序（§7.2）**：`IsOutside` 排在外框判斷前面，因為警報要的「艙外沒扣繩」名單也要包含外框外的人；外框省的是逐一查遮罩。
- **被浪打倒（§3.2）**：暈眩 120 ticks、水花，不冒文字（2026-11-17 使用者決定）；沒有加原版「濕透」的想法（那是天氣的情境想法，不能直接給）。
- **不冒文字提示**（2026-11-17 使用者決定）：扣繩只有扣繩聲和畫出來的繩子，被浪打倒只有暈眩與水花。
- **繩子的畫法（§4）**：純色材質，**深灰色、寬 0.12 格**（2026-11-17 使用者決定，原本米黃 0.07 格），加 `MaterialPropertyBlock` 調顏色，沒有繩子貼圖；海面擺動用 `Time.time`；錨點貼圖只有一張 `Thing/DR_RopeAnchor`，沒有 `_Full` 變體。
- **舊存檔寬限（§6）**：`MapComponent_RoughSeaOverboard` 存一個版本號，讀到沒有版本號的存檔時給 1 小時寬限。
- **惡劣海況改成天氣（2026-11-17）**：§3.2 的海況原本只看風速；現在海面地圖有「惡劣海況」與「海上暴風雨」兩種天氣（概念設計稿 §4.4b），它們的擺動倍率下限（2.0／2.5）讓 `OverboardHazard` 一定判定為 `RoughSea`。風速很大的原版天氣仍然照風速算。
- **測試**：單元測試 `RopeAnchorMath`；驗收測試 A1（航行，掛在 S2 的船塢流程上）、A2（水面惡劣海況，用 `OverboardHazard.debugSeaFactor` 固定天氣倍率、`MapComponent_RoughSeaOverboard.debugAlwaysHit` 讓擲骰必中）。沒有驗收存讀檔。

一句話：在甲板上固定一個安全繩錨點，範圍內待在艙外的 Pawn 自動扣上安全繩（一個錨點最多兩條）。潛艇航行時、或水面層遇上惡劣海況時，扣著繩的人不會被沖走失蹤。

## 2. 扣繩規則

### 2.1 誰可以扣

- 我方（`VoyageOverboard.IsOurs`）：殖民者、囚犯、奴隸、動物、機械體。
- 其他派系（訪客、商人、敵人）、野生動物：**不會**自動扣上。
- 水生的魚（`CompFishCatch.IsAquatic`）不需要，也不扣。
- 倒地、被扛著的人：見 §2.4。

### 2.2 什麼時候算「在範圍內」

三個條件同時成立：

1. 同一張地圖。
2. 和錨點的直線距離 ≤ **繩長 `RopeLength` = 9 格**（`(pawn.Position - anchor.Position).LengthHorizontalSquared <= 81`）。
3. 錨點到 Pawn 之間的直線沒有被牆擋住：繩子不能穿牆，人走到牆後面就超出範圍。用自己的判定 `RopeTetherMath.RopePasses`：沿 `GenSight.PointsOnLineOfSight` 逐格看，`edifice` 的 `def.Fillage == FillCategory.Full` 而且**不是門**就算擋住。**門不管開關都讓繩子通過**（繩子夾在門縫裡），這樣結果只跟建築有沒有在那裡有關，可以快取（§7.3）。原版的 `GenSight.LineOfSight` 會被關著的門擋住，門一開一關結果就會變，所以不用它。

### 2.3 自動扣、自動解

不做「去扣繩」的工作（Job）：工作會打斷玩家下的指令，而且航行中第一次 250 ticks 的檢查就會先把人沖走。改成**自動、即時**：

- **掃描時機**：錨點所在地圖「有風險」時（§3 的 `Hazard` 不是 `None`）每 **60 ticks** 掃一次（比落海檢查 250 ticks 密，保證人一走出艙就先扣上）。沒有風險時不扣也不畫，已扣的繩子全部解開（甲板上不會一直拖著繩子）。
- **扣上**：範圍內、在艙外（`VoyageOverboard.IsOutside`）、還沒扣繩的我方 Pawn，依下列順序填滿空位：
  1. 殖民者（含奴隸）＞機械體＞囚犯＞動物；
  2. 同一類比距離，近的先扣。
  一個 Pawn 同時只扣一個錨點。幾個錨點都能扣時，選有空位、最近的那個。
- **已扣的人不會被別人擠掉**：排序只決定空位給誰，不搶已扣的位子（避免繩子每秒換人）。玩家可以用 §5 的指令手動調整。
- **解開**（任一成立）：Pawn 走回艙內（不在艙外）；離開範圍或視線被擋；離開地圖、死亡；地圖不再有風險；玩家手動解開。走回艙內就解開是為了把位子讓給下一個人。
- **扣繩、解繩的回饋**：扣上時播短音效（不冒文字）（借原版 `Standard_Drop` 一類的金屬聲，見 §10 待決事項 5）。

### 2.4 扛著與被扛

- 扛著別人的 Pawn 扣了繩：被扛的人一起受保護（對應 `VoyageOverboard.Sweep` 裡「扛著的人一起失蹤」的反面）。
- 倒地的人自己不會扣繩（沒有行動能力），但如果倒地前已經扣著，繩子繼續有效：**這是錨點最重要的用途之一**——在甲板上被打倒的人不會被浪捲走。
- 扛著東西不影響扣繩。

### 2.5 斷開

- 錨點被摧毀、拆除、搬成可搬運的物品：所有繩子立刻斷開，**同一 tick** 對那些人跑一次落海判定（§3），讓「打斷錨點」在戰鬥中有意義。
- 船體搬動（出航、下錨、上浮、下潛的 `ShipSeparationUtility.HullPlaced`）：搬動前解開、搬動後下一次掃描重新扣。DMSE 出港那一刻留在船體外的人本來就留在原地圖，不受影響。

### 2.6 不限制行動

扣著繩的 Pawn **不會**被拉住：走出繩長就失去保護（§2.3 解開），不做尋路限制。理由：限制尋路要改原版 `PathFinder`，代價高又容易卡住工作。改用 §5 的警報和半徑圈讓玩家自己規劃工作區（例如用區域限制把人圈在錨點附近）。

## 3. 風險判定（兩個情境）

新增 `OverboardHazard`（純計算，`Submarine/` 或新的 `Rope/` 資料夾），回傳一張地圖現在的風險：

```csharp
public enum HazardKind { None, Voyage, RoughSea }
public static HazardKind HazardOf(Map map);
```

### 3.1 (A) 潛艇航行 — `Voyage`

- 條件：地圖是某艘 `WorldObject_Submarine` 的地圖，而且 `VoyageOverboard.Underway(sub)`。
- 結果：**沿用現行規則**——每 250 ticks，艙外、沒扣繩的人**全部**失蹤。唯一的改動是在 `VoyageOverboard.Sweep` 的篩選加上 `!RopeTether.IsProtected(p)`（`IsProtected` = 自己扣著繩，或被扣著繩的人扛著）。
- 扣著繩的人：不失蹤。航行中被水流拖著，額外加一個小的 hediff `DepthRim_TetheredInCurrent`（**移動 −30%、操作 −10%**，扣繩期間持續、解開後 1 小時內消退），表現「在水流裡掛在繩子上工作很吃力」。（是否要這個懲罰見 §10 待決事項 2。）

### 3.2 (B) 水面惡劣海況 — `RoughSea`（新機制）

- 地圖：海面地圖的**水面層**（`SeaLevels` 的水面層，不是平台層）。艙外的人實際上只會站在浮船（船體平台）、支柱腳旁的浮船、浮在海面的潛艇甲板上。
- 海況：用 `MapComponent_SeaSurface.TargetSwayFactor()`（由風速算，`SeaSway.WeatherFactor`）。**不要用 `SwayFactor`**：那是畫面用的、在 `Update` 裡按真實時間平滑，暫停與遊戲速度都會讓它和 tick 對不上。
  - 倍率 < **1.8**：平靜，`None`。
  - 倍率 ≥ 1.8：惡劣海況，`RoughSea`。（倍率 1.8 ≈ 風速 1.17；原版暴風雨、雷雨風速 1.5～2，倍率 2.0～2.5。）
- 判定：**機率**，不是一定失蹤（水面上的船沒有在跑，浪是一陣一陣的）。每 250 ticks 對每個艙外、沒扣繩、`CanBeSwept` 的 Pawn 擲一次，平均間隔（MTB，遊戲小時）：

  | 天氣倍率 | MTB（小時） |
  |---|---|
  | 1.8 | 12 |
  | 2.0 | 6 |
  | 2.5 | 1.5 |

  中間線性內插 MTB 的倒數（也就是機率率）。再乘上：
  - **靠近海的程度**：Pawn 所在格 2 格內有開放海面 ×1；更裡面（甲板中央）×0.4。
  - **倒地** ×3（躺在甲板上被浪一沖就走）。
  - **移動能力**低於 50% ×1.5。
  
  全部放在 `OverboardHazard.RoughSeaMtbHours(factor, nearEdge, downed, moving)`，方便單元測試和調整。
- 結果：和航行中落海一樣改為失蹤（共用 `VoyageOverboard` 的 `Lose`，改成 `internal`），寄同一種信，信件文字換成「被大浪捲走」（新 key `DepthRim.RoughSea.OverboardLabel／Text`）。
- 扣著繩的人被浪打中（同一次擲骰成功）：**不失蹤**，改成被浪打倒——暈眩 120 ticks（`pawn.stances.stunner.StunFor`）、身上 `Wet`（原版潮濕的想法）、播一個 `PawnEmergeFromWaterLarge` 水花（§4.4b 已經用過）。不受傷。
- 惡劣海況剛開始（`None → RoughSea`）時發一則訊息「海況惡劣：水面層艙外的人可能被浪捲走」，提醒玩家蓋錨點或把人叫回艙內。

### 3.3 掛在哪裡

- 航行：維持在 `WorldObject_Submarine.TickOverboard` 呼叫 `VoyageOverboard.Sweep`。
- 水面：新的 `MapComponent_RoughSeaOverboard`（只在水面層有作用），每 250 ticks 呼叫 `OverboardHazard` + 擲骰。
- 扣繩掃描：新的 `MapComponent_RopeTethers`（每張地圖一個），每 60 ticks 掃描。錨點清單直接用原版的 `map.listerThings.ThingsOfDef(DR_RopeAnchor)`，不自己登記（§7.1）。

## 4. 視覺：繩子的畫法

### 4.1 要畫出來的樣子

- 從錨點頂端（錨點畫面位置往北 0.3 格）拉到 Pawn 的腰（`pawn.DrawPos` 往南 0.1 格）。
- **懸垂**：繩子是一條下垂的曲線，鬆的時候垂得多、拉直時幾乎是直線。
  - 鬆緊度 `slack = 1 − 距離 / RopeLength`；
  - 中點下垂量 `sag = 0.6 格 × slack`（畫面往南偏）；
  - 用拋物線近似懸鏈線，分 **12 段**。
- **跟著海擺**：水面層上，繩子中段（不含兩端）加上 `SeaSway.Offset(t, …)` 的一小部分（×0.15），和海水同方向晃；航行中改成往船尾方向（`VoyageMotion` 的水流方向）偏 0.2 格，表現被水流拖著。
- **一個錨點最多兩條**，所以錨點貼圖畫兩個扣環（左右各一）：第一條從左扣環出、第二條從右扣環出，兩條不會從同一點長出來疊在一起。

### 4.2 實作

- 在 `MapComponent_RopeTethers.MapComponentUpdate` 裡畫（每幀；只畫目前地圖、鏡頭範圍內的繩子，`Find.CameraDriver.CurrentViewRect` 擴 2 格剔除）。
- 每段用一個拉長的四邊形畫：寬 0.12 格、深灰色，材質 `MaterialPool.MatFrom("Things/Building/DR_RopeAnchor/Rope", ShaderDatabase.Transparent)`（貼圖是一小段帶麻花紋的繩，沿長度方向重複；第一版先用 `SolidColorMaterials` 的純色，再換貼圖）。
- 高度層：`AltitudeLayer.PawnState`（Pawn 之上、物品之上），否則人站在繩子上時繩子會被身體蓋住、看起來斷掉。
- 選取 Pawn 或錨點時，對應的繩子加亮（顏色乘 1.3）。
- 航行時 `SectionLayer_VoyageDarkness` 把艙外畫暗：繩子在暗化**之後**畫的話會在黑暗中發亮，所以要乘上同一個暗化係數（從 `VoyageView` 拿離船體的距離）。
- 過場（出航、出水、下潛）擷取船體影像時不畫繩子（§2.5 搬動前已經解開）。

### 4.3 錨點本身

- 貼圖 `Things/Building/DR_RopeAnchor`：甲板上一個鋼製底座加兩個扣環，旁邊捲著一圈繩子。
- 兩條都扣上時捲繩畫小一點（`Graphic` 換成 `_Full` 變體，可選）。

| 錨點的說明（Inspect） | 「安全繩：2／2（A、B）」或「安全繩：0／2」；沒有風險時「待命（只在航行或惡劣海況時扣繩）」 |
| 錨點的指令 | **解開全部**；**允許自動扣繩**（開關，預設開；關掉時錨點不扣新的人，已扣的不動） |
| Pawn 的說明 | 扣著繩時：「扣著安全繩（錨點位置）」 |
| Pawn 的指令（扣著繩時） | **解開安全繩**：解開並在 2,500 ticks 內不再自動扣這個錨點（讓位給別人） |
| 右鍵選單 | 選了 Pawn、右鍵錨點：「扣在這個錨點」——把這個錨點的一條繩子換給他（已滿時擠掉最遠的那個，那個人立刻重新找別的錨點） |
| 警報 `Alert_UntetheredOutside` | 地圖有風險（§3）時，艙外有我方 Pawn 沒扣繩就出現（紅色：航行中——一定會失蹤；黃色：惡劣海況）。點擊選取這些人。 |

## 6. 存檔

- `Building_RopeAnchor`：`List<Pawn> tethered`（`Scribe_Collections.Look(ref tethered, "tethered", LookMode.Reference)`，讀檔後清掉 null 與不在同一張圖的人）、`bool autoTether`。
- `MapComponent_RopeTethers`：不存檔（錨點清單來自 `listerThings`；反向索引與格子快取在讀檔後第一次掃描時重建，§7）。Pawn 身上「暫時不扣這個錨點」的冷卻存在錨點裡（`Dictionary<Pawn, int>`，`LookMode.Reference, LookMode.Value`）。
- `MapComponent_RoughSeaOverboard`：存上一次的 `HazardKind`（避免讀檔時重發「海況惡劣」訊息）。
- 舊存檔：沒有錨點就不會有任何變化；水面層的惡劣海況落海是新風險，**升級後第一次載入**時如果水面層正處於惡劣海況，先給 1 遊戲小時的寬限期（不擲骰），避免玩家一讀檔就失蹤一個人。

## 7. 搜索與效能

目標：沒有錨點、或沒有風險的地圖上幾乎不花時間；有錨點時每次掃描的成本只跟「我方的 Pawn 數」和「錨點數」有關，不跟地圖大小或全部 Pawn 數有關。每一步都**先做便宜的判斷、能提早結束就提早結束**。

### 7.1 錨點清單：`listerThings.ThingsOfDef`

- 錨點一律用 `map.listerThings.ThingsOfDef(DepthRimDefOf.DR_RopeAnchor)` 取得：原版在 `Spawn`／`DeSpawn` 時維護這份清單，查詢只是字典取值，**不用自己做登記**，也不會有登記漏掉、讀檔後重複的問題。
  - 藍圖、框架是別的 def，不會混進來；搬成可搬運物品的錨點是 `MinifiedThing`，同樣不在清單裡。這正好就是「有效的錨點」。
  - 原版的 `ListerThings.EverListable` 只排除 mote 與投射物，建築一定會進清單，`ThingDef` 不用特別設定。
- **第一個提早結束**：`ThingsOfDef(...).Count == 0` 就整個跳過——大部分地圖（陸地基地、沒裝錨點的船）每 60 ticks 只花一次字典查詢。
- **第二個提早結束**：`OverboardHazard.HazardOf(map) == None` 就不扣新繩，只在「剛從有風險變成沒風險」那一次把已扣的繩子全部解開。`HazardOf` 每次掃描只算一次、存在 MapComponent 裡給警報和畫繩子用。
- 錨點自己不 tick（`tickerType = Never`），所有工作集中在 MapComponent。

### 7.2 候選 Pawn：只看我方，不掃全圖

- 扣繩只給我方（§2.1），所以候選名單用
  - `map.mapPawns.SpawnedPawnsInFaction(Faction.OfPlayer)`：殖民者、奴隸、殖民地的動物與機械體；
  - `map.mapPawns.PrisonersOfColonySpawned`：囚犯。
  
  都是原版維護好的清單，**不用 `AllPawnsSpawned`**（那份還包含訪客、敵人、野生動物、魚，海洋地圖上魚可能很多）。
- 每個候選 Pawn 的判斷照便宜到貴的順序，任一不成立就跳下一個：
  1. 已經扣著繩（反向索引，§7.4）→ 只做「還有效嗎」的檢查（§7.5），不重新找錨點。
  2. 死亡、沒在地圖上、水生 → 跳過。
  3. **所有錨點的外框**：掃描開始時把全部錨點的位置合成一個 `CellRect`、往外擴 `RopeLength`；Pawn 不在框裡就跳過。船上的錨點通常集中在一區，絕大多數艙內的人在這一步就被排除。
  4. `VoyageOverboard.IsOutside(pawn)`：`GetRoom` 走的是原版的區域快取，很便宜，但比外框判斷貴，所以排在後面。
  5. 對每個「還有空位、而且允許自動扣繩」的錨點查格子遮罩（§7.3）。滿了的錨點在掃描開始時就從這一輪的清單裡拿掉。
- 動物數量多時，第 3 步已經擋掉大部分；不另外分批。

### 7.3 範圍與視線：每個錨點一張格子遮罩

距離與「牆有沒有擋住」（§2.2）只跟錨點位置和建築有關，跟 Pawn 無關，所以**預先算好、快取起來**，掃描時變成查表：

- `RopeCoverage`：以錨點為中心、`(2 × 9 + 1)²` = 361 格的 `bool[]`（或 `BitArray`），一格 = 「這格在繩長內，而且從錨點拉過去不會被牆擋住」（`RopeTetherMath.RopePasses`）。查詢是 `mask[(dz + 9) * 19 + (dx + 9)]`，O(1)，沒有配置記憶體。
- 半徑內約 255 格，每格的直線最多 9 格，一張遮罩重算一次約兩千多次格子讀取，只在快取失效時才做。
- **快取鍵**：`map.listerThings.StateHashOfGroup(ThingRequestGroup.BuildingArtificial)`。原版每加入、移除一個人造建築就更新這個雜湊，所以牆蓋好、被打掉時鍵就會變，遮罩自動失效。門的開關不改變雜湊，也不影響 `RopePasses`（§2.2 讓門不擋繩子就是為了這一點）。
  - 錨點被搬動、重新裝設時，錨點本身就是新的建築，雜湊同樣會變。
  - 天然岩石（海床地圖上）不在 `BuildingArtificial` 裡。錨點只能裝在平台上，旁邊很少有岩石；保險起見，遮罩另外每 2,500 ticks 強制重算一次。
- **放置預覽**（§1 的綠色格子）用同一份 `RopeCoverage` 計算，但在 `PlaceWorker.DrawGhost` 裡只在滑鼠換格時重算，不是每幀。

### 7.4 反向索引：`Pawn → 錨點`

- `MapComponent_RopeTethers` 維護 `Dictionary<Pawn, Building_RopeAnchor>`，扣繩、解繩時同步更新（錨點自己的 `tethered` 清單是存檔用的正本，索引在讀檔後第一次掃描時從各錨點重建）。
- `RopeTether.IsTethered／AnchorOf／IsProtected` 都只查這個字典：`VoyageOverboard.Sweep` 與惡劣海況的擲骰對每個艙外的人呼叫一次，不能每次都去翻所有錨點。
- `IsProtected` 判斷被扛的人：`pawn.ParentHolder is Pawn_CarryTracker carrier && IsTethered(carrier.pawn)`，也是 O(1)。

### 7.5 已扣的繩子：只在需要時重驗

- 每次掃描對已扣的人只查三件事：還在地圖上、`IsOutside`、所在格在遮罩裡（O(1)）。
- 記下上次驗證時的 `pawn.Position`；位置沒變、遮罩快取鍵也沒變，就連 `IsOutside` 都不用查（人站著不動工作時最常見）。

### 7.6 分散在不同 tick、不配置記憶體

- 掃描時機用 `(Find.TickManager.TicksGame + map.uniqueID) % 60 == 0`：多張地圖（潛艇、海面兩層、基地）不會擠在同一個 tick。惡劣海況擲骰（250 ticks）同理，並和 `VoyageOverboard` 的檢查錯開。
- 掃描過程不用 LINQ：外框、這一輪可用的錨點、候選清單都用 MapComponent 裡重複使用的 `List<>` 欄位（每次 `Clear()`）。
- 順便改 `VoyageOverboard.Sweep`：現在每 250 ticks 用 `AllPawnsSpawned.Where(...).ToList()` 配置一份新清單。改成先用重複使用的清單收集，**沒有人在艙外時不配置任何東西**；落海的人才另外建立回傳的清單。

### 7.7 未扣繩名單：給警報直接讀

- 掃描時順便收集「有風險、艙外、我方、沒扣繩」的 Pawn，存成一份清單。
- `Alert_UntetheredOutside.GetReport` 只讀各地圖的這份清單，不自己掃 Pawn（原版警報會被頻繁重算）。清單最多晚 60 ticks，對警報來說夠了。

### 7.8 畫繩子

- 每幀只處理目前地圖：先看 `HazardOf` 的快取結果與反向索引是否為空，空的就直接結束。
- 剔除：錨點或 Pawn 任一端在 `CurrentViewRect`（擴 2 格）內才畫。
- 12 段的點用固定大小的 `Vector3[13]` 重複使用；每段一個 `Matrix4x4` 加 `Graphics.DrawMesh(MeshPool.plane10, ...)`。一個錨點兩條、一般船上幾個錨點，一幀不到一百次繪製，不需要 `DrawMeshInstanced`；錨點很多時再改成一次 `DrawMeshInstanced`（用同一個 `Matrix4x4[]` 緩衝）。
- 材質在靜態建構時建立一次（`[StaticConstructorOnStartup]`），加亮用 `MaterialPropertyBlock` 改顏色，不另外建立材質。

### 7.9 效能驗收

- 單元測試：`RopeCoverage` 的遮罩和逐格呼叫 `RopePasses` 的結果完全相同；門不擋、牆擋；快取鍵在牆蓋好／拆掉後改變、門開關後不變。
- 驗收測試（併在 §9 的 R1）：裝 4 個錨點、20 個殖民者與 30 隻動物的船，航行中跑 2,500 ticks，記錄 `MapComponent_RopeTethers` 每次掃描的平均時間（`Stopwatch`），寫進測試輸出；沒有錨點的地圖確認掃描在第一個提早結束就回傳。

## 9. 測試

依 [`.source/DepthRim.Tests/README.md`](../.source/DepthRim.Tests/README.md) 與 [`.source/DepthRim.Acceptance/README.md`](../.source/DepthRim.Acceptance/README.md) 的流程。

**單元測試（`Tests_RopeAnchor.cs`）**
- 範圍：距離 9 格內算、9.1 格不算。
- 扣繩排序：殖民者＞機械體＞囚犯＞動物；同類近的先；已扣的人不被擠掉；滿兩條就不扣第三個。
- 懸垂：距離 0 時下垂最大、距離 = 繩長時下垂 0；12 段的端點正好落在錨點和 Pawn 上。
- 海況：倍率 1.79 → `None`、1.8 → `RoughSea`；MTB 表格三個點與內插；倒地、靠海邊的倍率。

**驗收測試（代號待定，例如 R1、R2）**
- **R1 航行**：潛艇上蓋一個錨點，三個殖民者走到沒屋頂的甲板（都在範圍內），出航推進中：兩個扣上（畫出兩條繩子、截圖），第三個在第一次落海檢查時失蹤；扣著的兩人留下、有 `TetheredInCurrent`；其中一人走回艙內後繩子解開、空位在下一次掃描時沒有人可扣；拆掉錨點後剩下那人在同一 tick 失蹤。停船後繩子全部解開。
- **R2 惡劣海況**：水面層浮船上蓋錨點，強制風速讓倍率 2.5：扣繩的人被浪打中時暈眩、不失蹤；沒扣的人（用固定亂數種子）在預期時間內失蹤並收到「被大浪捲走」的信；倍率降到 1.5 時繩子解開、警報消失；平台層的人不受影響。截圖確認繩子在海擺動時跟著晃。

## 10. 待決事項

1. **「最多兩條」是保護上限還是只是畫面上限？** 本稿採「保護上限＝畫面上限＝2」，讓錨點數量本身是規劃資源。另一個做法是保護範圍內所有人、只挑最近兩人畫繩子——比較寬鬆，但玩家看到沒畫繩子的人也沒事，會覺得繩子只是裝飾。
2. **航行中扣繩的懲罰**（§3.1 的移動 −30%、操作 −10%）要不要？不加的話，航行中甲板作業和停船時完全一樣，錨點的代價只有建造成本。
3. **材料**：鋼 + 布料，還是鋼 + 已有的 DepthRim 材料？布料在海上不容易拿到，可能卡住早期玩家。
4. **命名**：其他 def 都用 `DepthRim_` 前綴，`DR_RopeAnchor` 要不要改成 `DepthRim_RopeAnchor`？（貼圖已經用 `DR_` 開頭，例如 `DR_LightPlatform`，所以 `DR_` 也說得通。）
5. **音效**：扣繩聲借原版，還是之後補自己的（`Sounds/CREDITS.md`）？
6. **失蹤後的救回**：被浪捲走的人日後要不要出「海上漂流者」事件撈回來（概念設計稿 §2.4 只講了破口失蹤）？和本設計無關，但信件文字可以先預留伏筆。
7. **敵人**：登船戰鬥時敵人要不要能割斷繩子（一個工作），或敵方潛艇也有錨點？本稿都不做。
