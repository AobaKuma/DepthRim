## 1. 現況盤點

### 1.1 原版爆炸流程（Assembly-CSharp，1.7）

```
GenExplosion.DoExplosion(...)                // 所有爆炸的入口（DMSE 魚雷 MissileImpactUtility / WarheadEffect 也走這裡）
 └ GenSpawn.Spawn(ThingDefOf.Explosion)      // 產生 Verse.Explosion
 └ Explosion.StartExplosion(sound, ignored)
     ├ damType.Worker.ExplosionCellsToHit    // 決定受影響格
     ├ damType.Worker.ExplosionStart(...)    // 推熱量；doVisualEffects 時：ExplosionFlash、鏡頭震動、ExplosionVisualEffectCenter（煙、中心 fleck/effecter、內部 fleck）
     ├ PlayExplosionSound(sound)             // doSoundEffects 時：自訂聲或 damType.soundExplosion
     ├ doVisualEffects 時 FleckMaker.WaterSplash(...)
     └ Notify_Explosion（25 個 region 內所有 Thing）
Explosion.Tick()                             // 依距離 × 1.5 / propagationSpeed 逐格延遲
 └ AffectCell(c)
     ├ damType.Worker.ExplosionAffectCell     // doVisualEffects 時每格 explosionCellFleck/Mote（火光格）；然後套傷害
     ├ pre/post spawn thing、postExplosionGas
     └ chanceToStartFire → FireUtility.TryStartFireIn
DamageWorker_Flame.ExplosionAffectCell        // Flame 另外再擲一次起火
```

重點：
- **所有視覺都被 `Explosion.doVisualEffects` 擋住，所有聲音都被 `doSoundEffects` 擋住**（中心 flash、煙、每格火光、WaterSplash、鏡頭震動）。這兩個欄位是 public、會存檔，正好拿來「關掉原版、換成我們的」，不用 transpiler。
- 傷害、熱量、`Notify_Explosion`、生成物與氣體不受這兩個欄位影響 → 第一期不動它們，玩法完全不變。
- 起火（`chanceToStartFire`、Flame 的額外起火）與視覺無關，要另外處理（§3.4）。

## 2. 觸發規則

### 2.1 哪些爆炸「在水中」

以**爆炸中心格**判斷（不逐格判斷，避免一半火光一半氣泡的怪畫面）：

```
IsUnderwater(map, center) =
    flooding != null && flooding.HasWater
    && center.InBounds(map)
    && ( flooding.IsOpenAt(center)                         // 開放水域
         || flooding.LevelAt(center) >= ImplosionMath.MinLevel )   // 淹水艙室
```

- `ImplosionMath.MinLevel` 預設取 `FloodingMath.SubmergedLevelStanding`（0.75）：水淹到胸口以上才算「水中」，和「站著被淹沒」同一條線，玩家直覺一致。
- 半淹（0.05–0.75）的艙室：維持原版爆炸，但可加一個小水花（§4.6，選做）。
- 迷霧格：**照實際水位判斷**（這是邏輯判定不是給玩家看的資訊），但視覺與聲音若中心在迷霧內就不畫／照 `UnderwaterAudio` 的悶音規則（§4.7）。
- 海面地圖（SeaSurface，平台在水面上）：平台甲板上的爆炸不是水中；若 `HasWater` 在這類地圖為 false 就自然排除。實作時要在海面地圖實測一次（驗收 I6）。

### 2.2 哪些傷害類型排除

使用者指定排除：**EMP、煙霧、眩暈、消防泡沫**。做法：

1. 新增 `DepthRim.UnderwaterImplosionExtension : DefModExtension`，欄位：
   - `bool exempt`：true = 這種 DamageDef 在水中照原版爆。
   - `bool keepDamageType`：true = 火焰類在水中也不轉成燙傷（§3.4）。
   - `bool scald`：標記燙傷 DamageDef，讓視覺辨認（只掛在 `DepthRim_Scald` 上）。
   - （選做）`float visualScale = 1`、`SoundDef soundOverride`：給特殊彈種調整。
2. 用 Patch XML（`1.7/Patches/Implosion_DamageDefs.xml`，`PatchOperationAddModExtension`）掛到排除名單上。**動工第一步先用 rimsearcher 確認實際 defName**，預期是：
   - `EMP`
   - `Smoke`
   - `Stun`
   - `Extinguish`（消防泡沫）
   - **只排除這四種**（2026-11-18 決定）：毒氣、Deadlife 等以放氣體為主的爆炸**照樣內爆**，附帶的氣體（`postExplosionGasType`）也照原版放出（§3.1 不碰氣體欄位）。
   - Patch 用 `PatchOperationConditional`（defName 存在才加），避免其他模組改名或移除時報錯。
3. 程式端另有一道保險：`damType == null` 或 `explosion.doVisualEffects == false`（呼叫端本來就不要特效，例如部分技能、腳本爆炸）→ 不接手。

純函式（可單元測試）：

```csharp
public static bool ShouldImplode(bool exemptDamage, bool callerWantsVisuals, bool hasWater, bool openWater, float level)
```

## 3. 攔截點設計

### 3.1 Harmony：`Explosion.StartExplosion` Prefix

新檔 `.source/DepthRim/Implosion/Patch_Explosion_StartExplosion.cs`：

```csharp
[HarmonyPatch(typeof(Explosion), nameof(Explosion.StartExplosion))]
public static class Patch_Explosion_StartExplosion
{
    [HarmonyPrefix]
    public static void Prefix(Explosion __instance, ref SoundDef explosionSound)
    {
        if (!UnderwaterImplosion.TryClaim(__instance))   // 判定 §2；成功時登記並回傳 true
            return;
        __instance.doVisualEffects = false;   // 關掉原版 flash、煙、每格火光、WaterSplash、鏡頭震動
        __instance.doSoundEffects  = false;   // 關掉原版爆炸聲
        __instance.chanceToStartFire = 0f;    // 水中不起火（§3.4）
        if (UnderwaterImplosion.IsFireDamage(__instance.damType))
            __instance.damType = DepthRimDefOf.DepthRim_Scald;   // 火焰類改成燙傷（§3.4）；要在 ExplosionCellsToHit 之前換
    }

    [HarmonyPostfix]
    public static void Postfix(Explosion __instance)
    {
        if (UnderwaterImplosion.IsClaimed(__instance))
            UnderwaterImplosion.Begin(__instance);   // 交給 MapComponent_Implosions 播放 §4、§5
    }
}
```

- 為什麼選 `StartExplosion` 而不是 `GenExplosion.DoExplosion`：有些模組直接 `GenSpawn.Spawn(Explosion)` 再呼叫 `StartExplosion`，掛在這裡覆蓋面最大；而且此時 `radius`、`damType`、`Position` 都已設定。
- 為什麼在 Prefix 改欄位而不是 Prefix return false：要保留原版的傷害、熱量、`Notify_Explosion` 完整流程。
- `doVisualEffects` / `doSoundEffects` 會隨 Explosion 存檔，讀檔後仍維持關閉，不會突然冒出原版火光。

### 3.2 登記與生命週期

- `UnderwaterImplosion` 靜態類別持有 `HashSet<int> claimedIds`（`thingIDNumber`），在 Postfix 把資料（中心、半徑、damType、深度層級、開始 tick）轉存到 `MapComponent_Implosions.active` 後就移除 id。
- `MapComponent_Implosions`（新）：
  - `List<ImplosionInstance> active`：每個實例記 `IntVec3 center`、`float radius`、`int startTick`、`DepthTier tier`、`float energy`（由 damAmount × radius 推）、`int seed`。
  - `MapComponentTick`：推進時間軸，到點觸發延遲事件（崩塌聲、反彈、氣泡柱、鏡頭震動）。
  - `MapComponentUpdate`：畫主氣泡與震波環（§4.2，依 `Find.TickManager.TicksGame + 插值` 計算進度，暫停時凍結）。
  - **不存檔**：整段特效 < 3 秒；讀檔時遺失特效可接受（傷害在 Explosion 本身，已存檔）。`ExposeData` 不寫 active，避免存檔膨脹。
  - 同時上限 `MaxActive = 12`；超過時新的只放簡化版（只放氣泡粒子＋聲音，不畫主氣泡），避免轟炸時掉幀。

### 3.3 每格效果

原版每格火光被 `doVisualEffects=false` 關掉了。改成在 `DamageWorker.ExplosionAffectCell` 掛 Postfix（只對已登記的 Explosion 有作用）：每格以機率 `ImplosionMath.CellParticleChance(radius)` 丟一顆「往中心吸」的氣泡／碎屑 fleck（§4.3）。
因為 Explosion 依距離逐格延遲處理，粒子會自然呈現「由內往外一圈圈出現、然後往回吸」的時序，不用另外排程。

實作提醒：`Explosion` 在 Postfix 階段已從 claimedIds 移出，所以每格判斷改看 `MapComponent_Implosions.IsImploding(explosion)`（以 thingIDNumber 對照 active 清單），或直接在 `ImplosionInstance` 記 explosion 的 id。

### 3.4 起火與火焰類

**決定（2026-11-18）：火焰類爆炸在水中改成燙傷傷害。**燃燒彈在水裡點不著，但會把周圍的水瞬間煮沸。

- `chanceToStartFire` 在 Prefix 歸零（§3.1）。
- 新增 DamageDef `DepthRim_Scald`（`1.7/Defs/Implosion/Implosion_Damage.xml`）：
  - `workerClass`：`DamageWorker_AddInjury`。**不用** `DamageWorker_Flame`，所以原版 Flame 另外擲的那次起火自然不會發生，不必另外 patch 起火。
  - `hediff`：原版 `Burn`（燒傷的治療、疤痕、疼痛都沿用）；`armorCategory`：`Heat`（防火裝備照樣有效）。
  - `isExplosive`：true、`harmsHealth`：true、`label`："scald"／「燙傷」、`deathMessage`："{0} has been scalded to death."／「{0}被燙死了。」
  - `defaultDamage`、`defaultArmorPenetration` 比照 Flame（呼叫端多半會傳自己的數值，這只是後備值）。
  - 掛 `UnderwaterImplosionExtension`，標記 `scald = true`，讓視覺能辨認（§4.1 加橘紅核心）。
- 「火焰類」的判定是 `UnderwaterImplosion.IsFireDamage(def)`：`def == DamageDefOf.Flame`，或者 `def.workerClass` 是 `DamageWorker_Flame` 的子類別（能涵蓋其他模組的燃燒彈）。DamageDef 若掛 `UnderwaterImplosionExtension.keepDamageType = true`，就保留原傷害類型。
- 換傷害類型的時機：一定要在 Prefix 裡換，因為 `StartExplosion` 接著就呼叫 `damType.Worker.ExplosionCellsToHit`，之後每格的傷害也都讀 `damType`。`damType` 會隨 Explosion 存檔，所以讀檔後仍是燙傷。
- 傷害量、穿甲、半徑都不改，只換傷害類型。

**燙傷型（火焰類改來的）的差異**：閃光與主氣泡核心帶橘紅色；氣泡柱更密、持續更久（像水被煮沸）；混濁水團改成偏白的蒸氣色。依 `ImplosionInstance.scald` 切換，不另做 FleckDef，只改 `FleckCreationData` 的顏色與數量。

### 4.2 主氣泡繪製器（自畫 mesh，不用 fleck）

原版 FleckDef 只有線性 `growthRate`，做不出「膨脹→崩塌→反彈」的曲線，所以主氣泡與震波環由 `MapComponent_Implosions.MapComponentUpdate` 自己畫：

- `Graphics.DrawMesh(MeshPool.plane10, matrix, material, 0, null, 0, propertyBlock)`，altitude 用 `AltitudeLayer.MoteOverhead`。
- 尺寸：`ImplosionMath.BubbleScale(t, period)` 回傳 0–1 的半徑比例，`BubbleAlpha(t)`、`RimBrightness(t)`（崩塌瞬間邊緣最亮）——全部是純函式，可單元測試、可在 dev 模式畫曲線。
- 材質：
  - `Textures/DepthRim/Implosion/Bubble.png`：中空的球（透明中心、亮邊、帶一點折射高光），`ShaderDatabase.MoteGlow` 或 `TransparentPostLight`。
  - `Textures/DepthRim/Implosion/ShockRing.png`：細環，加色混合。
  - 顏色以 `MaterialPropertyBlock` 設 `_Color`，依深度層級調色（§4.5）。
- 第一期只要求畫得出來、曲線正確：每個實例每幀呼叫兩次 `DrawMesh`（主氣泡、震波環），加上 `MaxActive = 12` 的上限，就足以應付轟炸。批次繪製、折射 shader 等優化留到第二期（§9）。
- 迷霧：中心格 `Fogged` 時整個實例不畫（聲音仍照悶音規則播）。
- `DepthRimModSettings.particles == false`（或新增的 `implosionVfx` 設定）時只畫主氣泡、不丟粒子。

### 4.3 粒子 fleck（新增於 `1.7/Defs/Implosion/Implosion_Effects.xml`）

| FleckDef | 用途 | 貼圖 | 行為 |
|---|---|---|---|
| `DepthRim_ImplosionFlash` | 0 秒閃光 | 原版 `Things/Mote/ExplosionFlash`，染青白 | 短 solidTime，`MoteGlow` |
| `DepthRim_ImplosionInward` | 每格往中心吸的碎屑／氣泡 | 原版 Foam / 自製小氣泡 | `velocityAngle` 指向中心、速度 = 距離 / 崩塌時間；落地前淡出 |
| `DepthRim_ImplosionBubble` | 崩塌後上升氣泡柱 | `Textures/DepthRim/Implosion/BubbleSmall_[A-C].png`（RandomGraphic） | 向 +z 漂、`rotationRate` 小、`growthRate` 正（上升變大） |
| `DepthRim_ImplosionMurk` | 混濁水團／揚起的沉積物 | 原版 `Things/Mote/Smoke`，染深青灰、低 alpha | 很慢的 `growthRate`、長 fadeOut；在 Seabed 層級改成泥沙色 |

FleckCreationData 由程式產生（`FleckMaker.ThrowExplosionCell` 不夠用），每格最多 1 顆；整個實例粒子總數上限 `ImplosionMath.MaxParticles(radius)`，大半徑（BombSuper 等）不會爆量。

### 4.4 鏡頭震動

原版 `ExplosionStart` 的震動被關掉了，改在**崩塌時刻**呼叫 `Find.CameraDriver.shaker.DoShake(...)`，強度 = 原版公式 × `ImplosionMath.ShakeFactor`（建議 1.3，水中衝擊更「實」）× `explosion.screenShakeFactor`；只在 `Find.CurrentMap == map` 時震。

### 4.5 依水深縮放（物理味道，但數值好調）

真實水下爆炸氣泡（Willis 公式）：最大半徑 ∝ (E / P)^(1/3)、脈動週期 ∝ E^(1/3) · P^(-5/6)。越深壓力越大 → 氣泡越小、崩塌越快越猛。轉成遊戲參數：

```csharp
// ImplosionMath（純函式，全部可測）
float PressureOf(DepthTier tier)   // Shallow 1, Thermocline 3, Deep 8, Seabed 15（相對值，可調）
float MaxBubbleRadius(float explosionRadius, DepthTier tier) // = explosionRadius × 0.9 × PressureOf(tier)^(-1/3)，下限 0.6
float Period(float energy, DepthTier tier)                   // 秒；= base × energy^(1/3) × PressureOf^(-5/6)，夾在 [0.35, 1.2]
float ReboundRatio(DepthTier tier)                           // 第一次反彈大小：淺 0.45 → 深 0.25（深處能量損失大）
Color Tint(DepthTier tier)                                   // 淺：青白；溫躍層：藍綠；深：暗藍＋亮邊；海床：帶泥沙棕
```

`energy` 由 `damAmount × radius` 推（不需要真實 TNT 當量），所以迫擊砲、手榴彈、魚雷、BombSuper 會自然大小有別。

### 4.6 半淹艙室（選做）

0.05 ≤ 水位 < 0.75 時仍是原版爆炸，但額外丟幾顆 `DepthRim_LeakSpray` 水花，讓「水被炸開」有感。原版本來就會 `WaterSplash`，若視覺上已足夠就不做。

### 4.7 不洩漏資訊

- 中心在迷霧格：不畫任何視覺、不震鏡頭；聲音照播（`UnderwaterAudio` 會把迷霧聲源當作全在水中而悶掉，和原版「聽得到但看不到」一致）。

## 5. 音效設計

### 5.1 新 SoundDef（`1.7/Defs/Audio/DepthRim_Sounds.xml` 增補）

| SoundDef | 時機 | 內容建議 | 參數 |
|---|---|---|---|
| `DepthRim_ImplosionThump` | 0 秒 | 很低的悶「咚」（40–120 Hz 為主），像隔著水被重擊 | `onCamera=false`、`maxDistance` ≈ 原版 Explosion 的 1.3 倍（水傳聲遠）、pitch 0.9–1.1 |
| `DepthRim_ImplosionCollapse` | 崩塌時刻 | 短促的爆裂／撕裂聲（cavitation crack）＋金屬性回響 | 依半徑調 pitch：大爆炸更低 |
| `DepthRim_ImplosionTail` | 崩塌後 | 氣泡翻滾＋低頻隆隆，約 2 秒淡出 | 可沿用 `Sounds/DepthRim/BubbleLoop` 的片段當一層 |

音檔放 `Sounds/DepthRim/Implosion/{Thump,Collapse,Tail}/`，每類 3–4 個變體（`clipFolderPath`，隨機挑）。來源依現有慣例：OpenGameArt CC0 或 Pixabay，或模組作者自製；**每個檔案都要登記到 `Sounds/CREDITS.md`**。

### 5.2 與 `UnderwaterAudio` 悶音的互動（重要）

`Patch_SampleOneShot_TryMakeAndPlay` 會對水中聲源一律加低通＋降音量。內爆音效本身已經是「水中音色」，再悶一次會幾乎聽不見。處理方式：

1. 新增 `DepthRim.UnderwaterNativeSoundExtension : DefModExtension`（掛在 SoundDef 上），欄位 `float muffleFactor = 0.3f`：悶音強度乘上這個值（不是完全不悶，聽者在乾艙室時仍要有「隔著艙壁」的感覺）。
2. `UnderwaterAudio.Apply` 讀 `SubSoundDef.parentDef` 的 extension，套 `muffle *= muffleFactor`。
3. 純函式 `FloodingMath.AudioMuffle` 不改，新增 `FloodingMath.NativeMuffle(muffle, factor)` 方便測試。

### 5.3 音量與距離

- `SoundInfo.InMap(new TargetInfo(center, map))`，`info.volumeFactor = ImplosionMath.VolumeFactor(radius)`（夾在 0.6–1.4）、`info.pitchFactor = ImplosionMath.PitchFactor(radius, tier)`（越大越深越低）。
- 同一 tick 多發爆炸（轟炸、集束）：`MapComponent_Implosions` 對同一類聲音做每 6 tick 最多 2 個的節流，避免疊音爆音。

### 5.4 保留呼叫端自訂聲音？

呼叫端傳入的 `explosionSound`（例如某些模組的特殊彈）被 `doSoundEffects=false` 一起關掉。預設**一律換成內爆聲**；若 DamageDef 掛了 `UnderwaterImplosionExtension.soundOverride` 則改用它。

## 9. 第二期：mesh 繪製優化

第一期每個實例每幀各呼叫兩次 `Graphics.DrawMesh`，貼圖也是平面的。第二期只改繪製，玩法與時間軸不動：

1. **批次繪製**：同一材質的主氣泡、震波環分別收進 `Matrix4x4[]`＋每實例的顏色／alpha 陣列，每幀各呼叫一次 `Graphics.DrawMeshInstanced`。材質要 `enableInstancing = true`，在 `WaterTierMaterials` 的建材質流程裡建一份並快取，不要每幀 new。
2. **視野剔除**：用 `Find.CameraDriver.CurrentViewRect`（擴張 Rmax）跳過畫面外的實例；地圖不是 `Find.CurrentMap` 時整個不畫。
3. **專用 mesh**：氣泡改成程式產生的環形網格（內外兩圈頂點，頂點色帶亮邊），用來取代「中空球貼圖＋plane10」。崩塌時可以只壓縮內圈、做出向內塌陷的形狀。震波環改成細環網格，各頂點的 UV 讓 shader 做扭曲。網格依段數（例如 24／48 段）建好後快取。
4. **折射 shader**：新增 `1.7/Shaders/DepthRim_ImplosionRefract.frag.glsl`，沿用現有自訂 shader 的載入流程，讓震波環扭曲背後的水體。設定關閉或 GPU 不支援時，退回第一期的貼圖材質。
5. **參數改由 shader 計算**：`BubbleScale`、`RimBrightness` 的進度直接用 `_Progress` 傳進 shader，由 shader 算形狀與亮度。CPU 端只傳一個 float，曲線仍以 `ImplosionMath` 為準（單元測試比對 CPU 與 shader 的公式）。
6. **驗收**：dev 工具一次觸發 50 發，比對第一期與第二期的幀時間（用 Unity profiler 或 Dev 模式的幀率顯示）；`MaxActive` 可視結果放寬。
