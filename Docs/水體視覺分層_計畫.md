# 水體視覺分層計畫

狀態：計畫中（2026-11-01，§7 已和使用者確認方向）。前置：兩層水體渲染已完成（外海層 `SectionLayer_WaterOuter`、艙室層 `SectionLayer_WaterVolume`，見設計稿 §2.2）。

## 1. 目標

1. **放大波紋尺度。** 目前波紋太細，會干擾辨認水中的 Pawn、建築和地形。改成大尺度、低對比的起伏。
2. **可見度由光照決定。** 有光的地方水比較清澈，看得到細節；沒光的地方水變得混濁。不再用固定的透明度。
3. **依水深層級使用不同的疊加層。** 只有淺海有明顯的波紋反射；海中央（變溫層、深海）和深海海床各有自己的視覺。

## 2. 現況

| 項目 | 現況 | 問題 |
|---|---|---|
| 波紋取樣 | 世界座標 × 0.09–0.15，`_RippleTex` 大約每 7–11 格重複一次 | 太細碎，和地形、物件的細節混在一起 |
| 光紋 | 波紋高度的細帶，強度 0.22–0.35 | 在暗處也一樣亮，不符合深海 |
| 透明度 | 外海層固定 0.30，迷霧區 0.93 | 和光照無關；原版光照暗化（3180）只是把整體變暗，水的混濁度不會變 |
| 水深層級 | `FloodingUtility.DepthTierOf(map)` 已經有，但渲染沒有用到 | 所有地圖看起來都一樣 |
| 材質 | 兩層各一個靜態共用材質 | 不同地圖沒辦法用不同參數 |

## 3. 設計

### 3.1 波紋尺度

- 外海層波紋改成世界座標 × **0.025–0.04**，大約每 25–40 格重複一次；兩層方向不同的波紋相乘的做法保留。
- 光紋帶寬跟著放大，對比降低。只在淺海保留明顯的光紋（見 §3.3）。
- 艙室層的積水面積小，用中等尺度（× 0.06），否則一間艙室裡看不出波紋。
- 尺度、強度都做成材質參數（`_RippleScale`、`_CausticStrength`），不寫死在著色器裡，方便調整。

### 3.2 可見度由光照控制

**資料來源：** 原版 `GlowGrid.VisualGlowAt(c)`（每格的光照顏色與亮度）。原版 `SectionLayer_LightingOverlay` 也是在網格頂點上取四格平均。

**做法：**
- 外海層與艙室層的每個頂點，取四格平均光照，寫進頂點色的 **g 通道**（外海層目前沒用到 g；艙室層的 g 是開放水域旗標，改用 uv 通道存光照）。
- 著色器依光照決定混濁度：
  - `alpha = mix(_MurkAlpha, _ClearAlpha, smoothstep(_LightMin, _LightMax, light))`
  - 暗處：水接近不透明的深色，看不到底下的細節。
  - 亮處：水變清澈，只剩淡淡的水色和波紋。
  - 光的顏色會稍微帶進水色，例如暖色燈光讓附近的水偏青綠。
- **混濁度範圍（已決定：中等）：** `_ClearAlpha` 約 0.15、`_MurkAlpha` 約 0.85。沒燈的地方仍隱約看得到地形輪廓。
- **重建時機：** `relevantChangeTypes` 加上 `MapMeshFlagDefOf.GroundGlow`。原版在光源改變時就會標記這個旗標，`SectionLayer_LightingOverlay` 也靠它重建。
- **迷霧區：** 不讀光照，維持固定的深海外觀。光照會洩漏迷霧下有沒有光源，而原版的迷霧本來也會蓋住光照。

**和原版光照暗化的分工：** 原版的 Darkness（3180）仍然套用在整個畫面上，負責「暗」；我們的光照只負責「清不清楚」。兩者疊加的結果是：沒有燈的地方又暗又混濁，有燈的地方明亮而且看得清楚。

### 3.3 依水深層級的疊加層

每張地圖依 `DepthTierOf(map)` 選一組材質參數；外海層在這之上再加各層級專屬的效果。

| 層級 | 適用地圖 | 外觀 | 主要效果 |
|---|---|---|---|
| **淺海** | 冰洋基地（升降井下方）、潛艇在淺海下錨 | 青藍、相對明亮 | 大尺度波紋反射、穿過冰層的光紋、偶爾出現的斜向光柱 |
| **變溫層** | 潛艇在變溫層懸停（之後） | 灰藍、帶霧感 | 不明顯的波紋；水平方向的折射晃動帶（溫躍層扭曲），整體偏混濁 |
| **深海（海中央）** | 潛艇在深海懸停（之後） | 近黑的深藍 | 沒有波紋；緩慢下沉的「海洋雪」顆粒、零星的生物光點；可見度幾乎完全靠光照 |
| **深海海床** | 潛艇海床觸底下錨、終局星艦地圖 | 黑中帶一點青綠 | 貼近地面的沉積物霧氣、緩慢漂移的懸浮顆粒、稍多一點的生物光；熱液泉附近有局部的熱擾動 |

生物光風格（已決定）：**稀疏冷色**。零星的青藍、青綠小光點，緩慢閃爍、漂移，低調、偏寫實。

**實作方式：**
- **材質參數組：** 新增 `WaterVisualTierDef`（每個層級一個 Def），存顏色、混濁度、波紋與光紋強度、顆粒密度、扭曲強度。
  - 外海層和艙室層在 `Regenerate` 時，依地圖的層級選用對應的材質。每個層級各建一份材質，所有區塊共用，不會每個區塊都建材質。
  - 數值寫在 XML，不需要重新編譯就能調。
- **著色器分支：**
  - 用一個著色器加上參數控制（例如 `_RippleStrength` 為 0 就不算波紋），不要每個層級各寫一份。這樣比較好維護，編譯錯誤也只需要排查一個檔案。
  - 程序化的顆粒（海洋雪、生物光）用世界座標雜訊加時間算，不產生 Thing 或 Mote，沒有 CPU 成本。
  - 變溫層的折射晃動（已決定：**先用假扭曲**）用 uv 偏移波紋與顏色做「看起來在晃」的效果，不擷取畫面。只有在效果不夠時，才考慮比照 DMS 的 `sceneGrab` 做真正的畫面扭曲（成本是每幀多一次畫面複製）。
- **局部效果（海床熱液泉）：** 等熱液泉建築或地形做出來之後，在它周圍的頂點寫入「熱擾動權重」，或另外做一個 SectionLayer。這一項不在這次的範圍內。

### 3.4 艙室裡的積水

- 艙室層同樣依層級選材質，但效果收斂：只保留水色、混濁度、中等尺度波紋。艙室是人造環境，不需要海洋雪或生物光。
- 艙室裡的光照通常比較亮（有燈），所以清澈度主要由光照決定。

## 4. 階段

| 階段 | 內容 | 驗收 |
|---|---|---|
| **A** | 放大波紋尺度、參數化（`_RippleScale` 等） | 截圖比較前後；單元測試確認參數有預設值 |
| **B** | 光照控制可見度：頂點寫入光照、`GroundGlow` 重建、著色器依光照決定混濁度；潛水服頭燈 | 驗收：在開放水域放一盞燈，燈下頂點的光照值高於遠處；穿潛水服的殖民者周圍變清澈；開燈前後截圖 |
| **B2** | 暗處的己方 Pawn 提示（§6） | 驗收：暗水中的己方 Pawn 有提示、敵方沒有；亮處沒有提示 |
| **C** | `WaterVisualTierDef` 與每層級材質；淺海效果（光紋、光柱） | 單元測試：四個層級都有 Def、數值在範圍內；驗收：冰洋基地使用淺海參數 |
| **D** | 深海與海床效果（海洋雪、生物光、沉積霧氣）、變溫層的晃動帶 | 驗收：用開發者設定強制切換層級，四個層級各截一張圖 |
| **E** | 艙室層的層級化與收斂版效果 | 驗收：同一個艙室在不同層級下的截圖 |

C、D 需要能切換地圖的層級。潛艇還沒做出來之前，先加一個開發者設定或除錯動作，讓冰洋基地暫時套用指定層級，方便截圖與調參。

## 5. 測試

- **單元測試：**
  - 光照轉混濁度的函式抽成純函式放進 `FloodingMath`（比照現有做法），測單調性與上下限。
  - 每個 `WaterVisualTierDef` 的欄位都存在、數值在合理範圍內，四個層級都有定義。
  - 著色器新增的 uniform 都有 `@default` 註解（避免材質沒設值時是 0）。
- **驗收測試：**
  - **V4：** 光照寫入頂點、開燈後重建、迷霧格不帶光照資訊。
  - **V5：** 四個層級各截一張近景與全景圖，並確認材質參數套用正確。
  - 截圖後多等幾幀再結束測試（已知限制，見驗收測試 README）。

## 6. 暗處的己方 Pawn 與照明視線（已決定）

**決定：** 只提示己方 Pawn；照明另外提供額外的「視線距離」。

**己方提示：**
- 己方 Pawn（殖民者、己方動物、己方機械體）站在混濁度高的水中時，畫一個淡淡的輪廓或光點。混濁度越高，提示越明顯；在亮處淡出，不和正常畫面重疊。
- 敵人與野生生物沒有提示，只能靠照明或聲納發現。
- 實作方向：用原版的 Pawn 剪影繪製（`PawnRenderer` 已經有 `silhouetteGraphic` 與 `ShaderDatabase.Silhouette`），畫在外海層之上；只在 Pawn 所在格的「光照混濁度」高於門檻時才畫。

**照明提供的視線距離：**
- **光源周圍水變清澈**（§3.2）就是視覺上的視線距離：燈照得到的範圍內看得到細節，照不到的地方是混濁的深水。
- **個人照明：** 潛水服加上頭燈（原版 `CompGlower`，小半徑、冷白光），讓每個穿潛水服的殖民者自帶一圈清澈範圍。出艙作業時不用先鋪燈也看得到周圍。
- **探照燈、照明彈（之後）：** 用同一套光照機制，只是半徑更大、可移動或有時效。
- **已決定：照明先只影響畫面。** 不改變遊戲機制（偵測、命中率等）。之後若要讓混濁度影響機制，另開一份設計。

## 8. 風險


1. **混濁度的實際數值**（0.15／0.85）要看過畫面再微調。
2. **生物光的密度。** 風格已定（稀疏冷色），密度先做成可調參數，看圖再定案。
3. **效能。** 光照讓重建變得更頻繁（例如燈的開關、日夜變化）。冰洋地圖沒有天光，日夜不會觸發；但大量燈具一起開關時要觀察重建成本。必要時改成只把光照寫進一張整張地圖大小的貼圖，不重建網格。
4. **1.7 的著色器沒有官方文件。** 新增的 uniform 和分支都要靠驗收測試的截圖與 Player.log 確認有編譯成功。
